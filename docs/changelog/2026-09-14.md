## `isocan/rc` carries the client a host constructs

Sheep's collie hosts the rc's room in a Cloudflare Worker, and the
Worker has to speak to the daemon. The room declared the calls it makes
as `RoomRoutes` and said a host could construct `DaemonRoutes`, but no
entry a host with no Node could import exported it: the root registers
tsx. Writing the wire again in sheep would make a second client, so
`isocan/rc` now re-exports `DaemonRoutes` and `ApiError` from a new
`@isocan/api/routes` subpath, with core's `BadgeStore` and
`StoredBadge`. A host builds it as
`new DaemonRoutes(base, badgeStore)` over the global `fetch`.

What stood in the way was `Buffer`. `downloadBlob` answers a
`Uint8Array` now, and `DaemonClient` wraps it back into a `Buffer`
without copying, so the blob reads in the CLI and the modules did not
change. The
boundary test names `routes.ts` as the one `@isocan/api` file the entry
reaches, and adding a `node:` import to it fails that test. The
release's declaration rewrite learned the subpath. The installed-bundle
test checks that `DaemonRoutes` is inlined into the browser bundle.

## A stopped rc stops answering at once, and hosts get the address helpers

Sheep's collie walked its `collie off` against a real daemon and
measured 9 seconds between the collie letting go of its hold and the
tray's Add an agent disappearing. The cause was isocan's: `POST
/api/rc/hold` released the hold on the request's `close`, and a POST's
request has already closed by the time its body is read. The listener
never heard the socket close later, so a hold lasted its full `waitMs`
after the rc was gone. A laptop's `isocan rc` stopped with Ctrl-C had
the same delay. The hold now releases on the response's `close`, which
fires with the socket, and releases immediately when the client left
before the handler reached that line. The log watch had fixed the same
mistake in its own route with a comment, and nothing stopped a second
route from repeating it. So `rc-hold-close.test.ts` aborts a hold from
a plain `node:http` client and reads nobody listening within a second.
Put the old line back and it fails. It also reads the server's sources
for any listener on a request's `close`. The oplog long poll, a GET
whose request does close with its socket, moved to the response too, so
only one spelling exists to copy (lessons.md #68). The hosted home runs
the same `packages/server` route, so dev picks the fix up when `green`
does.

And `canvasUrlWithPass`, `parseCanvasAddress` (with its `CanvasAddress`
type) and `isLoopbackBase` are now exported from both `isocan/rc` and
`isocan`. They are core's own functions, the same objects, so the collie
stops keeping its own copies of an address's spelling. `isocan/rc`
already reaches core, so the boundary test passes as it stood. The
packaging test checks that both emitted entry declarations re-export
them from core inside the tree, and that the installed browser bundle
parses a pass address.

## Design lint research and roadmap

The `@shadcn/lint` announcement prompted a compatibility study against the
actual HTML authoring path. Its useful contribution is a diagnostic that tells
an agent which existing component treatment or token can repair a violation.
The package itself targets Tailwind v4/JSX, while canvas screens are
self-contained HTML and the app uses ordinary CSS.

The synthetic probes found both sides of the boundary: the upstream plugin
reported five findings for a TSX example and ignored HTML/CSS; the existing
HTML auditor credited an undefined CSS variable, missed spacing and font
shorthand, and flagged a color string in prose. Tailwind's suggested `p-3.25`
also demonstrated why removing arbitrary-value syntax does not enforce a
canvas's discrete spacing scale.

The [research](../research/2026-09-14-design-lint.md) keeps the executable probe
and results beside the argument. [#299](https://github.com/dglazkov/isocan/issues/299)
tracks shared HTML diagnostics, scoped contracts, a browser/agent repair loop
with an equal-budget eval, and an optional Tailwind repository spike. No
product behavior or application dependency changed. Implementation, visual
acceptance and agent lift remain future work.

## Design lint phase 1: source findings with governing provenance

The regex audit is replaced by parsed HTML and CSS, with source ranges,
explicit coverage, actual custom-property resolution and candidate repairs.
Missing variables no longer earn credit, font/spacing shorthands are checked,
and prose, comments and URLs are not declarations. The old aggregate fields
remain, with their narrower meanings documented beside structured findings.

The useful correction was that DESIGN.md does not inject CSS. Starting variable
resolution with its expected palette would approve a reference the browser
cannot resolve. Resolution now begins with the artifact's actual declarations,
and candidates explain when exported CSS must be included. A second correction
keeps parser loading behind a dedicated core subpath: the runtime plugin loader
retains a whole core namespace, so a static barrel export added 72 KB gzip to
the initial app chunk. The isolated path leaves only a three-byte gzip delta.

Node and browser adapters read the same per-item report, including nested-group
and inherited provenance and policy-bearing source reads. Full tests,
typecheck, build and the deep suite passed; independent source probes and a
fresh-daemon CLI/API comparison held. The project walk now proceeds to findings
in the interface and explicit conditional repair. No paid model run occurred.

Landing preserved concurrent drawer, Inbox and Voice Agent additions on main,
including their dependency graph. The final combined build and typecheck passed,
as did all 5,190 fast tests. Two archived-history cases timed out in an earlier
six-worker run amid concurrent disk-synced setup, then passed alone and in both
complete four-worker reruns; test limits and product code stayed unchanged.
The recorded deep run predates those upstream additions.


## Design lint phase 2: findings that survive the save

HTML screens gain a Design check panel with source selection, governing
provenance, CSS prerequisites and explicit repair. The CLI gains item/file
selection, local DESIGN.md checks without a connection, opt-in failing exits,
and captured repairs. Both use the same input hashes and orchestration; JSON
arrival results carry stored success plus available or unavailable audit evidence.

The important boundary turned out to be the write receipt. `sendEchoed` can
finish while a write is queued; a timeout can follow a real commit. Treating
either as refusal or saved content loses the state the person needs to recover.
The new path distinguishes accepted, refused and pending, and a pending result
keeps the proposed version identity. Ordinary editor saves retain their version
stacking operation but now clear only the accepted bytes, preserving newer
keystrokes. A draft's opened base remains its base even after a refresh sees
another person's newer version.

The conductor walked real browser upload, exact findings and source selection,
one-version repair, canvas Undo, stale refusal and delayed/refused normal saves.
Twelve real CLI commands covered file modes, exit codes and post-storage audit
failure. Temporary local Java/Firestore tools let the full strict suite run:
5,772 tests passed across 576 files, with three opt-in model/sandbox skips.
Typecheck, build and the final full suite after upstream's test-only rebase also
passed. The parser stays lazy; no model was called and no cloud resource was
created. Scoped declarative contracts are the next design-lint phase.


## Design lint phase 3: a contract that survives the round trip

Scoped recipe contracts now reserve padding, radius and type properties while
allowing placement and other declared caller controls. Both clients show the
effective policy, source, treatments, exceptions and their reasons. Ordinary
policy edits and Undo refresh the same report; HTML repair cannot change the
governing item. Analysis advances to rule version 1.1.0 so old captures do not
silently reuse different rules.

The costly finding was preservation. The old YAML subset silently changed
quoted reasons, booleans, nulls and nested lists. Canonical JSON flow data now
keeps the whole extension; unsupported inputs refuse conversion. DTCG needed
more than opaque policy bytes: its generic importer renamed token paths, so
native vendor imports now restore reference targets, including partial type
roles carried in metadata. CSS export names its narrower token-only boundary.

Independent probes also caught grants inherited from Object.prototype,
over-broad shorthand allowances and selector cases that could report a false
clean result. Escaped CSS identifiers remain explicit incomplete coverage;
the strict run was stopped for that correction and rerun in full. The final
proof passed 34 contract cases, 11 preservation/conversion cases, 5,322 fast
suite tests, typecheck/build, and all 578 strict-suite files (5,879 tests with
three opt-in model/sandbox skips). The conductor's real browser/CLI walk
verified policy editing, exact finding/provenance refresh, actual Undo and
HTML repair preserving governing bytes. The initial entry is 762,562 raw /
258,847 gzip bytes, within the unchanged hard limit, with analysis still lazy.

Phase 4 now measures optional repository linters. No paid model call, human
intent judgment or cloud resource is part of this phase's proof.
