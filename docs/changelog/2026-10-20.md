# 20 October 2026 — A closed read of the room stays closed

Dion, on a canvas whose critics had spoken days before: "when I load this
canvas this right sidebar always shows up and I don't want it to." The card
was the critique module's **read of the room** overlay, and its close button
only set component state (`useState`), so every load opened the newest read
again — however old it was, and however many times it had been closed.

- **Which read this viewer closed is remembered**
  (`packages/modules/critique/src/room-web.tsx`), per canvas, in this
  browser's `localStorage` (`critique:room-dismissed:<canvasId>`). The card
  comes back only when the room is asked something new — a new ask is a new
  comment id. Local rather than an op on purpose: closing a card is one
  person's view, not the canvas's, and nothing is lost by it, since the
  lead's posted read is a comment in the Chat. Restricted storage falls back
  to what it did before: closed for this visit.
- **Guard (`critique/test/room-dismiss.test.ts`).** On a synthetic Acme
  canvas: the read opens, closes, stays closed across a fresh mount, opens
  again for a second ask, and a dismissal on one canvas closes no other. The
  first case fails on the old component.

## Later: slide transitions go behind an experiment

Presenting a deck of screens, Dion: "The push transition is REALLY janky… it
doesn't smoothly push at all" — and then, "place the transitions behind an
experiment 'Presentation Transitions' as they aren't feeling good right now…
and if the experiment is off the transitions should be as they used to be…
the fade".

- **`presentation.transitions`** (`lib/experiments.ts`), per browser like
  every experiment. With it off, `flipTo` (`lib/deckflip.ts`) is the flip from
  before 19 Oct exactly: a flip that touches a frame never rides a view
  transition and leaves no note for the frame pool, so a deck of screens
  dissolves (the pool's `.html-view` opacity); a deck of images and text
  pushes on a view transition; the canvas's chosen motion is not read.
- **Nothing offers a choice it would not play.** Full screen's *Transition*
  button (`FocusHeader`), the drawer's *Slide transition* (`Toolbar`) and the
  morph's twins (`MorphStage`) all wait on the experiment. The canvas
  property and `isocan slides transition` are untouched — whoever has the
  experiment on still sees the deck's choice — and the agent guide and README
  now say the motion plays only with it on.
- **Guard (`transitions-experiment.test.ts`).** Off: a screen-to-screen flip
  set to Depth navigates with no live-flip note; no choice is offered and no
  twins mount. On: the same flip leaves the note the pool plays.

The live push between screens is not fixed by this — it is hidden until it
is. That is the next thing for the experiment.

## Later: History takes the top when the Chat is the bottom bar

"History is broken if chat is on the bottom… I guess it should go on top?"
Both were bottom-centred, and the Chat bar rides higher (`--z-bar` over the
scrubber's `--z-float`), so the composer covered the rail, the track and Play.

- **`Scrubber` reads where the Chat is** (`chatAt`): while it is the bottom
  bar (and not hidden by an embed), the panel wears `at-top` and sits under
  the top bar's clusters (`top: calc(var(--edge) + 34px + 12px)`). Docked on
  the left, the bottom is free and History stays where it always was.
- **Guard (`scrubber-place.test.ts`).** Bottom bar → top; docked left →
  bottom.
