# 27 October 2026 — offline notes, Stage saves and stickers

Speaker-note creation and Stage version saves now use the same deterministic
text staging and durable operation outbox as ordinary text notes and drawings.
They remain visible locally when the home cannot be reached and upload their
bytes before their operations on reconnect. Stage still waits for the home's
receipt before marking a version saved; repeated save shortcuts cannot enqueue
duplicates, and typing during that wait remains a dirty draft after acceptance
or refusal.

The web module host also stages editable text and SVG, carrying the bytes from
`putBlob` to `send` on the same host. Sticker placement and replacement therefore
work offline without a module-specific queue. Current stickers are UTF-8 emoji
files, rather than the SVG described in the original Loop finding. Binary
uploads retain their existing behavior, and permission checks still apply.

Regression coverage exposed another instance of shared-identity cleanup: two
identical stickers name the same blob hash. Retiring or refusing one queued
operation must retain local bytes while another operation still needs them.
Cache cleanup now checks the remaining hash references. Tests cover offline
creation, reload, ordered reconnect flushing, duplicate hashes, refusal,
permissions, and Stage's retained newer edits.

The operation vocabulary, CLI verbs, agent guide and README are unchanged:
these are repairs to browser persistence of existing operations, with no new
user or agent action. No external Loop decision or publication was made.
