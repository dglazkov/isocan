# Identity you can prove, and revocation that means something

**2026-08-24** · Phase 9 · Dimitri Glazkov

The desk gets its teeth. Before today a canvas could stop *new* arrivals and
nothing else: turning off a link left everybody who had already walked in
exactly where they were. Now revoking a grant expels the people it let in —
down a chain of passes, several hops deep — while keeping the ones another
grant still covers. And identity stops being something you assert: prove you
read an inbox and a second browser can be the person your laptop already is.

## The sweep, and why order was the whole problem

"A pass-derived admission inherits the root of the badge that minted it" reads
like a lookup. It is not one: the minter's own root may be changing in the same
sweep. The first implementation read stale roots in whatever order the desk
handed badges back, and expelled Jordan's daemon a moment before Jordan's tab
re-rooted onto the grant that had invited her by name — the design's own named
failure, one hop down, decided by a list order. A badge now adopts its
minter's *outcome*, decided once, recursively. Cycles and dead middles stopped
needing cases and fell out of a wider question: not "rooted in the revoked
row" but **"whose root no longer stands"**.

Measured against a real daemon: a tab on the link, its daemon on a pass, an
agent on a pass from that — one revocation, three expelled, the creator
untouched. Then with an email grant in play: `{expelled: 1, rerooted: 1}`. The
stranger goes; the person invited by name stays. That is the sentence the
design has carried since it was written, as a measurement rather than a
promise.

## Borrow, never mint

isocan still has no accounts, no passwords and no user table, and today's work
was careful not to accidentally create the first one. Identity Platform was
provisioned as the borrowed bench — magic-link email as the floor, Google and
GitHub above it — and what comes back is written onto the badge as one
attestation and nowhere else. There is no Firebase SDK in the web app on
purpose: two REST calls do the whole flow, and the 150 KB alternative would
have parked a second identity, with its own lifetime and its own opinion about
who you are, beside the badge. The ID token is used once and dropped.

The gesture that follows is the point. A browser that had never been Jordan
was refused when it tried to self-claim the name, proved an address, and was
offered *"another surface that proved the same address answers to: Be Jordan"*.
One click, and the tab was her. Meanwhile a home that has borrowed no attester
refuses an `email:` grant with its reasons and shares by link exactly as
before — the trap this work was told not to walk into.

## Two lessons that cost nothing and could have cost a lot

The provisioning script was rewritten from what its first run *measured*. A
`gcloud auth login` credential bills its API quota to gcloud's own shared
client project, so the API answered `403 SERVICE_DISABLED` naming a project
nobody had heard of, moments after the script enabled it on ours. And
`initializeAuth` sits under `v2/` while its neighbours are `admin/v2/` — the
wrong path answers an HTML 404, so a check looking for `"error"` in the body
found none and reported success. That is this codebase's oldest recurring bug,
reproduced in a provisioning script on the day the phase that closed it was
committed.

Then the same shape once more, from the other direction: a documentation edit
used an unquoted heredoc, so backticks around a script path became command
substitution and **writing the changelog's own source ran the provisioning
script**. Nothing broke, and only because every step in that script checks
before it creates. It is a better argument for the idempotence rule than the
one in the README.

## Also today

- The blob route is **closed**. It had been open since phase 2 on the argument
  that a sandboxed iframe cannot carry a badge; measured in Chrome, the
  iframe's own load is same-origin and sends the cookie — only requests from
  *inside* the blob are cross-site, and those never resolved anyway.
  `Cache-Control` gained `private`, because a credentialed response at a shared
  CDN edge is a closed route with an open back gate.
- Kill-a-badge, scoped to badges that share an identity with you — so a
  stranger admitted by a link cannot end the recognition of the person who
  shared it, and the listing can never become a roster of people to expel.
- `repo:` grants are deferred to phase 11, with the refusal left honest.
