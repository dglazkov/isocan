# 6 September 2026 — The switcher, and the content origin goes live

Two threads and a long tail. Going to another canvas without the trip through
the home screen — the branch was cut at 4 September's head and forward-ported
over the module work and the two days after it. And the answer to yesterday's
open decision: how a cookieless origin knows who may read a private canvas's
bytes, which closes stage 4 of the content-origin plan, and with it the plan.

The tail is the more interesting half of the day, and none of it was planned:
deploying that change ran into a red main nobody had noticed, which was
holding `green` eleven commits back, which had stopped dev deploying — and
unpicking that turned up two commits of real work stranded on one laptop and
a CI arrangement that made main the first place anything is ever tested. Each
is written up below in the order it was found, because that order is the
argument.

## Read auth on the content origin: signed URLs, isocan.store, five minutes

Yesterday's [`content-read-auth.md`](../projects/multiuser/content-read-auth.md)
costed three options and left two numbers to the owners. Both are answered
and the code is in.

**The collision, restated because it is the whole design.** Expulsion reaches
the bytes (23 August: the blob route requires a badge and an admission, and
sends `private` so no shared cache can hand a swept badge what it was just
expelled from). And the content origin holds nothing (26 August: no cookie to
steal, no API to call, which is what makes `allow-same-origin` safe to grant
there). The origin that must serve private bytes is the origin that must not
carry the credential saying who is asking.

**So the URL is the credential, and it dies in minutes.** The badged app
origin mints an HMAC over `(canvasId, hash, expiry)`; the content origin
verifies it and serves or refuses, looking nothing up. `content-auth.ts` is
the scheme on its own — no Fastify, no desk, no store — with four verdicts
that collapse to one 403 for the caller and stay four for the log, and the
signature checked *before* the clock so nobody can pick which refusal they
get by writing a date in the query.

**The mint is a `GET`, and that is load-bearing rather than tidy.**
`GET /api/projects/:id/blobs/signed?hashes=…` sits under the canvas-scoped
prefix, so the door's one hook has already re-asked `canvasId ∈ admissions`
before a signature exists — the whole enforcement, with signing knowing
nothing about it. A POST would have been refused by the capability hook to
any badge below `edit`, and a view-only member who cannot mint is one who
sees an empty canvas.

**The TTL is five minutes, and the argument for the calmer hour evaporated.**
That argument was the cost of a mint per frame render. Signatures are minted
in one batched call per canvas visit, so a canvas of forty screens is one
round trip either way; with the cost gone, the number that makes expulsion
nearly immediate wins. `ISOCAN_CONTENT_TTL` overrides it.

**The key is a desk ledger** (`Desk.contentKey()`), minted on first ask and
create-once across concurrent callers — a Firestore transaction on
`meta/content-key`, the file desk's own write chain. A rollout runs two
instances of a home for a few seconds, and two keys would have broken half
the frames on every open tab.

**Invariant 4 needed a second mechanism.** Locally the content origin is its
own listener and "blobs and nothing else" is an enumerable route table. The
hosted origin is a Host header on the app's single Cloud Run `$PORT`, so it
is a refusal at the top of the door hook instead — before the badge is even
resolved — plus one on the WebSocket upgrade, which is hijacked off the raw
server and no Fastify hook would have reached. The predicate matches a sha256
path segment rather than any segment, and that was not caution: a shape-only
pattern let `/blobs/signed` — the *mint* route — through to an unbadged
caller on the origin that exists precisely because it carries no badge. The
invariant-4 test found it by enumerating the refusals, which is the argument
for enumerating them.

**Invariant 2 grew a third answer.** `itemFrame` may now return `null`,
meaning "the signature has not landed yet", and the web half renders the
empty card the frame would sit on. Falling back to an app-origin src for that
beat would have paired it with `allow-same-origin` — the exact whole-home
compromise the invariant exists to make unbuildable.

**The edge copy comes back.** A verified signed read is `public, max-age=<what
is left of its TTL>` — never `immutable`, because the bytes are permanent and
the URL's right to them is not. That reasoning holds only while the cache key
includes the query string, so `infra/82-content-origin.sh` sets it explicitly
rather than inheriting Cloud CDN's default: a future "include-query-string=
false" typed by somebody optimizing hit rates would be a silent, total
authorization bypass.

**The honest cost, written into the blob route's ledger in `http.ts` where
the promise it qualifies lives.** On the hosted shape expulsion reaches the
bytes *within one TTL*: an expelled badge cannot mint (immediately), and what
it already minted lives out its minutes. Both halves have a test —
`contentauth.test.ts` asserts the second as deliberately as the first,
because a documented cost that nothing tests is a claim.

**Infra:** `82-content-origin.sh` (the certificate beside the app's on the
same proxy, the host rule turning yesterday's parked 301 into a route to the
same backend, the cache-key policy), `ISOCAN_CONTENT_DOMAIN` in `config.sh`
with `isocan.store` in `prod.env`, and `70-cloud-run.sh` passing it to the
daemon as `ISOCAN_CONTENT_HOST`. That one variable turns the hosted half on —
frames move, reads sign, that Host is refused everything else — and unsetting
it is the rollback for all of it. Dev has no second domain and every one of
these does nothing there.

## Deploying it, and the four things that were in the way

The design was the easy half. Getting it onto prod took four detours, and each
one was a real defect that had been sitting there quietly.

**Main was red and nobody knew.** `docstatus.test.ts` requires every research
note owing work to name the issue that follows it; the architecture-review note
had landed `status: partial` with no `issue:`. One assertion, 348 other files
passing — and because `release.yml` only advances `green` on a green run,
`green` had been stuck **eleven commits** behind main, which had stopped
dev.isocan.io deploying, and none of it was noticed until somebody went to
promote to prod and found `green` four days stale. #185 carries the note's
remaining work; the front-matter line is what turned main green again.

Adding it made `docs/ROADMAP.md` stale, which `roadmap.test.ts` catches — so
the fix for a red main would itself have reddened main, one commit later, had
the suite not been run by hand first. That is luck, not a system, which is the
third finding below.

**Two commits of real work existed on one laptop.** Merging the content-origin
branch produced "ahead by 9" where 6 was expected. The extra two — teleport
carrying blobs, and canvas export/import — were four days old, on local `main`,
never pushed, and one `git push origin main` from reaching the trunk unreviewed
as a side effect of somebody else's deploy. Four differently-named branches all
pointed at the same stale tip, which is the signature of branches **created but
never checked out**: each session cut its branch, committed to `main` instead,
and never pushed. #186 has the story, #187 the work, and `lessons.md` the habit
it earns — `git log origin/main..main` before trusting a branch count.

The teleport commit is worth reading on its own. *A canvas naming any blob
could not move*: bytes went first, into a canvas the far home did not hold yet,
where every route 404s until `adopt` creates it — so the first upload was
refused and the move stopped, safely and uselessly. **The only teleport test
moved a blob-less canvas, which is why it was green.**

**Nothing runs on pull requests.** Every workflow here triggers on `schedule`,
`workflow_dispatch` or `push: branches: [main]` — so main is the first place
anything is ever tested, and every problem above follows from it. `pr.yml` runs
the same suite, the same emulator and the same anti-skip switch on
`pull_request`, sharing setup with `release.yml` through a composite action
rather than a comment asking two files not to drift. Advisory, not a required
check: deleting the file is the whole rollback. `lessons.md` #30 states the
shape — **ask when a check first CAN fail, not whether it exists.**

**And the infra scripts had two bugs only a real run could show.** The test for
"is this certificate already on the proxy" used `grep "…$\|…,"`, and `\|` is a
GNU extension: BSD grep, which is what macOS ships, reads it as a literal pipe,
and then the `$` stops being an anchor because it is no longer last. It passed
on Linux and failed silently on the machine the operator was using. Worse, the
re-write it caused was not harmless — `--ssl-certificates` REPLACES the list
and the replacement was a hardcoded pair, so a proxy carrying a third
certificate would have had it dropped by a script that only meant to add one.
Separately, `70-cloud-run.sh` defaults to `:latest` while the build trigger
deploys by commit sha, so re-running it to change one environment variable
could have rolled production backwards without saying so. Both fixed; the
second now prints both images and asks.

The shape those two share is worth keeping: **a control that only runs on the
maintainer's platform is not a control**, and these scripts are written on
Linux and run on a Mac.

## What the browser showed

The proof, in one attribute, off a real canvas:

```html
<iframe class="html-view"
        src="https://isocan.store/api/projects/prj_…/blobs/a9a722b…?exp=1788678125&sig=GKAz8HW…gicEA"
        sandbox="allow-scripts allow-same-origin">
  #document   <!-- DOCTYPE, html, head, body: the bytes arrived -->
```

The src left the app origin. The credential is the URL. The signature is 43
characters, which is HMAC-SHA256 in base64url and nothing else. And
`allow-same-origin` is present *because* the src is cross-origin — invariant 2
as a rendered attribute rather than an argument. The `exp` decoded to three
minutes and sixteen seconds in the future, which is the whole answer to the
23 August ledger's objection to a token in a URL: a durable token is a
credential where people paste, and this one is not durable.


## The switcher: the launcher's second face

Going to another canvas meant the home screen: the `⌂`, a scroll, a click.
Right for choosing, and a tax when you already know where you are going —
which, nearly always, is the canvas you were on ten minutes ago.

**One window, two faces.** The ⌘K palette now carries a `mode`:
`commands` is the launcher it was; `canvases` is a list of canvases with a
field over it. `uiStore.paletteOpen` went from a boolean to
`PaletteMode | null` so that one state says both whether the window is open
and which face it wears. It is one component rather than a second dialog
because it is the same gesture — a field, a list, Enter — and a second
modal over the first would have had to answer which of two Escapes closes
what. Backspace on an empty field steps back to the commands.

**Three doors.** `⌘O` (it crosses a cover like ⌘K does: leaving is the one
act that makes sense whatever is covering the canvas, and it acts on
nothing here); the "Switch canvas…" row in ⌘K, which flips the window
rather than closing it — closing first would have unmounted the palette and
mounted a new one, a flash and a lost keystroke; and a `⌄` beside the
canvas's name in the bar, the shape every app with several documents uses
for "the others are under here", and the one entry point that needs no key
to be found. The commands face also finds a canvas on its own: type a
title and up to five matches appear under the actions as "Switch to", so
the common trip is ⌘K, three letters, Enter, with no mode to know about.

**Lately first.** The list leads with the canvases this browser was on,
most recent first, then everything else by activity — the home screen's
default order, so it is the one already learned. "Lately" is a fact only
the browser knows (the daemon sees writes, not visits, and a canvas read
for an hour without a change is exactly the kind you come back to), so it
is `localStorage` (`lib/recents.ts`, `isocan.canvases.recent`, twenty
rows, title riding along). The title is why the list paints before
`GET /api/projects` answers, and why it paints at all when it never does:
offline, the recents are the whole list, and every one opens from the
replica. The fetch is the home screen's own `listCanvases()` — the canvases
this origin is the home of — for the same reason the home screen narrows:
a client-side navigation never asks the server, and a row for a canvas
homed elsewhere would open a stale local copy of it (phase 10.3).

**Fuzzy, where the launcher deliberately is not.** The launcher matches
whole terms, because a matcher that scores letters anywhere is how a
palette starts offering "Delete everything" for "de". That rule is about
what a wrong match DOES. Switching canvases does nothing to any of them and
Back undoes it, so here the trade goes the other way: `fuzzyMatch` in
`core/canvasswitch.ts` takes the letters in order from anywhere, and the
scoring still prefers the certain reading — letters together, letters that
start words, a prefix — so among titles that all contain the letters the
obvious one comes first. `rankCanvases` is in core because it is pure
logic a test can hold still, and because the terminal could show the same
order tomorrow; it does not today, and deliberately: an agent switches
canvases by naming one, so a viewport gesture gets no verb.

**A move rather than a cut.** The route element is the same `CanvasPage`
for every canvas, so without anything the surface was simply replaced
between one frame and the next, which reads as the page breaking and then
fixing itself. `lib/canvasswitch.ts` sets `switching: "out"`, waits 140ms
for the surface to recede, navigates, sets `"in"` for 220ms while the next
canvas comes forward from a touch larger. The class is on `.canvas-surface`
— the viewport's wrapper — and not on the page, because the bar and the
rail are the same chrome on both canvases and chrome that lurched would
say the app reloaded. Under `prefers-reduced-motion` the keyframes are off
AND the wait is skipped: a person who asked for no motion should not be
asked to wait for motion they cannot see. A test holds the CSS durations
to the helper's constants.

**Two things corrected on the way.** The `?` panel's ⌘K row still said
"Message your emissary from anywhere", which had not been true since ⌘K
became the launcher; it now says what the launcher does. And the accent
guard caught the first draft of the highlight painting text in `--accent`
(2.5:1 on graphite); it is `--accent-text`, as every other accent-coloured
word is.

Tests: `core/test/canvasswitch.test.ts` (the matcher's preferences, the
ranking, the tiebreaks, the highlight runs) and `web/test/switcher.test.ts`
(the recents rule, the three doors open one window, the key the palette
prints is the key the help panel prints, the durations agree, the surface
moves and the chrome does not).

## The plan behind the switcher, and every open note gets an issue

The switcher shipped before its plan was written, which is the wrong order
and was corrected the same afternoon:
[`projects/switcher/design.md`](../projects/switcher/design.md) records what
the field converged on (a field over a list, opened by a chord, fuzzy, the
title as a door, commands and documents in one window — from use, and said
to be unmeasured), what already existed in core, the decisions phase 1 made
and why, the two open questions (whether a real browser window hands ⌘O to
the page; recents being per browser), and phases 2–5. #134 follows it.

**The word.** Asked to make "project" and "canvas" consistent, with a canvas
living in a project and several canvases per project later.
[`research/2026-09-06-project-and-canvas.md`](../research/2026-09-06-project-and-canvas.md)
counts 331 "project" against 4,879 "canvas" in source and sorts every
survivor: the `project.*` ops, `/api/projects`, `/p/`, the marker and
`defaultProjectId` are the wire and the container and stay (an oplog replays
forever, and under the model they are right — `project.create` makes the
container, which makes its one canvas); the web store's `project` field and
the list page's `setProjects` call the surface a project and are the
renames; the prose was already right. The model — canvas is the surface,
project is the directory that holds canvases, space is an access grouping
and not a container — is written so the multi-canvas project, when it comes,
touches the wire once. #135 follows it.

**Every open research note now has an issue.** Nineteen notes stood at
`designed` or `partial` with nowhere to be followed; each got a GitHub issue
(#136–#154) carrying the finding, what is left, and the related notes by
number, and each note's front matter gained `issue: <n>`. `docStatus` reads
the field, `isocan doc status` prints it, and the roadmap links it, so the
tracker is one click from the argument and the argument one line from the
tracker. A test now refuses a note owing work with no issue. The roles note
was found saying `designed` two days after its project's last phase closed
on prod; it says `built` now. JSON Canvas's issue asks for a decision rather
than a build: by its own verdict there is nothing left, and a note cannot
sit in "partly built" forever.

**Four of those issues closed on arrival, which is the field working.** The
branch was cut at 4 September's head and the two days that followed built
four of the things it had just filed: the DTCG round-trip (#136), element
properties on the stage (#142), pan inertia (#144), and the sheepdog, whose
note is superseded by an external sheep CLI (#153). Their notes read `built`
or `superseded` on main, so the stamp came off each of them — a note that
owes nothing carries no issue — and the issues were closed against the
commits that answered them. Three notes written in those two days owe work:
modules and mobile web already had issues opened the same way (#156, #182)
and now carry the field, and taking a deck somewhere else got #184 — its
PPTX and its Google Slides both still open, the second behind the per-user
sign-in. The roadmap links all three like the rest.
