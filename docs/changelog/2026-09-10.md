# 10 September 2026

## Site addresses wait for submit

Typing `https://` into Add → Site could blank the canvas before the address
was finished. Both the automatic guess and the pinned Site preview called
the strict URL normalizer during render, so an incomplete address threw
outside the submit handler. A complete pasted address skipped that moment.

The field now keeps incomplete addresses as drafts. Enter or Add site runs
the shared normalizer before checking frameability or creating an item.
Invalid input stays in the field, with an inline error explaining that HTTP
or HTTPS is required and showing example addresses. The error wraps inside
the popover, is associated with the input, and clears when typing resumes.
The unpinned field has the same protection. Existing valid-paste, canvas and
Google Doc classification stays with the shared classifier.

The web suite exercises every prefix of complete addresses; real-browser
checks cover character-by-character typing, inline rejection, Enter, native
paste followed by Add, and the error in both themes and in an 800×300 window.
No operation, CLI verb, agent-guide, shared-core or README change: site
creation still uses the existing item.add path and the same URL contract.

## And the preview waits with it

Keeping a half-typed address in the field left the line under it reading the
draft as a promise. `https://` rendered "Add  as a live site" — a sentence with
the address missing — and `file:///etc/passwd` was announced as a live site
directly above the error refusing it. The preview now waits while an address is
still being typed, and says which schemes can be projected when the answer is
already no, rather than promising an add that submit will turn down.

## The sheep harness

An agent enrolled with `--harness sheep` now runs in a cell at a
[sheep](https://github.com/dglazkov/sheep) home instead of a subprocess on
the laptop. The rc, its routing and its custody rule stay where they were:
the rc still starts every turn, and what moves is the machine the agent's
shell runs on. The spike (phase 0) answered the open identity question
without a new credential. The rc mints an `isocan pass` for the agent's
own actor, the pass rides into the cell as a pasture secret, and the
pasture's setup redeems it once, so the pass never appears in a prompt or
a transcript.

Phase 1 made it a harness like the others. The spike's hand-written
`sheep` block in `config.json` is gone: `isocan harness` finds `sheep` on
the PATH and the home its kennel names, and the rc row carries that home
and kennel beside the sheep id, so a summons from any directory resumes
the same sheep and a kennel pointed elsewhere since is refused. Before a
birth the rc reads the pasture's herd, so a sheep the row forgot is
resumed rather than born twice with a second pass. The birth narrates
each step and what it costs, a cell quiet past the home's idle period is
said to be probably running setup, and a station asked to reach a canvas
on the laptop's daemon is refused at the summons with both homes named.
The face gets tool beats by reading the transcript every three seconds
during a turn, because `sheep attach --json` prints only the final entry;
a sheep-side journey (sheep#7) asks for an entry stream that would
replace the read, and journey 1 was amended to say so.

Walked on the deployed station against a scratch canvas at dev.isocan.io:
a birth answered in 2 minutes 17 seconds with each bash call on the face,
and a resume from the herd twelve minutes later. That resume hit the
station's container service dropping mid-setup; the agent remembered the
first comment but ended its turn without a reply, and the next summons
worked. No new operation, no new verb: `--harness sheep` on `rc add` is
the only gesture, and the agent guide and `isocan harness --help` say
what it means.
