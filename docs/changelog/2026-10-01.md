# 1 October 2026 — Groups by hand, a cricket bat, and a composer that had lost the keyboard

## Groups by hand: researched, decided and built in a day (#373)

Dion asked for three things: an easier way to get items in and out of groups,
stacks, and a shadow while dragging. Mid-way he added a fourth, a drag that
other viewers can watch.

**Research came first** (`ee4e88b6`). It is a note checked against the tree,
with a prototype beside it. It found three facts:

- **Nothing could drag an item out of a group.** The frame grows to keep it, by
  design.
- **⌘ was the one modifier unused on a press or drag.**
- **Moving out needs no new op.** `transform` with `containerId: null` already
  moves and reparents to the canvas in one undo.

**Dion decided the open questions the same afternoon** (`dd3b8b58`). Stacks are
shared and remembered, and opening one is not. ⌘-drag-out lands where the
pointer is. A plain drag never detaches. He added one rule: **hover must say
what a press takes.** The dashed outline had been CSS `:hover` on whatever was
under the pointer, so it outlined a member while a click took its group.

**Then four phases, each landed whole by the conductor:**

1. **The lift** (`3679d908`). A dragged item wears `--shadow-lift`, with no
   scale and no offset, so where you see it is where it lands. It is its own
   `.lifted` class on the drag's roots, so a group's frame lifts and its members
   don't.
2. **⌘ takes one item** (`6e9688c3`).
   - Core's `groupAim` decides both the outline and the press.
   - ⌘ reaches the item.
   - ⌘-drag can carry it out, with an *Out of …* pill.
   - `isocan mv --out` gives agents the same move.
   - The hover code loads lazily, and `groupAim` got its own module because
     sharing one with eager code pinned it into the entry chunk.
3. **Others see the drag** (`d9d1dc04`).
   - The drag rides presence, never ops, so nothing replays.
   - A ghost cancels once its item has left `from`, holds through the release
     race, and glides home if the mover leaves.
   - It is written as a CSS `translate`, so the remote-drag frame census reads
     p99 16.8 ms with nothing over 32 ms.
   - The entry chunk went *down* with the feature in it. One `follow()` helper
     replaced fifteen hand-kept listener calls.
4. **Stacks** (`f95ec5e4`).
   - A group shown as a seeded messy pile: turns hashed from each member's id,
     so every viewer sees the same pile.
   - It fans into a hand and opens into a grid.
   - It is stored as `GroupLayout.display`, and members never move.
   - `isocan canvas group stack` is the CLI twin.

**Every phase ended in a browser journey** in `scripts/journeys.mjs`: `lift`,
`group-reach`, `live-drag` (two browsers) and `stack`. Three phases first
landed over the entry ceiling. Each time the builder found honest bytes rather
than asking for a raise, and the chunk ends at 701,186 against 701,300.

Three small limits are on the project's Open roster:

- a frozen tab that stays connected keeps its drag ghost up;
- a card ⌘-dragged out of an open stack isn't seen live by viewers;
- stacked members still steer snapping, the minimap and auto-placement.

## Submenus that forgive a diagonal (`9bd1a334`)

Moving from *Style* across to its submenu closed it on the way, because every
row the pointer crossed took the hover. The one shared ContextMenu now uses
`lib/menuaim.ts`:

- **A safe triangle.** While the pointer heads into the submenu, the rows it
  crosses are held off.
- **Hover-intent timers.** Open after 100 ms, close after 300 ms of grace, and
  hover hands back after a 300 ms stop inside the triangle.

Clicks and keys never wait. The `submenu-diagonal` journey walks the diagonal
at a hand's pace and fails without the fix. A first version walking fast
passed on the grace timer alone.

## A text composer that had lost the keyboard (`30c897b9`)

The nightly journeys went red overnight: four of them could not type into a
new text node. `git bisect` named `a22c3f1a` (30 Sep, text colour and fonts).
That commit made the composer mount only while open, to save first-paint bytes.
The composer's focus logic assumed it stayed mounted. On a fresh mount the
render that would have focused the field never came, so typed words went to the
canvas's single-key shortcuts instead.

The fix is one line, `placeCaret` starting true. A jsdom test now mounts the
composer for real, so the suite catches it next time, not just the nightly run.
The fix is on main but not yet promoted to isocan.io.

## A test that read the developer's git config (`7f9f2307`, lesson 105)

`module add from a git spec` failed on any machine whose global gitignore lists
`dist/`. The fixture's `git add .` silently skipped the module it then
installed. Its git now runs with `GIT_CONFIG_GLOBAL=/dev/null`, and a guard
finds every test that commits a fixture.

## The roadmap opens with what needs a person

`docs/verify/` has been the queue of things built, shipped and never exercised
by a human since 20 September. But its table was hand-kept in its own README,
a copy of what each walk's `**Status:**` line already said, and the roadmap,
where people go to ask what's left, did not show it at all. The same kind of
second copy the roadmap was built to get rid of.

Each walk now says its own state in front matter: `status`, `since`, `never`
(what has never been exercised), `needs` (what the person needs in hand) and,
when there is one, `issue`. Core's `verifyStatus` reads it through the same
front-matter reader as `docStatus`. `scripts/roadmap.mjs` puts the result
first on `docs/ROADMAP.md`, ahead of everything waiting on somebody building,
because this is the one list waiting on somebody *using*. The README's table
is now a pointer. A walk that leaves out what was never exercised, what you
need, or a date fails the roadmap's check, and so does a walk marked `broken`
with no issue: a person handed a walk should not have to guess.
