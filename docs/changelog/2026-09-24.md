# 24 September 2026 — The writer stops waiting on the home

The day began with the findings from the 23rd's wireframes walk on
isocan.io. The worst was not a wireframe bug: every write on a laptop
daemon queued for minutes behind a blob check. Once that was fixed, the
check itself was cut from thousands of requests to a handful. The rest of the
walk's findings were answered too: arrow labels, round 1's maybes, text
headings and choosing a design system. Wireframes then took five more asks
from real use. Several things that only a person could do got a CLI verb or a
web door, and a standing agent now says when it arrives.

## The isocan.io write stall (lessons #95, #97)

**The blob check held the single-writer chain.** `Engine.reconcileBlobs` ran
whole inside `enqueue`, sending one HEAD to the home per blob. The blob keeper
runs it for every replica canvas every ten minutes. On a laptop replicating
an isocan.io canvas of 1,450 blobs at ~171 ms a HEAD, every write on the
daemon queued for about four minutes: every canvas, every home. It looked
like `isocan set` and `wire link` taking minutes while the write did land,
and like every home link reporting an unfinished dial at the same moment.
The measurement settled it: a harmless `set --prop` every 30 s took 0.7 s
steady, then 23.5 s, 301.9 s and 32.5 s during a sweep. Because the output
itself arrived late, the wait was in the daemon, not the CLI. A locally homed
canvas has no home to ask, which is why a local daemon never showed it. The
chain now takes only the listing. The HEADs and uploads are content-addressed
and idempotent, so they run off it.

**Then the check stopped asking one question per blob.** Off the chain, it
still meant ~2,550 requests a sweep from one laptop. Nearly all of them were
about bytes the home had confirmed the sweep before, at a door that meters by
address and answers a tripped limit with a silent 401 on somebody else's
request. The home now answers for a list: `POST .../blobs/present`, up to
1,000 hashes a call. It sits behind exactly the HEAD's gate, so a view-only
member may ask what it may already HEAD. The route is served by FileStore and
by CloudStore, so it covers isocan.io. The keeper also remembers what the home
said yes to, for six hours, and does not ask again. A quiet canvas now costs
its home nothing: 1,100 blobs went from 1,100 requests to 2, and 40 confirmed
blobs from 40 to 0. A home older than the route gets one HEAD per hash and
another try at the batch an hour later, so the deploy that adds the route is
noticed without a restart. "I could not ask" is still never answered by
uploading. `isocan blobs` never trusts the memory, because a person asking
gets a fresh answer.

**Then the same shape twice more.** `putBlob` waited for a replica's upload
and its confirming HEAD inside the chain, so one large file to a slow home
held every write on the machine. The migration preview asked the home from
inside the chain as well. Both now do only local state on the chain, and a
test holds the home's socket open for each and requires a write to land
meanwhile. Lesson #95 names the shape: the network kept inside the lock that
exists for a read-modify-write.

## The walk's other findings

**Arrow labels no longer sit on each other.** Lanes are 26 world units
apart, so below ~0.7 zoom two lane labels near the same x become one pill.
Placement had only asked whether a label's own run could hold it, never
whether a neighbour's label was already there. A collision pass now gives each
label one number, `show`: the lowest zoom at which it is drawn at rest. The
stylesheet compares it with `--scale`, so zoom still re-renders nothing. The
arrows drawn at rest go first, so pointing at a screen never moves a label
that is already there. A later label slides along its own run, and one that
still collides waits for a zoom where it clears. Routes never change.

**Round 1 over-includes, and keep prunes.** Phase 6 found Jev's P(yes)
overconfident by ~0.4, so "yes ≥ 0.5 or leave it out" was leaving out
screens people wanted. Screens from 0.3 to 0.5 are now drawn in their place
as *maybe*, with a dashed outline and a tag from a module underlay. Nothing is
written into the screen's own file. The mark is derived from `wireMaybe` and
not `wireKeep`, so keeping a maybe is still one op and one undo, and the mark
comes back if the keep is undone. The 0.3 floor comes from phase 6's recorded
answers: in that band Jev was right no less often than in 0.5–0.7. Those
answers were to a different question, and `compose.ts` says so. Later in the
day the floor was measured again on round 1's own runs and held.

**A text node's headings scale with its words.** A `#` was drawn at the card
renderer's fixed 18px against a body that runs from 16 to 128px. In a large
node the heading was smaller than the paragraph under it: at display size,
a seventh of it. Headings are now in em. `textBox` had learned the 18px too,
so it now measures at h1's 1.5em, or the bigger heading would have been
cropped, which is lesson #94 again. The type-size ratchet went up by four,
with the reason written beside it: these are ratios, not new pixel sizes.

**Choosing a design system got a web door and a verb.** The web had no way
to say which DESIGN.md governs the canvas or a group, and `design set`
printed nothing about what it governed. `designUse` in core makes an item
the system of its scope. If that scope already has a system, the item's
words become a new version of it, byte for byte what `design set` sends.
If not, the item takes the role in place. That is one op and no new op type,
and the CLI's `isocan design use` and the item menu's "Use as design system"
are held to the same ops against one daemon. `design set`, `import` and
`use` now also say what they govern.

**The entry chunk stayed under its ceiling without moving it.** With the
maybe marks, the chunk measured 730,173 against a CEILING of 730,100. A
behaviour-preserving trim of `core/textnode.ts` took it to 730,001: one
`oneOf` guard instead of three copies, and a label derived from the id instead
of spelled out. The day's later work spent some of that room, and every
commit said what it spent. The chunk ended the day at 730,069. The
unused-exports ratchet (39) read 42 on the landing tree, because three
`design use` helpers had been exported and were only used where they were
defined. They are now private.

## Two acts that only one surface could do

**`isocan docket`.** A persona finding on the board is answered with a mark:
✅ accepts and ❌ rejects. Only the web could do that, so an agent could read
a finding and not answer it. "A docket only a web app can read is a
dashboard with a second name." `reactOp`, the chip's toggle, moved into
core. `docketAnswer` is built from it, and `scripts/docket.mjs` reads its
marks from core. That makes the chip, the verb and the script the same bytes
in the log, and they cannot disagree about which emoji is which. `--because`
leaves the reason as a comment in the same undo group.

**`choose` on the web.** Converging an exploration was terminal-only.
Nothing in `packages/web` imported `convergePlan`. `convergeOps` in core is
now the one list: the chosen version onto the source, then every child to the
trash. The CLI and the item menu's "Choose this variation" both send it under
one group, and a test holds the menu's ops equal to the ones the CLI logged
against a real daemon. One ⌘Z brings back all three.

## Wireframes, from real use

- **Plain words.** Round 1 used to ask about archetype ids described by
  component ids. It now asks in plain words, "a list of things you can
  scroll…". This was measured on the same 350 screens against ids re-asked
  that day: better on every accuracy measure, calibration unchanged, and
  17–20% fewer tokens. The gain is small, and no single comparison clears
  McNemar, which the commit says. The spec never holds the words.
- **Fleshed by default.** "Why am I not getting the pass where it flushes
  out and puts text on top of the blocks?" Dion expected sample content to
  be part of composing, not a second act. `wire` and `/wire` now ask the pack
  question with round 1 and fill in round 3, all in the flow's own op group,
  so one undo removes it all. `basic` / `--basic` composes plain grey wires.
  `--flesh` still works so older scripts keep running.
- **The prototype sits above its flow.** It used to sit off to the right and
  drift further away as variations collected. It is now centred over the
  flow's own kept screens and clears every arrow lane. A rebuild moves it
  back there, unless a person has moved it: `wirePrototypeAt` remembers where
  the composer put it.
- **Selecting a prototype lights its screens.** Every kept screen it plays,
  guests included, pulses once and keeps a ring, and the rest steps back
  under a veil. This is one person's view, so nothing is written. Agents ask
  the same thing with `wire kept --prototype`. The property keys moved off
  the first-paint record to pay for it.
- **`by` on the spec.** A stub's dice and Jev's choice looked the same to a
  later reader, so keep marks could not yet serve as calibration labels.
  Every composed screen is now signed with the actor, the answerer (jev,
  stub or agent) and the route. A home that fell back to the stub says stub.

## Standing agents announce themselves

Asked on the day: "When my pet joins, can he announce himself in the chat so
I know?" Until now the only sign was the tray and a line in the rc's
terminal, on a machine the canvas's person may never see. The **rc room**
writes the line in the agent's own name, and only after the hold comes back,
so "is here" is never said of an agent that did not become answerable. The
home or the daemon would each post twice or post again after a restart. The
room is one writer per canvas and agent, and it knows the listen policy the
line reports. **The roll-call rule** (`rollDue`, core): "is here" first, then
"is back" only after more than five minutes away. So a flapping connection
or a crash-restart says nothing, and a deliberate stop says "stepped away".
**No new op and no new field.** A roll line is an ordinary reply whose
comment is a record, and `Comment.record` widens from `true` to
`true | "here" | "back" | "away"`. Every reader tests it truthily, so it is
still a record everywhere. Records now never wake an `--all-ops` agent.
Before this, two agents' hellos would have woken each other, which is a loop.
`isocan rc --no-announce` and `rcAnnounce` in config keep it quiet.

## The first small persona (#205)

`librarian` is the first persona machinery hands to a model: Haiku, a
declared budget of $0.05 and 6 turns a run, one number (relative links in the
docs that point at nothing, 4 on the day, a ratchet), and `escalate: reviewer`.

## Voice runs the canvas's skills (`f3b9daea`)

Asked to build wireframes and then told "you know there's a /wire skill — use
that", a voice session said it had hit "an issue while trying to enroll the
wireframing skill" and drew nothing. Three second copies of things the
composer already had were the cause. The session's brief read the compiled
built-in commands, so `/wire` — a module command — was a word it had never
heard. There was no tool for running a command, and the rule taught
`say "/build …"`, so a skill sounded like something you enrol. And even a right
`say "/wire …"` posted straight to the Chat, skipping the composer's local
door, so no dialog opened and, with nobody parked, nothing happened.

`WebHost.commands` now hands a module the composer's own list, and
`WebHost.runCommand` is the composer's send in its order: a module command
that opens a dialog opens it in the page (`/wire <request>` composes on the
spot), and anything else is posted with the selection attached. Voice has a
`run_command` tool and the rule names it. The answer says whether the command
RAN or was only POSTED, so a voice cannot report asked-for work as done. The
commit broke `npm run typecheck` in a test — vitest was run after the last
edit, the typecheck was not — and another session fixed it in `34f9b11d`.

## Judge: the corpus becomes isocan's own, and phases 1–2 (`25d6cf46`, `6df41215`, `529cd2fc`)

Judge was designed to calibrate on a personal knowledge base. The person ruled
that a separate project isocan does not read into, and chose isocan's own
wireframe decisions: round 1's P(yes) for each screen against what a person
then kept or took out. Re-cutting the walk around that found wireframes had
already done judge's groundwork — its phase 6 had measured this judge on
public screens (overconfident by about 0.4, ECE 0.39) and made every screen
carry `need` and `by` — so phase 1 became a reader, phase 3 became moving
wireframes' taste-set maybe band to the curve, and phase 4 retired.

Phase 1 is `isocan judge corpus`: it replays a canvas's log twice, the flow's
acts and the flow's plus the person's, and labels where they differ. It found
the labels record only disagreement, so phase 2 decided an untouched row in a
flow the person worked on counts as agreement, with the two kinds counted apart
on the page. Phase 2's harness writes that page, and its builder found the
pooled curve cannot decide "flat" — agreement labels step at 0.5 whatever P is
worth — so flat is read inside the bands. Both phases are part-done: the real
page needs the person's own rows, and will say it cannot conclude until about
470 labelled rows exist, which accrue only as `/wire` is used.
