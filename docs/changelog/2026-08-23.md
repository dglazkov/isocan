# The lid closes, and the daemon learns to dial

**2026-08-23** · 8 commits · 27 files · +3,900/−139 · Dimitri Glazkov, Dion Almaer

A short day with one large thing in it. Phase 6 lands: a local daemon stops
being a home and becomes a *replica* of one — it dials, presents a badge,
forwards every write, carries presence both ways, and reconnects by saying "I
have through N". Solo stops being its own topology and becomes the multiuser
one with a single member, which is what Scene 0 always claimed it was.

## The seq cursor, and the lid-close beat

The connect handshake grew a second answer. `/ws?projectId=X&since=N` now
replies either with `resumed` and the tail as ordinary `op-applied` messages,
or with a full `snapshot` when it cannot serve that tail — **one contract with
two halves**, and every client handles both. That is Scene 4's beat 7 made
literal: the laptop reopens at 9pm, says what it already holds, and the evening
streams down through the same reducer crash recovery replays, because it is
that code path.

Whether a tail is servable turned out not to be the obvious question. "Is my
cursor past the compaction horizon" is wrong, because compaction retains a
**set, not a suffix** — `chooseRetained` walks undo/redo causes back into the
past, so the live log after a GC has holes. Contiguity from `since + 1` is the
honest test.

And contiguity alone has a blind spot that review caught before the phase
closed: `[].every()` is vacuously true, and `chooseRetained` returns `[]`
outright for `keepOps <= 0`, which the GC route passes straight through from a
request body. A canvas at seq 6, a `keepOps: 0` collection, a socket at
`?since=2` — and the answer was `{"type":"resumed","from":2,"lastSeq":2}`,
telling the client it was current with four ops missing. A browser tab
self-heals on the next op, because the gap check fires. **A quiet canvas leaves
nothing to fire** — and from this phase on, that client can be a replica daemon
that believes it is in sync. The fix is completeness beside contiguity. The
shape is the memorable part: a guard written as a predicate over a list is a
guard that says yes to the empty list.

## The connection, and what a replica actually is

`HomeLink` holds a bearer badge at the home, opens one socket per canvas,
applies arriving entries with the home's seqs verbatim, and reconnects with
backoff on its cursor. Writes forward — ops, undo, redo, colours, and blobs —
so the home stays the single writer and the replica never numbers anything
itself. A write with the home unreachable **fails loudly and says the write was
not made**; queueing it would have been half-building phases 10 and 13.

The one-origin rule is now structural rather than a promise. A replica does not
register the page server, and therefore does not mint the cookie badge the page
server mints — that half is easy to leave behind, and wasn't. An unmatched GET
gets a 404 that names the home. The marker gains `home` beside `projectId`,
which is exactly what `offline-birth.md` had already assumed it would.

Two findings redrew the map. A replica's oplog is a **cache, not a copy of the
history**: a joining replica can only present cursor 0, so its log begins where
it joined — state converges exactly, history does not. And a replica discovers
canvases through a home-wide `GET /api/projects`, so a replica of a
*multi-tenant* home would mirror strangers' canvases onto a laptop. Correct for
solo, which is all this phase proves; phase 7's to narrow.

## A correction worth more than the fact

The phase nearly recorded that a person cannot be one actor in the tab and the
terminal because of `reincarnate`'s 30-minute window, and that this was where
phase 6 leaned on phase 8's passes. Measured, it is neither. The refusal is the
registry's **liveness** clause — *"becoming them would be one actor wearing two
faces"* — and with no live face the same `--as` claim succeeds, which is the
remedy the error itself prints. The guard reads per-daemon presence, which was
true before this phase too, so the constraint is pre-existing and passes do not
own it. A finding that names the wrong mechanism sends the next phase to fix
the wrong code.

## Dialled, and a fact that expired inside a day

The phase closed with one item open: everything it proved had run against local
daemons, and the address it was said to have was undialled. So it was dialled —
a replica pointed at **dev.isocan.io**, badge minted at the real door, one
socket over `wss:` through the load balancer. Fourteen checks, all green: the
canvas born through the replica exists at dev, a write forwards and arrives by
name, and the lid-close beat plays across the internet against a Cloud Run
instance that cold-started from zero. The local oplog came back contiguous —
**it resumed**, it did not re-snapshot, which is the phase's whole claim.

The run also overturned a finding from the day before. Phase 5 had measured
`/healthz` on the dev home as a branded 404 from Google's frontend, never
reaching the container; that measurement is why `healthPath()` exists. One day
later the same path returns **the daemon's own body** — `pid`, `root: /app`,
byte-identical to `/api/healthz`. Which end of the wire changed is not
established, and that is the finding: the fact the map rested on was never ours
to hold.

What survives is the argument that never depended on the frontend, and the same
measurement sharpens it — `/healthz/` and `/HEALTHZ` come back as a kilobyte of
`index.html` at 200, so a check on a near-miss path is green forever and cannot
fail for the right reason. `/api/` is the one prefix the SPA fallback does not
answer cheerfully. The map now keeps both reasons in order, the expired one
first: dropping a dead reason quietly teaches the next reader that the
survivor was always the whole story.

## And a replica is not a backup

Walking Scene 0's multi-device beat by hand turned up the day's other correction.
Two replicas of one home, a file added on the first: the second machine lists the
item perfectly and holds **zero bytes of it**. Blobs a replica did not upload
itself are streamed from the home on demand and not cached — the blob directory
was still empty after reading the file through twice.

Put that beside the earlier finding that a replica's oplog begins where it
joined, and the shape is clear: a replica holds the canvas's *state*, not its
*history* and not its *bytes*. The map's backups bullet said "the best backup
remains a thick replica — sovereignty by replica is also disaster recovery",
which was written before replicas existed. It fails in the one direction that
matters: a replica looks complete right up until the home is gone. Disaster
recovery is PITR and the scheduled export, full stop.

It lands on phase 13 hardest, where re-homing is drawn as "a thick replica
offers its store to a new home … hello, badge, offer, replay" — and the store it
would offer is missing exactly the two things a replay consumes.

The beat itself works, including the race nobody had run: a marker carried to a
second machine by git resolves against a replica that has never heard of the
canvas, without a `duplicate-id`, even when the command beats the home
connection's first sweep.

## The share, and a door that finally refuses

Phase 7 followed the same day. Every canvas is born with a standing **link
grant** — the status quo demoted to one revocable row — and the two policy lines
phase 3 left marked became the design's flowchart: already admitted → bootstrap
→ a grant admits → refused. Canvases that predate the change get their row from
a migration, because a door that refuses without one would have made every
canvas already in the world unreachable.

Revocation is a tombstone rather than a delete, because provenance points at a
grant id and phase 9's sweep has to be able to read the row it is expelling
people from. Turning the link off stops *new* arrivals; the people already there
keep their access until that sweep exists, and the dialog says so rather than
implying an expulsion that will not happen.

Sharing is the first gesture that is **not a canvas op** — it acts on who may
knock, not on what is on the canvas — so there is no new `Operation`, parity
lives at the daemon API, and a test asserts the oplog does not move across a
grant and a revoke. One endpoint, a button beside the facepile and
`isocan share`.

Two holes closed quietly. `actor.claim`'s `projectId` is admission-checked now,
or "is this name taken here" would be a probe into a room you were never let
into. And `/api/ops` had been admitting *after* the write — invisible for five
phases because the check could not refuse, and not a refusal at all the moment
it could.

## The same bug, three times in two days

The day's real lesson is a shape. `/healthz/` answers 200 with the app shell.
`/c/<id>` rendered a blank page. And a socket refused by the door fell into the
ordinary reconnect backoff, so a switched-off link looked like a network blip
forever. **This system's default answer to a wrong address is a cheerful one** —
which is exactly the failure mode that cannot be caught by a check that only
asks whether something answered.

All three are now legible, and the door was not loosened to do it. A caller's
mistake was being mis-reported too: a DELETE with a JSON content-type and no
body returned 500 "internal error" on three routes. The handler gates on
`statusCode` now, because Fastify already tags a caller's mistake 4xx and its
own failures 5xx — 4xx is about the request and its message is safe to repeat;
5xx is ours and stays opaque.
