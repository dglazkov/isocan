# Phase 6 to phase 9 in a day, and a design system drawn as itself

**2026-08-23** · 39 commits · 334 files · +27,875/−1,257 · Dimitri Glazkov, Dion Almaer

The longest day in the project so far, and two of them running side by side.
On one track the multiuser build goes from phase 6 to phase 9 in a single
Sunday — the daemon learns to dial, a link becomes a share, escalation becomes
one command, and identity becomes something you can prove and revoke. On the
other, the canvas grew a design-system viewer, an eval programme, four standing
reviewers, and a fistful of fixes for things that had been quietly wrong.

Phase 6 lands first: a local daemon stops
being a home and becomes a *replica* of one — it dials, presents a badge,
forwards every write, carries presence both ways, and reconnects by saying "I
have through N". Solo stops being its own topology and becomes the multiuser
one with a single member, which is what Scene 0 always claimed it was.

## The seq cursor, and the lid-close beat

The connect handshake grew a second answer. `/ws?projectId=X&since=N` now
replies either with `resumed` and the tail as ordinary `op-applied` messages,
or with a full `snapshot` when it cannot serve that tail — **one contract with
two halves**, and every client handles both. That is Scene 4's beat 7 made
literal: the laptop reopens at 9pm, says what it already holds, and the evening
streams down through the same reducer crash recovery replays, because it is
that code path.

Whether a tail is servable turned out not to be the obvious question. "Is my
cursor past the compaction horizon" is wrong, because compaction retains a
**set, not a suffix** — `chooseRetained` walks undo/redo causes back into the
past, so the live log after a GC has holes. Contiguity from `since + 1` is the
honest test.

And contiguity alone has a blind spot that review caught before the phase
closed: `[].every()` is vacuously true, and `chooseRetained` returns `[]`
outright for `keepOps <= 0`, which the GC route passes straight through from a
request body. A canvas at seq 6, a `keepOps: 0` collection, a socket at
`?since=2` — and the answer was `{"type":"resumed","from":2,"lastSeq":2}`,
telling the client it was current with four ops missing. A browser tab
self-heals on the next op, because the gap check fires. **A quiet canvas leaves
nothing to fire** — and from this phase on, that client can be a replica daemon
that believes it is in sync. The fix is completeness beside contiguity. The
shape is the memorable part: a guard written as a predicate over a list is a
guard that says yes to the empty list.

## The connection, and what a replica actually is

`HomeLink` holds a bearer badge at the home, opens one socket per canvas,
applies arriving entries with the home's seqs verbatim, and reconnects with
backoff on its cursor. Writes forward — ops, undo, redo, colours, and blobs —
so the home stays the single writer and the replica never numbers anything
itself. A write with the home unreachable **fails loudly and says the write was
not made**; queueing it would have been half-building phases 10 and 13.

The one-origin rule is now structural rather than a promise. A replica does not
register the page server, and therefore does not mint the cookie badge the page
server mints — that half is easy to leave behind, and wasn't. An unmatched GET
gets a 404 that names the home. The marker gains `home` beside `projectId`,
which is exactly what `offline-birth.md` had already assumed it would.

Two findings redrew the map. A replica's oplog is a **cache, not a copy of the
history**: a joining replica can only present cursor 0, so its log begins where
it joined — state converges exactly, history does not. And a replica discovers
canvases through a home-wide `GET /api/projects`, so a replica of a
*multi-tenant* home would mirror strangers' canvases onto a laptop. Correct for
solo, which is all this phase proves; phase 7's to narrow.

## A correction worth more than the fact

The phase nearly recorded that a person cannot be one actor in the tab and the
terminal because of `reincarnate`'s 30-minute window, and that this was where
phase 6 leaned on phase 8's passes. Measured, it is neither. The refusal is the
registry's **liveness** clause — *"becoming them would be one actor wearing two
faces"* — and with no live face the same `--as` claim succeeds, which is the
remedy the error itself prints. The guard reads per-daemon presence, which was
true before this phase too, so the constraint is pre-existing and passes do not
own it. A finding that names the wrong mechanism sends the next phase to fix
the wrong code.

## Dialled, and a fact that expired inside a day

The phase closed with one item open: everything it proved had run against local
daemons, and the address it was said to have was undialled. So it was dialled —
a replica pointed at **dev.isocan.io**, badge minted at the real door, one
socket over `wss:` through the load balancer. Fourteen checks, all green: the
canvas born through the replica exists at dev, a write forwards and arrives by
name, and the lid-close beat plays across the internet against a Cloud Run
instance that cold-started from zero. The local oplog came back contiguous —
**it resumed**, it did not re-snapshot, which is the phase's whole claim.

The run also overturned a finding from the day before. Phase 5 had measured
`/healthz` on the dev home as a branded 404 from Google's frontend, never
reaching the container; that measurement is why `healthPath()` exists. One day
later the same path returns **the daemon's own body** — `pid`, `root: /app`,
byte-identical to `/api/healthz`. Which end of the wire changed is not
established, and that is the finding: the fact the map rested on was never ours
to hold.

What survives is the argument that never depended on the frontend, and the same
measurement sharpens it — `/healthz/` and `/HEALTHZ` come back as a kilobyte of
`index.html` at 200, so a check on a near-miss path is green forever and cannot
fail for the right reason. `/api/` is the one prefix the SPA fallback does not
answer cheerfully. The map now keeps both reasons in order, the expired one
first: dropping a dead reason quietly teaches the next reader that the
survivor was always the whole story.

## And a replica is not a backup

Walking Scene 0's multi-device beat by hand turned up the day's other correction.
Two replicas of one home, a file added on the first: the second machine lists the
item perfectly and holds **zero bytes of it**. Blobs a replica did not upload
itself are streamed from the home on demand and not cached — the blob directory
was still empty after reading the file through twice.

Put that beside the earlier finding that a replica's oplog begins where it
joined, and the shape is clear: a replica holds the canvas's *state*, not its
*history* and not its *bytes*. The map's backups bullet said "the best backup
remains a thick replica — sovereignty by replica is also disaster recovery",
which was written before replicas existed. It fails in the one direction that
matters: a replica looks complete right up until the home is gone. Disaster
recovery is PITR and the scheduled export, full stop.

It lands on phase 13 hardest, where re-homing is drawn as "a thick replica
offers its store to a new home … hello, badge, offer, replay" — and the store it
would offer is missing exactly the two things a replay consumes.

The beat itself works, including the race nobody had run: a marker carried to a
second machine by git resolves against a replica that has never heard of the
canvas, without a `duplicate-id`, even when the command beats the home
connection's first sweep.

## The share, and a door that finally refuses

Phase 7 followed the same day. Every canvas is born with a standing **link
grant** — the status quo demoted to one revocable row — and the two policy lines
phase 3 left marked became the design's flowchart: already admitted → bootstrap
→ a grant admits → refused. Canvases that predate the change get their row from
a migration, because a door that refuses without one would have made every
canvas already in the world unreachable.

Revocation is a tombstone rather than a delete, because provenance points at a
grant id and phase 9's sweep has to be able to read the row it is expelling
people from. Turning the link off stops *new* arrivals; the people already there
keep their access until that sweep exists, and the dialog says so rather than
implying an expulsion that will not happen.

Sharing is the first gesture that is **not a canvas op** — it acts on who may
knock, not on what is on the canvas — so there is no new `Operation`, parity
lives at the daemon API, and a test asserts the oplog does not move across a
grant and a revoke. One endpoint, a button beside the facepile and
`isocan share`.

Two holes closed quietly. `actor.claim`'s `projectId` is admission-checked now,
or "is this name taken here" would be a probe into a room you were never let
into. And `/api/ops` had been admitting *after* the write — invisible for five
phases because the check could not refuse, and not a refusal at all the moment
it could.

## The same bug, three times in two days

The day's real lesson is a shape. `/healthz/` answers 200 with the app shell.
`/c/<id>` rendered a blank page. And a socket refused by the door fell into the
ordinary reconnect backoff, so a switched-off link looked like a network blip
forever. **This system's default answer to a wrong address is a cheerful one** —
which is exactly the failure mode that cannot be caught by a check that only
asks whether something answered.

All three are now legible, and the door was not loosened to do it. A caller's
mistake was being mis-reported too: a DELETE with a JSON content-type and no
body returned 500 "internal error" on three routes. The handler gates on
`statusCode` now, because Fastify already tags a caller's mistake 4xx and its
own failures 5xx — 4xx is about the request and its message is safe to repeat;
5xx is ours and stays opaque.

## The home you answer to, and the flake that was two flakes

Phase 7.5 exists because someone tried to walk Scene 0 against the hosted home
and it cost three environment variables, a scratch storage directory, and a URL
read out of a marker file. That is not a missing feature — it is a missing
**verb**. `config.json` has had a `home` key since phase 6 and nothing could
ever write it; the error message in `refuseForeignHome` had been telling people
to set an environment variable, which is the gap confessing itself in prose.

`isocan home <url>` now checks the address answers, writes the config, and
restarts the daemon. The nicest thing in it is a refusal nobody asked for:
paste a canvas link instead of a home and it says *"that is a page at
https://dev.isocan.io, not a home — try `isocan home https://dev.isocan.io`"*,
handing back the corrected command.

Then the first claim against a busy home failed with *"Isaac" is taken here*.
The obvious diagnosis was a race — the home's registry not yet replicated — and
testing it proved it wrong: eleven names replicated, twelve seconds waited, same
failure. The real cause is a **scope mismatch**. Name allocation reads
admission-scoped queries, and a fresh replica's badge has no admissions, so
locally the name is genuinely free; the home then judges it against its own
scope and refuses. It looked self-healing on retry, but that was accidental —
the failed attempt burns a roster name and moves to the next.

## Two flakes, both timing, one of them a product bug

The armchair diagnosis was right: *flakes come from tests that depend on timing
instead of on a condition*. Twenty runs with **full output written to a file per
run** caught two — and the earlier sightings had been lost precisely because
somebody grepped a stream that had already scrolled. An unnamed flake is one
nobody can fix.

The first was not a test bug. **`Daemon.close()` never drained the engine's
single-writer chain.** Destroying a socket does not cancel the handler running
behind it, so a request that had reached `engine.claim` still had work queued —
and it wrote to the desk *after* `desk.close()` had drained and returned. Caught
in the act: a `.tmp-*` file appearing in the desk directory of a daemon that had
already said it was shut. Under test that reads as `ENOTEMPTY`; in a container
it is a write racing process exit.

The second was a test asking the wrong question: `exitCode !== null` is **null
for a process killed by a signal**, so on the SIGKILL path it read a dead daemon
as alive and waited forever on an event that had already fired.

And reading that led to a third thing: the daemon's shutdown handler had no
`catch`, so a rejecting `close()` left a process alive with its handlers
detached — stopped serving, refusing to die, which is the very condition that
forces the SIGKILL that made the second flake fire.

## Pushed, deployed, and the diagnosis that took three tries

Phases 7 and 7.5 went to dev.isocan.io — and testing there immediately showed
the name fix did not work, for a reason no local test could have caught.

`freeName` asked the home for a free name using the **claim's** scope:
admissions only. A replica's badge is minted fresh and admitted to nothing when
it asks, so every roster name looked free and the home returned the one name
guaranteed to collide. The fix had reproduced the bug inside itself.

It passed locally because a replica's sweep admits its badge in milliseconds
over loopback; across the internet the claim wins that race. The refusal then
names a canvas the badge had *not* been in when it asked, which is why it read
as nonsense.

Three diagnoses. The first was a registry race — tested, wrong. The second was
"dev is running old code", which was true and still not the cause: dev was
redeployed and the walk failed identically. The third was one badge and two
calls a single GET apart:

    no admissions           -> {"name":"Isaac"}   (taken on a canvas)
    after one admitting GET -> {"name":"Nico"}

That is the whole bug in two lines. Both earlier guesses were reasonable, and
both would have shipped a fix for a problem that was not there. What worked was
reducing to a single call whose answer could only mean one thing.

The repair gives the scope-gatherer a *reach*, and only the free-name route asks
for the wider one — admissions plus whatever a grant would admit. That is the
same trick phase 7 used when scoping the projects listing to admissions broke
replicas, and the code now says so rather than leaving two coincidences a year
apart.

## Escalation: one command, and the credential that carries the address

Phase 8. A thin guest goes thick in one line — `setup isocan.io/p/7f3a…#<pass>`
— and the canvas hands you that line itself: your own face in the pile now has
"Work from your terminal…" under it. The pass is a third desk ledger beside
badges and grants: single-use, fifteen minutes, minted by a badge already
admitted to a canvas, optionally naming one of that badge's own claims. Redeem
it and you are admitted *and* you are that person.

Two decisions are worth more than the feature. The first is that **redemption
endows the badge you already carry** rather than minting a new one, which
contradicts the design doc's own diagram — and the doc lost, because a browser
holds a cookie badge before it can ask for anything and the door deliberately
never returns a cookie's secret in a body. "The reply carries a new badge" is a
shape a browser physically cannot receive. The second is that the handed
identity is **not a claim at all**: `actor.claim --as` is refused while an
actor is visibly somebody, and the minter's tab is live at the exact instant
the pass is redeemed. A handoff is the opposite gesture — nobody asserts
anything; a holder that already is this actor said so on the record when it
minted. Two badges, one actor, which `bindClaim` has been expecting since
phase 3.

## Discovery stops being enumeration

The question phase 7 could not settle: a replica found its canvases by asking
the home what it had, so a laptop mirrored strangers' work the moment a link
was on. The pass is what fixes it — redemption writes an admission, so a
replica can be *told* what it holds instead of being *shown* what exists.
Measured before and after on real daemons: a fresh replica pointed at a home
with two link-granted canvases mirrored both in under two seconds, and now
mirrors none, indefinitely, until a pass lets it into one.

The narrowing had to be caller-stated, and that is the interesting part. `GET
/api/projects` is the browser's list too, and on a solo home the household is
one machine: a canvas made from the CLI belongs to the CLI's badge, while the
person's tab carries a cookie badge that has never been in it. Narrow the route
wholesale and a person's own front page hides their own canvas — a worse bug
than the one being fixed. So the replica asks `?reach=admitted` and the wide
answer stays the default.

What the narrowing then revealed was better than what it fixed: **two shipped
arrivals were living entirely off enumeration** — a `.isocan/project.json`
cloned by git, and a pass-less `setup <address>` — neither designed to
enumerate, both working because the home listed itself. They ask for one canvas
by name now. Removing an accidental capability is cheap; finding everything
standing on it is the work, and the suite found all three callers in one run.

## Played against dev, and the name was the tell

The walk that closes the phase ran against dev.isocan.io on deployed code, from
a shell with nothing exported: the dialog under a real face at dev minted the
pass, one pasted line put a machine that had not existed ten minutes earlier
onto the canvas as its person, and `@`-mentioning its agent from the browser at
dev woke that agent on the other machine — face in the facepile, cursor on the
canvas, reply back in the thread.

The measurement that could only be made there was the *name*. The agent was
handed **Sonia**, not Isaac — because Isaac, Kenny and Nico are all worn at dev,
and only a home with a populated roster can show that the free-name question was
asked at the home rather than in the replica's own empty scope. That was
yesterday's bug, and this is it re-measured where it lived. The other one: dev
holds six canvases and the escalated machine mirrored exactly one. Before today
it would have taken all six, because every one of them carries a live link
grant — which is the concrete shape of a sentence that has been in the
architecture map since phase 6 and is now deleted from it.

## The cheerful wrong address, four and five

An unmatched path under `/api/` answered **200 and the web app**, which meant a
replica's version negotiation with an older home was correct only because
parsing HTML as JSON throws. Phase 8 is what made that stop being theoretical —
a replica now asks its home to redeem a pass, and a home deployed yesterday has
no such route — so it answers a JSON 404 with a code. And the fifth: a pass
landing in the address bar of a tab that is *already open* is a same-document
navigation, so nothing reloads and the credential simply sits there. Found in a
browser, not in a test. The general lesson is about fragments rather than
passes — a credential in a `#fragment` is invisible to the one event a SPA
relies on, so anything arriving that way has to be read at load *and* on
change.

## The canvas side, which was not a footnote

Twenty-seven of the day's commits never touched the home. They are here because
the app kept finding things about itself.

**A design system, drawn as itself.** `parseDesign` had turned a DESIGN.md into
a real model since the day it shipped and the web app used it nowhere — so a
design system arrived on the canvas as a wall of collapsed key/value text,
which is the one thing a document about how things should look must not be.
Now every token is drawn as the thing it describes: a colour is a swatch, a
type style is set in its own face at its own size, a spacing step is a bar that
long. Two things a picture cannot do — `{colors.primary}` resolves through the
same helper the CLI uses, and every swatch wears the contrast ratio it can
actually carry, so a palette that cannot hold words says so where the palette
is rather than in an audit three weeks later.

**Items stopped landing on each other.** Dropping six files made a pile:
`addFiles` gave every one of them the same anchored placement, and an anchored
placement always resolves to the same coordinates. Fixed in the resolver rather
than either client, so every path that adds an item gets it — the spot you ask
for is honoured exactly whenever it is free, and only a collision moves
anything. The exception mattered more than the rule: ink is where the pen drew
it, so drawings and annotations are never tidied.

**⇧F fits an item to its content**, several at once, settling them so nothing
overlaps. The interesting part was measuring an HTML page without loosening the
sandbox that keeps it away from the app: the page is *asked* rather than
inspected, in a hidden frame with the identical sandbox and a few lines of our
own script that measures from the inside and posts the answer out.

**Selecting an item lets you scroll it** without stepping inside, because
scrolling is a wheel gesture and moving is a pointer gesture and they do not
have to collide. And entering an item stopped selecting its entire text, which
had been the actual complaint.

**A marketing site**, built against `pbakaus/impeccable`'s craft floor, with a
real multiplayer screenshot driven headless against a live daemon — three CLI
agents with real presence and a person in the browser.

**An eval plan and the first graders.** `docs/projects/evals/plan.md` argues that the oplog
already records the expensive part: undo is a labelled failure, and a version
stack is a preference pair somebody produced for free. `scripts/grade.mjs`
measures a screen eight ways.

**Four standing reviewers**, with the memory that makes them cumulative, and
`docs/reviews/lessons.md` — the failure modes this codebase has actually
produced, each with the guard that now catches it.

## The bugs worth remembering

Three of the day's fixes were the same shape: a thing that looked like it was
working.

- **A grader that scored a broken page 8/8.** The in-page probe had a syntax
  error; `Runtime.evaluate` answers that with `exceptionDetails` rather than
  rejecting, so every reading came back `undefined`, every fallback fell to
  empty, and every check passed vacuously. Found by mutation-testing it against
  a bug we had actually shipped. It now has a fixture built to break all seven
  checks and fails if any stays silent.
- **A test that could not fail.** The guard written for the "null is working"
  bug defined its own copy of the naming rule and asserted on that, importing
  nothing from `src/`. The bug was reintroduced and it passed 10/10.
- **⌘Up walked sideways.** "In that direction" compared far edges, so a
  neighbour in the same row counted as *above* whenever it was a pixel shorter
  — and two screens on a real canvas were 434px and 433px tall.

And one that was mine and never left the machine: `git add -A` while four
review agents were writing the tree swept a live mutation into a commit about
frontmatter, and `main` briefly carried a reducer with `item.add`'s trash check
deleted. With agents in the room, `-A` is a claim that everything on disk is
yours.
