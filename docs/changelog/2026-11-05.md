# 5 November 2026 — Journey failures leave evidence

The November 2 journey walk used nearly the entire job budget, then lost its
reporting step before the workflow enforced failure. The November 5 walk
finished but reported twelve failures. This work separates harness reliability
from product diagnosis; it does not claim the nightly walk is now clean.

Canvas navigation now waits for the requested canvas's world and for its
`canvas-finding` loading surface to leave. The existing real pointer hit test
still refuses covered controls. Both reported Undo journeys passed locally
before the fix, so those CI obstructions remain unreproduced observations.

Chrome socket opening, protocol replies and event waits now have finite
deadlines, with pending work rejected and timers cleared on disconnection.
Long local-judge batches declare their own measured-workload budgets. Focused
regressions cover never-ready canvases, a stalled websocket handshake, missing
replies, disconnects and late responses.

The runner now atomically checkpoints before setup, walking and cleanup, and
streams each result. The workflow rejects incomplete evidence and fails before
network reporting. Separate step budgets leave time for logs and a bounded
comment; interrupted diagnostics are best effort, never a claim of success.

A controlled latency experiment also exposed a timing error: Zen's fixed
100 pointer calls plus sleeps took 12.08 seconds when each browser response
was delayed by 80 ms. The replacement counts that latency within the movement
duration and passed the same experiment in 2.96 seconds of browser input.
Aurora, Pond and Zen now observe sleep in the browser's clock; the 3.5-second
bound and real pointer input are unchanged.

The implementation and proof record live in
[journey-guardrails](../projects/journey-guardrails/phases.md). This entry
describes the draft branch; merge and deployment require a separate decision.
