# 13 November 2026

## Exact apps on the canvas, specified

A new project, `docs/projects/exact/`, specifies a module that makes the
canvas the place an Exact app (Expo's Exact: one Contract source running
natively on the web, macOS, iOS, Linux and Android) is built end to end: a
flow map of every route on every device, live frames that click back to the
Contract line that drew them, tests as storyboards, agents' changes as
proposals pictured on every device, and signed over-the-air releases
(`92e7c6aba`). The design leans only on what Exact already exposes (the agent
driver, `contract build --json`, the source map and the design wire), so
isocan adds no compiler, runtime or operation. Two decisions followed
(`83da5cd9b`): live frames go through a paired door the shell owns and can be
turned off per machine, per screen and per bridge, with every scene still
working on captures; and once built, an agent diary goes back to the Exact
team through Exact's own `feedback`, on a person's yes.

## Phase 0: the bridge, the index and three doors

`isocan exact doctor` names the Exact checkout, Bun against Exact's pin and
the wire's protocol; `isocan exact open <app>` builds the app's index as an
item and posts a screenshot per route, a version only when the bytes change
(`e162e66b8`). A module may not spawn, so both run a release script the
person's own Exact answers, on a directory they typed, never on anything read
off a canvas.

## Phase 1: the map

`isocan exact open` lays the app out as a flow map: every route on phone,
tablet and desktop in light and dark, labelled arrows for every push, back and
tab select, the design file as the canvas's design system with each token's
uses, and an anatomy card per Contract file; `isocan exact live` re-captures
on save (`08efb5b9e`).
