### cli: setup-npx takes its ports from the worker's slice, not a listen(0) guess

`eb8f144`

The test chose its daemon port by listening on 0 and closing. Another
vitest worker's daemon could be handed that number back before setup
probed it; setup then adopted that daemon (with a birth default of its
own) as this machine's, so the fresh-machine block never ran and
report.birth was missing, as in release run 43615148472, and afterEach's
stopDaemons(port) killed whoever answered, the other worker ("Worker
exited unexpectedly"). A planted second daemon on the chosen port
reproduces report.birth undefined. Both ports now come from reservePort(),
as test/ports.ts asks, and the silent-home case dials a reserved port
nothing binds instead of a closed listener's released number. No product
change: both branches that write the reason were sound.
