## A bound of 0 cannot be tightened, so the report says what it is 0 past

The performance persona's *bytes past the last size somebody agreed to* has one
property no other goal has: its bound is the constant 0 by construction. The
number is the OVERSHOOT of `CEILING` in `scripts/bundle-ceiling.mjs`, not a
size. Every other goal gets re-asked the night somebody tightens its bound —
that is what makes tightening one an act with a consequence — and this one had
no bound to move, while the thing the decision is actually about, the agreed
size, appeared nowhere in the report.

So an `accepted` given at one ceiling went on covering creep against every
later one. Measured against the real queue: the four answered nights of 8–11
Sep read 3899, 1169, 4706 and 5799, so the smallest yes was 1169 and the
covered window 1169 x 1.1 = 1285. A night reporting 1,200 bytes past a ceiling
**12,306 bytes higher** — the raise of 11 Sep — sat inside that window and
never reached the queue. Twelve kilobytes of agreed growth, and the guard that
exists so a correct report cannot be ignored could not see it.

The finding carries the basis now. A persona goal may declare `against:`, the
command that prints what its debt is a debt against; `scripts/bundle-ceiling.mjs`
prints `CEILING` when run as a program, so there is no second spelling of the
number the hard gate enforces. A nightly finding reads *bytes past the last size
somebody agreed to is 5295, past 0 of 721200*, and `isocan persona ls` and the
board's panel print the goal as *at most 0 of what that command prints*, rather
than a 0 that reads as an absolute.

**Where it is weighed is the half worth keeping.** `findingKey`'s `goal|bound`
stays the one definition of *which question* — the basis rides beside `value`,
as a reading, and `findUnanswered` scopes an answer's coverage by it. Folding it
into identity was the obvious move and is wrong: for this goal the treadmill IS
the ceiling moving, so five nights of one question would have read as five
questions asked once, deleting the only signal that says a bound wants enforcing
rather than another answer. That signal is what produced the 11 Sep raise.
`test/review-queue.test.ts` holds both halves, and `docs/reviews/lessons.md` #55
states the shape: a bound of 0 on a derived number carries no identity, so the
thing it was derived from has to travel with it.

## `--names` exists wherever a guard says it does

The copied-rules guard has ended its failure message with "Which ones: node
scripts/measure.mjs copied-rules --names" since the day it was written, and that
flag did not exist. `measure.mjs` dispatched `--names` from an `if` on one
metric's name, so the command printed the bare count and exited 0 — handing
somebody whose commit had just reddened on 59 copied rule bodies the number 59.
`undocumented-exports` carried the same dead instruction.

`--names` is a `names()` beside a metric's `take()` now, off the same scan as the
count, and a metric that has none exits 2 instead of printing a number. Three
metrics answer it; `--list` marks which. `copied-rules --names` prints each
duplicated body with the selector that declared it first and the ones that
repeat it, biggest family first — today 59 copies over 38 bodies, the largest
being five controls agreeing about what the accent looks like.

The guard against the next one is `test/measure.test.ts`, which greps every
`measure.mjs <metric> --names` out of `test/` and `.agents/personas/` and runs
each, asserting it exits 0 and answers with more than the count. Recorded as
lessons.md #56: a comment that names a command is a claim, and nothing runs it.

## Existing areas become groups, and new canvases start there

Canvas-groups phase 5 closes the project. Conversion previews one stable
owner per item, follows annotation targets, preserves ordinary geometry and
expands frames for declared label repairs. Live and trashed areas convert in
one bounded v4 operation. Historical v1–v3 replay remains unchanged. Literal
old browsers and replicas receive no unsupported state, including on retry;
new clients show upgrade guidance without discarding queued work.

The boundary applies to every actor, including the converter's prior redo,
and ignores ordinary gesture labels so conversion stays independently
undoable. Rollback names surviving group-dependent live, trash and history
debt. It retains later primitive text and discussion. Ordinary root creation
Undo still removes a card after a collaborator moves it; grouped structural
changes retain their conflict checks.

Independent review and real walks found three more crossing points. Uploads
must capture mode before waiting for bytes; migration refusals must retain
that intent across reload; and export must capture snapshot and complete
history at one revision. Actual conversion and GC races proved the backup
checks. Firestore requires an explicit deletion for an absent boundary under
its merge semantics, and replica adoption must advertise its capability.

After integration with the latest main, the conductor's full suite passed
4,860 tests with three existing skips and all 477 files green, with Firestore
enabled. Typecheck, build, real old-client and two-daemon backup walks passed.
The final integrated entry is 733,714 bytes after Context and Personas became
deferred panels with retained state; the ceiling
stays 734,200. Normal creation, aliases and people-sharing commands were
