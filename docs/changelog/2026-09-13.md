## Canvas groups move, resize and make room for labels

Canvas-groups phase 3 closes the transform and insertion work on both clients.
Corner previews include every descendant and attached mark; cancellation drops
only that gesture's preview, and the accepted operation carries all resolved
boxes. Frame-only sizing and fitting preserve member geometry. Saved title,
brief and grid reservations drive the same placement helpers in the CLI and
browser. Add, file, text, site, document, module and sprint producers carry
membership into insertion rather than issuing a second reparent operation.
A first sandbox transcript inherits its program's group; later versions keep
the transcript's own parent, verified with an actual fenced program run.

The bounded insertion/content effects require canvas-groups-v2. Original v1
history still replays, including dense grids whose saved cells cannot hold the
new full spacing. Those grids disclose insufficient room and compress only
rendered inter-cell gaps; new layout requests enforce the full reservations.

The browser found failures the geometry tests could not: a keyboard timer
appending an empty transform after its nudge had already completed, delayed
receipts interfering with another gesture, and a file upload joining the new
canvas's queue after navigation. Queue and completion ownership now includes
the original canvas and gesture. The old history-view write guard remains
intact, as the full suite required. A canvas with 1,000 documents also exposed
unreadable previews and idle sprint subscriptions; those now stand down while
retaining selectable frames and image/video visual faces.

The conductor's final local suite passed 4,718 tests with real Firestore
emulator cases enabled; the bundle check skipped after rebase was rebuilt
and checked separately, leaving three existing ACP/dispatch skips. Workspace
typecheck passed.
Real HTTP, CLI and browser walks covered numeric transforms, both annotation
insertion orders, conflicts, all resize corners, transport ordering, nested
drops and exact undo. The 1,000-card nested fixture reached the browser 47 ms
after seeding completed, mounted no document previews at overview zoom and
fetched no blobs during movement. Pointer updates measured roughly 80–125 ms;
this is a recorded limit, not a claim of smooth 60-fps motion. The final entry
bundle is 721,172 bytes after deferring the Add form, content fitting and
operator-only refusal helpers; the 721,200 ceiling records that cost without
changing the long-term goal. After syncing upstream, delayed requests were
also checked against terminal access refusals: the refusal page stays visible,
and API badge recovery preserves the door's definitive answer.
Frozen request context and lifecycle are next in canvas-groups phase 4.

## `--names` exists wherever a guard says it does

The copied-rules guard has ended its failure message with "Which ones: node
scripts/measure.mjs copied-rules --names" since the day it was written, and that
flag did not exist. `measure.mjs` dispatched `--names` from an `if` on one
metric's name, so the command printed the bare count and exited 0 — handing
somebody whose commit had just reddened on 59 copied rule bodies the number 59.
`undocumented-exports` carried the same dead instruction.

`--names` is a `names()` beside a metric's `take()` now, off the same scan as the
count, and a metric that has none exits 2 instead of printing a number. Three
metrics answer it; `--list` marks which. `copied-rules --names` prints each
duplicated body with the selector that declared it first and the ones that
repeat it, biggest family first — today 59 copies over 38 bodies, the largest
being five controls agreeing about what the accent looks like.

The guard against the next one is `test/measure.test.ts`, which greps every
`measure.mjs <metric> --names` out of `test/` and `.agents/personas/` and runs
each, asserting it exits 0 and answers with more than the count. Recorded as
lessons.md #55: a comment that names a command is a claim, and nothing runs it.
