# 5 October 2026 — A voice for the whole flow, and wave 2 walked

## Copy-edit phase 5: `isocan wire voice`

`wire copy --ai` writes one screen's words at a time, and a flow with
eleven screens got eleven voices. `isocan wire voice [screens...] --flow --n 3
--brief "…"` makes ONE text-model call for the whole flow: it returns N named
voices (a stance each — "Warm and unhurried", "Plain and quiet"), previewed on
the first two screens and saved to a file. `--from <file> --pick <k|stance>`
then writes the chosen voice to every screen it touches and rebuilds the
prototype once, all in a single op group, so one `isocan undo` restores every
word.

Why a file in the middle rather than a dialog: an agent runs this. The
preview is something it can read, show a person, or choose from on its own,
and the pick names the file so nothing has to be held in a session. The file
also carries `by` and `placeholder`, so a pick made from a stub preview says
so on the canvas rather than claiming AI copy.

What moved in core: `copyVariantsRequest` grew a `FlowScope`, and
`FLOW_ADDRESS_SEP` (`::`) joins an item id to an address so one response can
be split back to its screens (`flowCopyDeck`, `splitFlowEdits`).
`writeWireCopy` takes `{ group, rebuild }` so the flow's writes share a group
and the prototype is rebuilt once at the end rather than once per screen.
Proved against a real model: an 11-screen restaurant flow, three voices in
22 s, one picked onto 8 screens and the prototype, one undo back. The web
half — *Choose a voice* in the pane — is still open; the phase is recorded
PART-DONE.

## Wireframes wave 2, walked in a browser

Phases 9–13 were built and unit-tested on 30 Sep and never driven. A
subagent walked them today in headless Chrome against a scratch daemon, from
the Chat where it could and from the CLI where it could not, and said which.
The verdicts are in each phase's status; the short form:

- **13 passes.** `/wire ds` lands a DESIGN.md item, restyles every wire and
  the prototype, and one undo removes all of it; `design check` reports zero
  AA warnings; `/wire polish` keeps every hotspot and `data-wf` path and the
  prototype still clicks through.
- **11 passes with caveats.** Edit and prototype re-version in one group and
  one undo reverts both; `why` answers in the Chat. But compose never records
  `WireSpec.decisions`, so `why` cites per-slot probabilities rather than the
  top‑3 and entropy the phase describes.
- **12 reached the real model from the browser and found a bug.** Claude
  wrote real words for the first screens, then Anthropic refused one screen's
  `blockContentSchema` as too large for strict output. The loop had already
  written six screen versions and had not rebuilt the prototype — canvas and
  prototype out of step, the state the one-group rule exists to prevent. One
  undo took the six back. Open: a smaller schema, and write nothing until
  every call has answered.
- **9 and 10 fail, each for one missing argument.** No composed flow ever
  gets a layout template because nothing in the compose path asks round 2
  with `layout: true`; the renderer itself reflows regions at 375 wide but
  lets the content overflow. And the entropy gate computes its `/ask`
  questions and nobody hears them: the comment is said only inside
  `if (opts.onGateAsk)`, and neither surface passes it. `--pin` works.

Two things were small enough to fix on the spot: `wire edit` said *prototype
rebuilt* even when the prototype's bytes had not changed, and a quoted
`/wire ds "…"` request kept its quote in the system's title. The rest is
recorded as open in `docs/projects/wireframes/phases.md`.

One finding about walking itself: the web's `/wire` always answers through
the home's judge, which 503s without a TYPESAFE key, so there is no
`--answerer stub` from a browser. A scratch walk needs a key or an intercept;
the walker used an intercept and said so.
