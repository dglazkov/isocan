# 11 September 2026

## What the rc hands over: the environment and the permissions

The day before, a one-line observation — "when I run rc and give it my
harness, it pretty much has access to my entire system" — became a research
note measuring exactly what a summoned agent got: the whole of the rc's
environment minus the harness variables, the harness's own shell on the
host, every permission answered yes by a regex, codex forced to full access
because its sandbox refused loopback, and any admitted member of a shared
canvas able to ring. The note weighed three layers and said the first needed
no decision. Today it was built.

**Permissions are answered by kind.** `session/request_permission` used to
be answered with the first option whose kind, id or name matched `/allow/i`,
else the first option. On the Claude adapter's plan-exit prompt every option
is `allow_always` and each one is a mode switch — `exit-plan-auto`,
`exit-plan-bypass`, and so on — so the regex chose a mode switch. Only
reachable when the person's default mode is `plan`, but the answer was wrong
in kind, not just in that case. Now the client selects the `allow_once`
option and, where there is none, the agent's own reject: a standing rule, a
mode switch, a directory added for good are the person's to grant at a
keyboard, not a turn's to grant itself. The refusal is narrated with what
was offered. The scripted adapter grew the plan-exit shape so the suite pins
both answers.

**The environment is a list.** `adapterEnv` used to start from
`{ ...process.env }` and delete the harness variables, so `AWS_*`,
`GITHUB_TOKEN`, `SSH_AUTH_SOCK` and every other export travelled into every
shell the agent opened. It now passes what a process needs (PATH, HOME,
locale, temp, the Windows set), the network plumbing (proxies, trust
stores), `ISOCAN_*`, npm's config and the version managers, and each
vendor's own namespace (`ANTHROPIC_*`, `CLAUDE_*`, `OPENAI_*`, `CODEX_*`,
`GEMINI_*`, `PI_*`) — where the API keys, base URLs and config directories
a harness reads already live. Anything else stays behind. A harness that
needs more is named once in `config.json` under `adapterEnv`, as names or
`PREFIX_*` — the `harnessVars` posture again: a list isocan knows, with a
hook for what it does not. The tests declare `FAKE_ACP_*` through that hook,
which is the mechanism working as a person would use it.

What this does not do: fence the agent to its directory, deny it the
network, or decide who may summon it. The first two are the two sections
below, which happened later the same day. The third — who may ring a
parked rc — was still agent-custody's open door until the end of the day (*Owner-only summons*, below).

## The sandbox spike, on Linux

Later the same day, one of the two spikes ran: `@anthropic-ai/sandbox-runtime`
0.0.76 around the ACP adapter, on Ubuntu 24.04 in a container whose kernel
has no IPv6 at all. The full record is in the research note; the short
version is that layer 3 is real on Linux, and the wrapper has to know five
things — a sixth turned up while building it, below.

The first was found the hard way. srt's Linux bridge — a `socat` listener
inside the sandbox forwarding to the host's proxy over a Unix socket — died
silently, because `TCP-LISTEN` wants an IPv6 socket and this kernel has
none; the only symptom was "connection refused after 0 ms" on every
request. A one-word patch to `TCP4-LISTEN` brought it up. The other four:
srt sets `NO_PROXY` to include `127.0.0.1`, so the child bypasses the only
path to the host for exactly the address that needs it — clear it inside,
and set `NODE_USE_ENV_PROXY=1` so Node's `fetch` uses the proxy at all;
`npx` needs the registry allowed and npm's own proxy keys, since npm honours
its config over `HTTPS_PROXY`; and `~/.claude` must be re-allowed or
sessions land on a tmpfs and never resume.

With those, the rc's own spawn path — `config.json` declaring the harness
as `srt … -- sh -c '…; exec npx -y @agentclientprotocol/claude-agent-acp'` —
completed real Claude turns: the agent ran `isocan --json whoami` from its
own shell and answered as the enrolled actor, could not read a canary in
`/root`, saw nothing of the home directory but the re-allowed checkout, had
its one Bash permission answered `allow-once` by kind, and resumed its
session on the next turn with the word it had been told. Credentials never
entered the sandbox: this machine holds no login on disk, the session's
egress proxy injects it, and the model call succeeded anyway — the vault
pattern, observed. Not measured: macOS, and codex nested (not installed
here).

## The fence, built

`isocan rc --sandbox`, and `{"sandbox": true}` in `config.json` for the
standing answer. It wraps every adapter spawn — both dispatch paths, so
there is no door that fences and no door that forgets — in a policy derived
from the enrolment rather than written by hand: the row's own directory,
`~/.isocan`, `/tmp` and the harness's config to write, the rest of the home
denied, the daemon's address and that harness's vendor domains to reach,
and nothing else.

Three decisions are worth the words. **Asking and not getting is a
refusal.** A machine missing bubblewrap does not quietly run the agent with
the person's reach; the start fails naming what is absent and what installs
it. A person who wants "fence if you can, otherwise run" says nothing at
all — one word must not also mean its opposite. **srt is looked for on the
PATH, not fetched and not a dependency.** It is a 0.0.x research preview, so
pinning a version here would be the hand-typed pin `harnesses.ts` was
rewritten to delete; and `npx -y` was measured and rejected for a better
reason, below. **A declared `sandboxCommand` is believed as it stands**, the
same posture a declared adapter gets: a person who brought their own jail is
not missing ripgrep.

Building it turned up the sixth thing, and the sharpest: **srt must be
readable inside its own fence.** An `npx`-cached or nvm-global srt lives
under `$HOME`, and a policy denying `$HOME` hides srt's own seccomp helper
from the mount namespace srt just built — the launch dies naming a path that
is plainly on disk. So the wrapper resolves srt's package root and re-allows
it, and the quiet start keeps its three-line budget: the fence says one line
when it holds, and `isocan harness` answers "could this machine fence?"
where machine facts are read.

`scripts/spike-srt.sh` is the macOS half of the measurement in one command
— a throwaway daemon and home, step 1, a real turn, and a table with the
sentence to paste back into the note. It ran here first: every row of step 1
holds, and the one row that does not is `isocan` itself correctly refusing
to fence a kernel with no IPv6.

## The sheep harness: withdrawal ends the sheep

Withdrawing an agent on the sheep harness now ends what it left behind.
Every path that withdraws one — `rc remove` and `agent remove`, a parked
rc seeing the web's Dismiss, an rc starting after a withdrawal it missed,
and a summons whose agent was withdrawn while its sheep was being born —
reads the rc row before reaping it and runs `sheep rm`, which aborts a
running turn first. The pasture stays, and the rc says so: it is the
person's, and re-enrolling births a new sheep into it that does not
remember the old one. A station deployed before sheep's end verb gets
`sheep abort` and a sentence saying the sheep is still there.

The badge the cell redeemed is ended too, by name rather than by guessing
from which surfaces share the agent's actor. The desk already recorded
which badge redeemed each pass; a new route, `GET
/api/projects/:id/passes/:passId`, reads that back to the badge that
minted the pass and to no other. The rc row keeps the birth's pass id
(never the token), `isocan badges` shows the cell's badge as `cell
(<agent>'s sheep)`, and withdrawal ends exactly it.

The phase's first CI run failed twice on "a web add gets its rc half
from the parked rc", a test that had flaked three times before. It was
not a flake: an enrolment landing between the rc's roster read and its
log tip waited for the end of a thirty-second poll. Forcing that window
reproduced CI's output exactly; the rc now re-reads the roster after the
tip and takes up from it (lessons.md #50). Walked on a local sheep home
and on sheep-2 against dev.isocan.io, where a withdrawal during a
90-second turn aborted it and ended the cell's badge, and showed that an
aborted turn exits cleanly, which the rc now reads as a withdrawal too.

## The design competition: an epic, designed, and the module system's hardest test

An ask for an epic — *choose your fighter*: pick famous designers (Jony Ive
and Apple, frog, IDEO and a few more), give them one brief, let an agent per
designer build a rival design in its own area of the canvas, and vote — built
as a module, explicitly to test the module system and extend it where it
cannot carry the feature. Nothing was built; a research note, a project
directory and fourteen issues were written.

**Reading the tree first changed the shape of it.** Almost everything a
competition needs already exists, built for the sprint and its neighbours:
areas and a board laid as data, desks, cross-canvas hand-in, the curtain,
placed dots, a tally that counts people and agents apart, `DESIGN.md` as an
item, and the rc waking an agent on a message. So the sentence became *a
sprint with one phase, cast by a picker*, and the feature adds no operation.
Two things that looked reusable are not: `choose` trashes every sibling, and
the siblings of a winning entry are the record of why it won; and `prefer`
writes nothing when a second voter agrees, so a multi-voter tally cannot be
read from it. Ballots are reactions instead — 🥇🥈🥉 by *which best answers
the brief*, 🔴 on the part you would steal, ⛔ for an entry that misses the
brief, and the Decider's 🏆.

**The cast is the whole cost, and every piece of it is a module-system gap**,
each measured to a file: a runtime build copies no assets; nothing can
contribute to a module; there is no dialog slot and a module command cannot
be local; nothing enrols an agent from either host and no summons carries a
persona (the gap `AddAgent` deferred on 30 Aug until a template could *decide*
something — a fighter pack is the first that does); and the curtain knows only
sprint phases. One of them is a latent bug rather than a missing feature:
`designSystem(canvas)` picks the newest design-system item on the canvas, so
three lanes with three `DESIGN.md`s would silently replace the canvas's own.
The fix extends `governingDesign`'s existing order to area → canvas → linked.

**The designers are living people, and that set the pack rules.** Emblems,
never faces (and not the Happy Mac, not frog's frog, not Linear's logo);
the principle leads and the person is a credit (*Less but Better*, after Dieter
Rams, never *Rams Bot*); an homage line on every card; references as
links unless the licence travels, and share-alike does not travel into an MIT
repo. The survey of AI design arenas supplied the vote's refinements: Design
Arena's five-vote bracket to a full ranking, WebDev Arena's 18% "both bad",
the polish bias style control found, and private reruns distorting ranks.

Three open questions were answered the same afternoon: the principle leads
and the person is a credit, which went further than the design's own *Rams
Bot* — no living person's name rides on an agent's ops at all; exhibition is
the default bout; and it ships on isocan.io, as a build-time module whose web
half is one lazy chunk, because the stickers module found a gate at render
still cost every first visit its bytes.

Phase 0 goes first and needs no code: a bout by hand, measuring whether people
can tell whose entry is whose. If they cannot, the packs are adjectives.
Epic [#250](https://github.com/dglazkov/isocan/issues/250), sub-issues #251–#263;
[`docs/projects/design-competition/`](../projects/design-competition/) and
[the research note](../research/2026-09-11-design-competition.md).

## The operator: a plan for #77

`/terms` promises that the person who runs isocan.io can kill a badge,
revoke a grant, delete a canvas and refuse somebody at the door, and #77
found that none of the four exists for anyone but the people already on a
canvas. `docs/projects/operator/` is the plan: twelve journeys, a design,
and nine phases ordered by what a real takedown needs first.

The central call is that **the operator is a proof, not a credential** — an
address `ISOCAN_OPERATORS` names, proved by the home's own attester within
ten minutes, carried with each act and written onto nothing, so no badge
holds operator standing and no agent can borrow it. Acts run in the daemon
and are desk records, never ops. **Taking down is not deleting**: an
owner's delete erases every replica, while a takedown stops the home
serving the canvas and leaves the copies on members' machines where the
innkeeper posture says they belong.

Mapping the code first found more than the issue named. Nothing a delete
removes is ever purged, so the terms' "and the files under it" is untrue for
every delete, the owner's included. A killed badge's open sockets stay open,
its minted passes stay redeemable, and the CLI can knock again and resume
the same name. `project.delete` needs only edit. And the badge-to-op log the
terms list among the ledgers was never built. The doc proposes a terms
wording for meanwhile and leaves it, as legal copy, to Dion; isocan.io's
operator list and eight posture questions are Dimitri's.

Dion asked for the issues' versions.

the ⌘O switcher whenever anything was typed, under every live match, with

**Below 460px the minimap folds, and the width writes nothing (#182).**
The first fix stacked the map above the zoom row, because the only fold
wrote `isocan.minimap` and a phone would then have decided the desktop's

## Owner-only summons

Decided by Dion today, and the consent half of the rc note's recommendations
(#238, recommendation 6; agent-custody's oldest open
question): **a parked agent answers only its owner unless its owner widens
it.** The fence built this morning bounds what a turn may reach; this bounds
who may start one, and on a shared canvas that was the sharper of the two —
any admitted member could ring somebody's rc and spend that person's tokens
on that person's laptop.

The smallest coherent shape turned out to be the gate that already existed.
`AgentRules.listen` (9 Sep) was a narrowing with "absent means everyone";
now it is read at the rc through its owner, where absent means **the owner
alone**, a list means the owner and those people, and `["*"]` is a team's
agent said out loud. The owner is the rc's own person — the machine's home
identity, compared through `actor.join` — because that is whose bill it is,
which only the machine can say; whoever happened to write the enrolment is
not it (an agent can enrol an agent, and the web's add is an ask the rc
completes). Every other actor the machine's badge speaks as counts as the
owner's word, so two agents on one laptop still ask each other things; the
cycle guard still bounds that.

Walking it in a browser against a scratch daemon found the hole that rule
leaves, before any test did: Maya's Chat line was turned away by Sian, woke
Percy (open to everyone), and Percy's reply — the owner's own machine — woke
Sian anyway, then ran to the cycle guard. So the rc now records whose asks
started each agent's turn (`speakersFor` in core, followed through agents)
and the gate reads the word an agent's reply carries, not the agent: Percy
answering Maya is Maya asking, as far as Sian is concerned. The memory is
the rc's; a restart mid-chain forgets it, which the walk also saw, and the
cycle guard is still the bound there.

**The gate lives at the rc, and the home carries its words.** Only the rc
starts a turn, so only the rc enforces. It computes one value per agent
(`answerPolicy` in core), applies it in `dispatchReason`, and announces the
same value with its hold — the research note's "the rc announces its policy
with its hold" — relayed up the home-link beside the faces, with the owner
vouched for the way a face is. `isocan who`, `agent rules`, `rc listen`, the
tray and the add dialog read that, not the stored field, so what they say is
what will happen.

**A refusal is words, never silence.** A mention from outside the gate is
answered in its thread in the system voice — *Sian listens only to Nico —
this did not wake Sian, and spent nothing. Nico can widen it: isocan rc
listen Sian --to Maya* — once per thread and asker, and not again from a
restarted rc. The CLI says the same on stderr as a non-owner posts the
mention; the web says it under the comment instead of *Sent*, and the row
of an agent that will not take the reader's word no longer promises
*answers if you comment*. `summonsState` grew a `refused` state, known at
once and never counted as *nothing answered*. Only mentions get words: the
Chat being loud is the room talking, and an agent narrating every sentence
it did not answer would be the noise the gate spares.

**Only the owner's word widens.** The gate sits in a record every admitted
member can write, so "owner-only" was one hand-made `agent.enroll` from
"everyone". The reducer now stamps `writtenBy` on the enrolment row, from the
envelope, as it stamps an item's `updatedBy`; the rc honours a stored gate
only when its owner (or its owner's machine) wrote it, and says so when it
sets one aside. Rows from before the stamp are taken as they stand. No new
op — the vocabulary stays at 33; `rc listen --to` now refuses inside a
harness session, because consent to spend somebody's tokens is not an
agent's to give; and the owner gets *Let anyone ask* on their own agent's
row, which sends the same re-enrolment. The add dialog is offered to the
rc's owner only, and the home refuses anybody else's ask with the owner's
name (`not-your-rc`) instead of letting it die in a countdown.

**The migration is the default.** Every enrolment with no gate — all of them
written before 9 Sep — answers its owner alone from the first rc that runs
this build, and that rc says so at start, per agent. The repo's own
machinery was walked for anything that summons an agent as somebody else.
The night's morning comment is a Chat line written as Night, an identity
claimed on the machine that runs it — the owner's hands when that machine
also runs the rc, and otherwise, rightly, no longer a wake for somebody
else's agents. A sprint's phase lines are the facilitator's Chat lines: they
still reach every `wait` park (which answers for itself and is untouched),
and reach a standing agent only if the facilitator is its owner or its owner
widened it. The design competition's fighters are enrolled on the pressing
person's own rc, so the brief is the owner's word. Persona runs, graders and
the sheep harness start no summons of their own, and `rc turn` is the
owner's own hand on a turn. Scout on the cloudtop answers Admiral One alone after its next start —
the other identity reaches it by `actor.join` or by being named in
`rc listen Scout --to`. The tests that summoned as Dimitri at a test badge
while the rc was Nico's now enrol their agents open to everyone, explicitly;
a block of their own pins the default, the words, the widening, the one-hop case and the
set-aside.

## The other half of the grant, researched and declined for now

Owner-only summons closed the *who*. Within the hour Dion asked for a UI
instead of a command line and Lamb mocked one up, and the mockup carried two
more toggles: *create and edit items* and *run shell / container commands*,
off for a fresh grantee. #272 builds the who and the how-long;
`docs/research/2026-09-11-per-asker-scopes.md` answers the what (#273), and
the answer is that neither toggle can be built honestly today.

Two corrections came first. The ladder is `view` / `read` / `edit` / `own`
and has no comment rung — one was considered by the roles project and left
out because *a comment reaches agents and can start work* — and every non-GET
below `edit` is refused at one hook, so a reply is a write. The mockup's
default state, reply yes and edit no, is therefore that refused rung wearing
the word *reply*, and on a canvas where a comment is a summons it has to be
refused harder than it was on 2 September: an actor who may comment but not
edit can still spend somebody's tokens on somebody's machine.

The second toggle fails for a sharper reason: an agent's hands are the CLI,
and the summons brief itself tells it to run `isocan comment reply`, so an
agent that may not run commands may not answer. Nor is there a channel to
enforce it — srt's policy is filesystem and network, not *no exec*, and codex
asks no permission for a shell command in its default mode.

What survives is **reach**, and only the owner's machine can hold it:
`fenceSpec` already runs per turn and already keys a policy file per canvas
and actor, so the key could grow an asker — narrowing the owner's own fence,
never widening it. The note recommends the gate entry as the record if
anything is ever built (it is #272 phase 3's object, so `listen` should
become an entry per name once rather than twice), names two triggers that
would change the verdict — an op somebody can point at, and a sheep cell
whose boundary the canvas describes — and one cheap first step at zero ops:
the summons brief telling the turn who woke it and whose bill it is.

## The refusal is the control

Owner-only summons shipped in the afternoon and was proved by the first
thing it refused. Dion asked Lamb — Dimitri's sheep-harnessed agent — for a
Star Trek themed canvas, nothing woke, and the thread said exactly what it
was supposed to say:

> Lamb listens only to Dimitri — this did not wake Lamb, and spent nothing.
> Dimitri can widen it: `isocan rc listen Lamb --to Dion`

Correct, complete, and a command line, to a person who was in a browser.
*"Maybe we can have UI that lets you give me access to a lamb … instead of
just saying the command line lol"* became issue #272, and the answer is one
sentence: **the thing that said no is where you say yes.**

**Phase 1 — under the refusal, for the owner alone.** The turned-away line
is already a system comment in the thread where the asking happened, and the
web already holds each agent's announced policy on the poll that drives the
tray. So the owner reading that thread gets two buttons under the message
that was refused — *Let Dion ask*, *Let anyone ask* — and nobody else's
screen changes at all. That last part is the rule rather than a nicety:
**never render a control to somebody whose click would be set aside.** The
rc honours a gate only when its owner wrote it (`writtenBy`, this
afternoon), so a button offered to a stranger would be a button whose op is
silently discarded, which is worse than no button. The reader is the owner
exactly when the policy the rc ANNOUNCED names them — the same value
dispatch applies, not the stored field.

**What the click writes, and what it does not.** The same `agent.enroll`
`isocan rc listen --to` writes, through one function in core
(`withListener`) so the button and the command cannot drift. It APPENDS to
the gate that already stands — and "stands" means `RcPolicy.listen`, the
announced value, not the stored field, because a gate somebody else wrote
has already been set aside and appending to it would quietly bring it back.
No new op: the vocabulary stays at 33.

**What the thread shows afterwards is a line, not a comment.** A grant that
posted its own system comment would fill threads with machinery talking
about machinery, and the record already exists — it is the enrolment op.
What the thread actually needed is for the refusal above to stop reading as
true, so the same place says *Lamb listens to you now — ask again*, to
everybody who can see the refusal it corrects. Finding the refusal to sit
under is core's too: `turnedAwayLine` now composes its middle clause from
`turnedAwayMark`, and `readsAsTurnedAway` reads it back, so one phrase is
written and recognised in one place rather than a marker being bolted onto
what a comment IS for one feature's benefit.

**Phase 2 — the tray names people.** The row's two-position switch (*Only
me* / *Let anyone ask*) becomes the gate itself: *Who can ask* opens
everybody on this canvas, each a checkbox, plus *anyone*. Naming one person
was CLI-only, which was a strange place for the two surfaces to differ,
because naming one person is the case that produced the issue. Agents are
not in the list and neither is the owner — the owner is always in, and a
checkbox that cannot be unticked is a control that lies.

**Phase 3 — how long, and where the expiry lives.** A grant may carry one,
and the section above asked that `listen` stop being a list of strings
**exactly once**, becoming an entry per name. It has: `ListenEntry` is an
actor id, or `{ id, until }`, and `ListenGrant` — `parseListen`'s reading of
either — is the single shape a plain grant and an expiring grant both take.

The first attempt packed the date into the string (`usr_dion until <ISO>`),
and the argument that moved it is worth keeping: **a gate that fails by
accident, in either direction, is exactly what this field exists to prevent,
so the failure has to be one a compiler can see.** With `string[]`, a reader
that forgets to parse compiles and silently matches nobody; with the union it
is a type error — which is literally how the three call sites outside core
were found when the shape changed. The other half is what an older build does
with an entry it does not understand: `rulesOf` has always kept only strings
in this list, so the object is dropped whole. The grant is absent, the agent
answers its owner alone, and nothing renders half a date as a person's name.
Fail closed, and pinned by a test that writes the old reader out
(`agents.test.ts`, "is dropped whole by a reader that has never heard of
expiry").

There is no migration, because both shapes are read and a grant with no
expiry is still a bare id: every gate written before today is unchanged, and
one that gains no expiry stays byte-identical. A sibling `until` map beside
`listen` was the third option and the only unsafe one — `rulesOf` drops keys
it does not recognise, so an older build would have gone on honouring a grant
that lapsed a month ago, a gate failing OPEN on the one field whose entire
job is deciding who may spend somebody's tokens. `listen` stays one field on
the enrolment either way, which is what let this be a field on a record
rather than a new op type.

The clock is read where the gate is applied — at the rc — and every reader
of the gate goes through core: `mayWake`, `listensTo`, `policyWords` and
`listenWords` all take a `now` and none of them will name somebody the gate
would turn away. A lapsed grant is KEPT in the list rather than swept, so
the refusal can say which refusal it is: the same sentence a gate that never
had them would give, plus *Dimitri's access lapsed 1h ago.* "You were never
let in" and "you were, until Tuesday" have different next moves, and only
the second one is the owner's to repeat. `isocan rc listen --to <who>
--until tonight|7d|24h|<date>` is the same gesture in the terminal, and the
read form prints what each grant has left.

**Out of scope on purpose.** The mockup Lamb drew on the canvas had two more
switches — *create and edit items* and *run shell / container commands*.
They are not the listen gate: what an agent may DO is its rung on the canvas
and the fence on its owner's machine (`rc --sandbox`), neither of which is
per-asker, and "Lamb, when Dion wakes it, may read but not edit" is a
capability travelling with a summons, which exists nowhere today. Shipping
it as a switch that silently did nothing would be worse than not having it.
It is the most interesting idea in the mockup, and the section above is the
note that examined it and declined it for now. The panel says so in one line
rather than leaving its absence to be guessed at: *a grant decides whether
this agent answers this person; what it may do here is its own rung on this
canvas.*

**Done on both surfaces, line by line:**

1. **Op vocabulary** — no new op; held at 33. `agent.enroll` carries the
   gate as before, with the expiry inside the `listen` entry.
2. **CLI verb** — no new verb. `rc listen --to` is still the widening;
   `--until <when>` says how long, and the read form shows what is left.
3. **Agent guide** — "Whose word wakes it" now says the owner can grant from
   the refusal and from the tray, that the command form is unchanged, and
   what a lapsed grant reads like — so an agent told "your agent ignored me"
   points at the buttons rather than reciting a command.
4. **Core** — `withListener`, `parseListen`/`spellListen`, `listenGrants`,
   `lapsedFor`, `listenUntil`, `untilWords`, `turnedAwayMark` /
   `readsAsTurnedAway`, `ListenEntry`/`ListenGrant`; a clock on `mayWake`,
   `listensTo`,
   `policyWords`, `listenWords`, `refusedMentions` and `turnedAwayLine`.
5. **README / WHATSNEW** — the user-visible half of the gate.
6. **Tests** — core (append-not-replace, the fail-closed spelling, a lapsed
   grant's silence and its words, dedupe by person with the longer grant
   winning, recognising a refusal, and an older reader dropping an entry it
   does not understand); CLI (`--until` written as an entry
   and read back; the rc's lapsed refusal end to end against a real daemon);
   web (the panel's core-computed list and its owner-only rendering, the
   grant control's predicates, and that it posts no comment of its own).
   Not driven in a browser: the daemon on this machine is Dion's own and
   driving it would mint identities on a live canvas, so the acceptance here
   is the suite. The afternoon's browser walk covered the refusal itself.

**Bytes, and the shape worth copying.** The feature measured 5,914 and cost
**473**, because the parts of it a first visit never reaches were put where a
first visit does not go.

Both of its controls are owner-only and occasional — a grant appears under a
message an agent turned away, the who-panel when its owner opens a tray row —
but all three of their hosts (the comment popover, the Chat, the agent tray)
are in the bytes a first visit downloads, so the controls were too. Behind
`lazy()` they become two chunks of 1,804 and 1,589 bytes, fetched by the
people who actually grant something, and they take `withListener`,
`listenUntil`, `listenGrants` and `readsAsTurnedAway` with them, since no
eager reader wants those. What stays eager is what a first visit genuinely
reads: the words on a tray row, and the refusal under a comment. A further
2,702 came back from the Help panel, which `CanvasPage` was loading whole —
shortcut tables and command registry behind it — into every first paint for a
modal most sessions never open; #267's ceiling commit named it as the first
thing to reclaim, and this is the feature that read that and took it.

So the entry chunk measures 657,916 and the ceiling moves 653,500 → 658,000.
Almost all of the raise is a debt from earlier in the day: 3,943 of it
arrived with owner-only summons this afternoon, which measured itself and
deliberately left the raise to "the answer to the performance persona's
finding". A second unremarked creep on top of the first is precisely the
failure `bundle-ceiling.mjs` was written about, so it is paid here rather
than carried.
