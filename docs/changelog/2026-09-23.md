# 23 September 2026 — Wireframes, from a request to a clickable prototype in a day

Most of the day was one project walked end to end: Dion asked for
wireframes in the morning, and by night the research, the design and nine
phases had landed, with the web door walked on isocan.io. Around it, voice
got a fast path that only listens so far, two Chat annoyances Dion hit were
removed at the root, and text nodes stopped cropping their own words.

22 September has no page of its own. The groundwork this day stood on —
the design journeys going green on Linux, one Node version, Renovate, and
the bundle reclaim — landed that afternoon and evening, and is written up
here with the day that needed it.

## Groundwork from the 22nd

**The design journeys were red on the runner, not in the product.**
design-contract and design-lint had failed every nightly since 17 Sep, and
the CI message — a DESIGN.md with a second copy of itself pasted in —
read like content corruption. It was a raw `⌘A`: CodeMirror's `Mod-a` is
Ctrl off a Mac, so on Linux the select-all selected nothing and the insert
landed at the caret. `rig.selectAll()` now picks the chord from the
platform the browser runs on. The next manual run got one step further and
failed on the same shape: since #44 a label prints its platform's shortcut,
so Undo is "Undo (Ctrl+Z)" on the runner and a selector for `⌘Z` matched
nothing. Selectors now match what a control is, not how a Mac spells it,
and `test/journeys.test.ts` forbids a hard-coded `⌘A` and any `⌘` inside
a title or aria-label selector. Lesson #89: when a journey fails only on CI, run it locally
before reading its message as a product bug.

**One Node, named once.** The suite ran on 24, five nightly workflows on
22, the image on `node:24-slim`, and a laptop on 24.5 — below the 24.15
jsdom 30 asks for — and nobody noticed. `.nvmrc` is now the version, read
by fnm, nvm and every `setup-node` step, and `test/workflows.test.ts` fails
if a workflow picks its own. `engines.node` says `>=24`, which is a
different question (the floor the code claims) and deliberately not
required to equal it. The Dockerfile comment now answers the question it
will actually be asked — why not 26 — rather than re-arguing 24 over 22.

**Dependencies are Renovate's, in four lanes**, because "nothing bumped
anything" was how the Node drift happened: patch and minor daily and
self-merging on a green suite; lockfile maintenance weekly, the same; every
major together weekly, for a person; and Node (`.nvmrc`, the image,
`@types/node`) in one weekly PR, because the suite holds `.nvmrc` and the
Dockerfile to one major and a split PR would fail it. AGENTS.md records the
lanes beside the other night-shift PRs.

**The entry chunk gave back 29 KB.** The nightly read 756,004 bytes, 9,004
past the ceiling. The emoji picker and its 23.5 KB table now load behind
the `+`, and the Pen's colour names through a `@isocan/core/colour`
subpath. The lazy picker alone saved nothing: one top-level `flatMap` in
`emoji.ts` looked effectful to rollup, so the module was kept wherever it
was reachable — through core's barrel, every first visit. One
`/* @__PURE__ */` is what let it move. CEILING went *down*, 747,000 →
727,800 once the operator move and the summons receipt were measured with
it, and the review queue emptied.

## Node pinned to 24.20.0

The 22nd's bump to 24.21.0 broke something no test covers: 24.21 fails
`UNABLE_TO_GET_ISSUER_CERT` on every Google Trust Services certificate —
isocan.io, isocan.store, google.com — so a laptop daemon restarted onto it
could not reach its home at all, while curl could. 24.20.0 verifies them
(24.15 and 24.18 do not). `.nvmrc` goes to 24.20.0, still above jsdom's
floor, and the Dockerfile stops floating on `node:24-slim` and pins
`24.20.0-slim` too. Whether the Linux image is affected was not measured;
a home that calls Google-hosted APIs over HTTPS is the wrong place to find
out. Lesson #93.

## A replica is waited on until it is current (lesson #92)

`design-decision.test.ts` failed twice under the deep lane on the 22nd
and passed alone every time. The wait was `expect.poll` on the relay's
store — vitest's default deadline of one second, aimed at the middle of
snapshot adoption rather than its end. Holding adoption open 1.5 s
reproduced it at once, and the same line sat in three more tests.
`untilReplicaCurrent` waits for the relay to hold the home's `lastSeq`, on
the 10 s deadline replication already uses, and names both numbers when it
fails; `test/replica-waits.test.ts` fails on a new bare poll of a relay's
store. The deadline is longer on purpose: the old one was nobody's choice.

## Wireframes, phases 0–8

Dion asked for wireframes composed by Jev from a catalog, with variations,
a way to tag the keepers, a prototype assembled from them, and a wire that
starts as a blue-on-white skeleton. The research unioned ten sources into
73 primitives and 50 blocks and found that Jev should *choose blocks into
archetype recipes* rather than compose primitives: no structural question
then has more than four options, and actionable text becomes a typed
intent, which is what lets prototype links be computed rather than guessed.
The design adds no operation — a screen is an HTML item with its spec
embedded, and keep is a property, like a slide.

- **0 · The catalog, drawn.** 18 recipes (kept in the research's own
  notation and parsed, so code and table compare line by line), 28 blocks,
  22 primitives, 49 intents. Undecided slots draw blue; chosen ones grey,
  with bars for copy — never lorem ipsum.
- **1 · Jev draws a flow.** `isocan wire "<request>"` lands a blueprint in
  ~50 ms, before any model is asked, then three rounds fill it in place;
  every op carries the flow's id as its group, so one undo takes the whole
  request back. Each distribution is kept, not just the argmax. The first
  real run changed the design: asking the nav bar per screen drew "Home,
  Search, Home" on one and "Home, Search, Search" on the next, so it is
  asked once and copied.
- **2 · Variations and keep.** A variation flips one decision to its
  runner-up, most probable first, nothing under 0.10; a screen with no
  honest alternative says "one way to draw this" instead of inventing one.
  Keep arrives on the web through a generic `ModuleMark` the shell draws
  without importing the module — paid for by splitting `slides.ts`, since
  the margin was 21 bytes.
- **3 · Links and the prototype.** Links are computed from intents on
  every call and never stored; a person's override is the one stored thing.
  The canvas arrows did not ship: the edge hook sees metadata and a spec
  lives in a file, and storing links as metadata was refused.
- **4 · Wires in your design system.** The wire look became a theme of
  eleven roles; `wire style` has Jev map the governing DESIGN.md's tokens
  onto them, as one op group, and a rerun asks nothing and writes nothing.
  Blueprints never take a theme: blue means still being drawn.
- **5 · The web door.** `/wire` in the Chat runs the CLI's own composer in
  the browser, through one `WirePort` both surfaces implement — a test runs
  both on the same answers and gets identical ops. The key never reaches
  the browser: `POST /api/judgment` answers with the home's key behind the
  same checks as `/api/ops`, plus a size cap and a per-badge budget. The
  entry chunk went 567 bytes over CEILING and it was *not* raised: the
  registration is what the shell must know before first paint, so it was
  landed as a finding for Dion. Walked on isocan.io — blueprint by 1.2 s,
  eight screens and eight variations by 13 s, clicked through.
- **6 · Calibration.** Jev asked "which archetype is this?" of 1,318
  Enrico screens: 33% strict, 61.5% top-3, ECE 0.39 — it ranks, but at
  p ≥ 0.9 it is right under half the time. So round 1 should over-include
  and let keep prune, and the voice fast path below inherits the lesson.
- **7 · Fleshed out.** Grey bars become believable content: 24 synthetic
  content packs and 44 pictograms, the pack chosen by Jev (generic under
  0.4, saying so). Filling is seeded and stored, so the list's first row is
  the detail's heading and restyles and variations keep it; an agent's exact
  words (`wire copy --apply`) are left alone. All of it in the lazy chunk.
- **8 · From real use.** Dion's list from using it: true arrows you can
  click, no title strip or frame-in-a-frame, prototypes findable on a busy
  canvas, and `/wire` acts in the Chat history. The research note chose
  orthogonal arrows per hotspot on ordered lanes (zero crossings on the
  recorded flow, where the naive spread gives one); a selected arrow offers
  Play from here, Go to, Change target, Reset and Remove, each the op
  `wire link` sends. A wire is now just the screen, with `wire render --all`
  to redraw the old ones; the minimap lights prototypes; every web `/wire`
  write leaves one record in the Chat, undone with it. Twelve of
  Porchlight's findings were answered — among them, per-hotspot link
  properties so two concurrent writers both survive. CEILING 727,800 →
  730,100, at Dion's call, with the reason beside the number.

## Voice: Jev listens, in shadow (phase 6)

Dion asked for simple spoken commands — "move the login page to the left" —
to be done by Jev and anything harder handed to the model. Phase 6 builds
the resolver and runs it on every finished turn *without acting*: it
records what Jev would have done beside what the model did and whether it
was undone within ten seconds. The threshold is to be measured, never
guessed — wireframes phase 6 had just shown Jev overconfident by ~0.4 — so
`decide` escalates everything until an action has 30 proposals at 95%
agreement. On the scripted set it agreed 94–95% (94–97% on a held-out hard
set written after the first run was scored), escalated 44 of 48 complex
commands, at ~200 ms p50; only `move` has reached the bar. The switch is
off by default and a test holds the shadow's source away from every
executor. The microphone walk is in `docs/verify/`.

## No one refreshes context

Two Chat messages were refused with "canvas context changed since preview;
refresh the context before sending", and Dion: the user should never have
to do any of this. The first fix only made the Refresh button appear when
it could do something, and styled it. The second removed the reason for
it: every message had carried its preview's revision and was refused if
anything had landed since — on a canvas where wires fill in and agents
work, nearly always. The web now sends only its roots, the preview rebuilds
itself ~600 ms after the canvas moves, and the home freezes the context at
the revision the message lands at. No Refresh anywhere; only a failed load
offers Try again. The canvas-groups design records the reversal.

## A text node keeps its words whole

An agent's note promoted with `isocan set --prop textStyle=heading` kept
the box measured at body size, so 32px type sat in a 16px box and the
node's deliberately hidden overflow cut the second line in half. The same
hole had three more doors — `isocan edit`, the web's step bar, and a
`⇧F` / `isocan fit` that gave a caption a screen's 1280×800 on the web and
refused it from the CLI. One computation in core now answers every writer:
`textRefit` grows the box to what the words need at the look they will have
once the patch lands, and `textNodeFit` is the repair for nodes already
stored short. `--size` still wins. Lesson #94 names the shape: a value
derived at birth, and later writes of its inputs that never re-derive it.
