# The home goes up, and a room of ghosts

**2026-08-22** · 46 commits · 279 files · +20,064/−1,764 · Dimitri Glazkov, Dion Almaer

The longest day so far, and two tracks running at once. The multiuser build is
redesigned and then *provisioned* — by evening a real canvas is being served
from Google Cloud, off Firestore, through a badge minted at the door. On the app
side, a colour audit, a changelog, and a cursor that finally says who it belongs
to — plus the day's best bug, in which a canvas full of live people rendered as
a canvas of absent ones.

## And then actually provisioned

Phase 5 ran all four stages against real infrastructure, and nearly every
finding is a thing that only fails when you run it.

- **Stage A**: `isocan-io-dev` in us-west1 serving a canvas off Firestore —
  created in a browser, stored as op documents, read back through a badge.
  Phases 2 and 4 became true in production rather than only in the suite.
- **Stage B/C**: load balancer, CDN, managed cert, nightly Firestore export —
  and three places Google's own docs are wrong. A backend service *rejects* a
  timeout when a serverless NEG is attached, documented as having no effect,
  and it rejects at the worst moment: create succeeds while nothing is attached.
- **The certificate**, created before the DNS record existed, so Google probed,
  failed, and parked the domain in `FAILED_NOT_VISIBLE` — a status that sticks
  rather than re-reading itself. A sticky failure is not a stuck one.
- **Stage D**: push to main builds, boot-checks and deploys with no hands. The
  first trigger build failed on an image that did not exist yet, because Cloud
  Build pushes its top-level `images:` list only after every step finishes.
- **The proof**: 150 ops written continuously against the live home while Cloud
  Run took two revision rollovers. None refused, seqs contiguous 31→180, no
  gaps, no duplicates, landed in the order written. That is phase 4's
  create-only precondition observed under the exact condition it exists for.

## The bug worth remembering

Everyone online, every face faint. The colour audit had run a search-and-replace
for `.face-mark {` that also matched the class in its *scoped* forms, and each
match left the tail behind as a bare selector. The worst of them dropped
`.face.away`, so the dimming that means "not here" was applied to the whole
room — and the rule meant to replace it became `.face.away .face.live`, a face
inside a face, which matches nothing.

Nothing failed. The build was clean and the tests passed. The only symptom was
that a canvas full of people looked like a canvas of ghosts, which is the worst
kind of bug in a presence UI: it does not look broken, it looks like nobody
came. The fix is one canonical block per class, with a test — the second time a
`replace()` has dropped a scope in that stylesheet.
