# 12 September 2026

Anatomy's project shortcut now follows the right tool rail's icon-only layout.
Module project views use the same square button as History and Reactions;
their names appear in the hover/focus tooltip and accessible label. The More
menu retains its text entry. Project navigation sits above the divider for
canvas-authored tools, whose labels remain part of their existing design.

This is a presentation fix: operations, CLI verbs, the agent guide, core
helpers and README feature descriptions need no changes.

A [full Anatomy usability review](../projects/anatomy/usability-review.md)
examines project navigation, exploration, Chat analysis requests, the command
family and shared mutations. It records 11 prioritized findings and a phased
follow-up plan. Browser probes reproduced draft loss when switching editor
modes and navigation context loss; synthetic reducer probes reproduced an
older input file replacing newer evidence, unrelated edits rejecting a draft,
and one invalid concept preventing a complete graph read. The review separates
these findings from recommendations. The follow-up below implements the two
edit-preservation fixes and navigation/motion work.

Validation: the final full suite passed 4,161 tests with 70 skipped; typecheck
and production build passed. The first run caught a stale generated Anatomy
roadmap note, refreshed from the already-committed design, and an agent teardown
timing assertion that passed on the full rerun. Browser verification confirmed
the project shortcut's square icon layout, accessible label and navigation.


The fluid-exploration follow-up gives module workspaces a temporary presentation
of native items. Anatomy expands its focal card, moves compact neighbors and
keeps distant concepts as context markers. Edges use the same moving bounds;
focal links paint above context. Comments, selection and item work keep their
native IDs. The ordinary canvas retains its saved geometry and camera.

Analysis, lens and focus are addressable; Back retraces exploration and View
Anatomy resumes it. Local pane sizes persist. Incoming edits highlight their
concept without moving the camera. A reducer-level `item.edit` precondition
protects body and metadata together; `anatomy draft` binds CLI files to their
original version, and changing editor modes preserves the unsaved draft.

Browser testing caught two integration failures: distant edges intercepted
nearby links at 300 concepts, and a pane resize cancelled initial framing on a
narrow reload. Both are fixed, with controlled camera/frame tests alongside the
real browser journey. The spring engine remains lazy; the first-load ceiling
now accounts explicitly for the accumulated Anatomy port (about 664 KB, around
3 KB above the earlier port). See the [acceptance record](../projects/anatomy/fluid-exploration.md)
for measured outcomes and the separate follow-up scope.

Follow-up validation: **4,176 tests passed, 70 skipped**; typecheck and production
build passed, with real browser checks on all three synthetic graph sizes.


Anatomy now isolates unreadable concepts, relationships and checkpoints instead
of failing the entire analysis. The browser keeps healthy concepts available,
labels diagnostics and offers a validated historical-file preview and recovery;
the CLI exposes the same through `validate` and `recover`. File-type changes
also remain diagnosable through native history. Incomplete views cannot become
silent partial exports or graph replacements.

Analysis requests now resolve their target through one shared helper. Stale or
ambiguous attachments and repository mismatches stop with an explanation.
Requesting work changes neither attachment nor repository, and another import
no longer replaces them. Versioned native request files carry Chat identities,
dispatch evidence and executor-reported outcomes. Concurrent identical requests
reuse an item identity; conditional edits arbitrate claims and retain competing
cancellation requests. A retry preserves its earlier receipt. Status is a report
from an executor, not an invented heartbeat or proof of a connected worker.

See [the recovery and requests acceptance record](../projects/anatomy/recovery-and-requests.md)
for validation and remaining boundaries.

Recovery/request validation: **4,190 tests passed, 70 skipped**; typecheck and
production build passed. Real CLI/daemon and browser checks covered file recovery,
request delivery, mismatch refusal, cancellation, retries and result navigation.
