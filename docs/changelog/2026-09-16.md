# 16 September 2026 — The facepile says whose, and the canvas learns to talk

## The facepile answers more than "who" (#309)

After an hour of real use the pile showed a row of near-identical blue
discs while the canvas held two people, four agents, two rcs and a sheep.
Every face answered *who is this*; nothing answered *is that a human* or
*whose agent is that*, and the second had never been answerable at all.
[The research note](../research/2026-09-15-reading-the-facepile.md) proposed
one channel per question, and the day built it.

**An agent wears its owner's colour.** Dion's shape: a person is a letter on
a solid disc of their own, an agent is its emoji inside the colour of the
person who owns it, so one glyph answers two questions. The colour goes on
the ring rather than the fill, because an emoji on a saturated disc fights
it — the argument `lib/face.ts` already made. `Face.owner` is one field,
`{id, name} | null`, where null *is* how a face is a person; an `agent`
boolean beside it could have disagreed. An unknown owner draws exactly as
before owners existed: better a plain face than a wrong one. People come
first, then a hairline, then the agents, and the hover card gains *owned by*
and the gate. The ladders followed the same day: lightness for whether a
face can be reached (away, enrolled, available), ring thickness for whether
it is doing something, up to a pulsing 3px for working. Enrolled standing
agents with no rc listening now appear at all.

**The "@" menu marks names that will not answer you, rather than hiding
them.** Dion asked for a filter; the change stops one step short. A name
that is absent reads as "does not exist", which erases the distinction the
bench spent a phase building, and the refusal already in the thread was the
most useful sentence of that evening — saying it before the click beats
saying it after, and saying nothing is worse than both. A shut agent reads
*won't answer you — <Owner>'s* and sorts last. The mention still resolves;
the gate decides whether a summons is answered, never whether the words
point at somebody.

**"you" now says who you are.** `policyWords` wrote *listens only to you*.
On 15 Sep a second machine had arrived as its own person (Admiral One, not
Dion), so granting Dion's id was redundant and the sentence was exactly
right — and it still cost an hour and a filed-then-retracted bug (#316),
because the reader had assumed which identity the machine had. It reads
*you (Dion Almaer)* now, and grant names get the same treatment.

The owner rings cost 757 bytes of the entry chunk, leaving it 1,113 past
the agreed 745,000 — a budget warning, named in the commit so it would not
turn up later as a mystery.

## Talk: a voice for the canvas, in the browser (#320)

Paul Kinlan's `@isocan/talk` module opens a Gemini Live session from the
browser with the viewer's own key, kept in that browser only. Tool calls
become ordinary operations through the shell's host, so a spoken request
wears the viewer's identity and their undo, and the session is handed the
canvas snapshot in the same wording the standing harness uses. It sits
behind the `modules.talk` experiment. Most of the PR was what using it
found: binary frames arriving as Blobs and dying in `JSON.parse`, a provider
refusal that read as silence, meters fed raw PCM that pegged or sat dead,
the model's image parts played as audio, and a StrictMode double mount that
opened the panel dead. The floating mic became the talker and ⌘K
"Configure voice" the settings. At Paul's request the module carries copies
of the harness's `live.ts` and audio code rather than depending on
`@isocan/voice-agent`, with header notes naming the originals.

## Smaller things, each with a reason

- **A comment that @-mentions somebody else is not for you.** In Chat or a
  shared thread, `@Dolly` is a question to Dolly, not a broadcast to the room
  or to everyone who ever spoke in the thread — so `reasonFor` returns
  nothing for the rest, and the inbox and `isocan wait` agree.
- **The design partner's always-on entrances go behind an experiment.**
  "Start design task" under every comment and "Ask design questions" at the
  foot of every thread meant forty controls on a forty-message canvas, for a
  feature a reader could not yet explain from the button. The panels still
  draw where a canvas already has design requests: hiding started work would
  be the worse bug. The project's design doc says what would bring them back.
- **`rc add` keeps listen grants**, and **`POST /api/rc/release` (#308)**
  lets a stopped rc drop its hold at once rather than waiting it out. Bench
  journey 4, the agent that answers at three in the morning, is walked in
  `bench.test.ts`.
- **The architect's question about core's dependencies was answered by
  measuring.** `core-runtime-deps` had been red since 12 Sep. Walking the
  runtime import graph from `packages/core/src/index.ts` reaches one of the
  nine declared dependencies (`nanoid`); the other eight sit behind the
  `./markdown` and `./design-audit` side entries. The reducer is as portable
  as the day the bound was set. The bound stayed at 1, and changing the
  instrument to count the closure was left for Dion rather than done to turn
  a red number green.
- **Grade PRs drain themselves**, implementing the rule in AGENTS.md.
- **Design-partner execution lessons** (87–88) and the measured phase
  timeline were written down, so later conductors run cheap staged checks
  before broad gates and one heavy verification job at a time.

Grades and a persona run landed as usual.
