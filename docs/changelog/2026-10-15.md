# 15 October 2026 — Capability-driven Node Focus: View, Edit Studio, Enter, and Node-Anchored Chat

## Why every node needed declarative capabilities and kind-aware focus

Selecting a node on the canvas used to scatter focus affordances across three unrelated doors: an under-card `"Full screen"` button, an ad-hoc `"Read / select text"` pill on Markdown cards, and a Workbench (`/w/:itemId`) built around raw text files. Static images had no metadata inspector or non-destructive crop/markup studio; `DESIGN.md` items lacked a live governed-screen matrix in View and a visual token/direction studio in Edit; wireframes had no visual slot/catalog composer inside Edit Focus; and opening Chat while editing an artifact was not anchored to the focused node or its active sub-element.

## What landed (`docs/projects/node-focus/`, phases 1–6 CLOSED)

- **Phase 1 — `NodeCapabilities`, top-left selection strip & context-menu/launcher rationalization (`packages/core/src/capabilities.ts`, `ItemView.tsx`, `menuentries.tsx`, `actions.ts`, `open --edit`).**
  Every node computes `{ view, edit, enter, file }` via `nodeCapabilitiesFor(item, version)` (extensible by loaded modules). Selecting a node renders a counter-scaled top-left strip with **`⤢ View`** (`Enter` → `/p/:canvas/i/:item`), **`✎ Edit`** (`E` → `/p/:canvas/w/:item`, when `caps.edit && canEdit`), **`↘ Enter` / `↖ Leave`** (**only** when `caps.enter` is true — screens, wireframes, documents, videos, and browser frames, never static PNG/JPEG images), and **`⊡ Fit`** (`F`). The right-click item menu and `⌘K` launcher are rationalized around the same four verbs (`View`, `Edit`, `Enter`/`Leave`, `Fit`), retiring legacy `"Open full screen"`, `"Open in the workbench"`, and `"Zoom to it"`. `isocan open <item> --edit` opens `/p/:canvas/w/:item` from the CLI.
- **Phase 2 — Unified Focus Header, `ModuleFocus` slot & Node-Anchored Chat (`FocusHeader.tsx`, `NodeFocusChat.tsx`, `ArtifactStage.tsx`).**
  `FullScreen.tsx` (`/i/:itemId`) and `Workbench.tsx` (`/w/:itemId`) share `FocusHeader` (`[ View | Edit ]` switch, editable title, version pill `vN`, and `💬 Chat (⌘J)` toggle). `WebModule` gains `focus?: readonly ModuleFocus[]`. When `caps.file` is true, Edit Focus offers `[ Studio | Code | Split ]` alongside `StageEditor` and `SaveToDisk`; when `caps.file` is false, CodeMirror stays out of the way. Opening Chat in Edit Focus mounts `NodeFocusChat` bound to `anchorItemId = item.id` with removable `FocusSubtarget` pills (`[focus: kind:id — label]`) and starter prompt chips.
- **Phase 3 — Image View (Metadata Inspector) & Image Edit Studio (`packages/core/src/image-metadata.ts`, `ImageFocus.tsx`).**
  Pure binary header parser `parseImageMetadata` (PNG `IHDR`/`tEXt`/`iTXt`, JPEG `SOF`/`APP1` EXIF TIFF tags, WebP, GIF, SVG `viewBox`/`<title>`/`<desc>`) and `imageBacklinksIn`. Image View Focus renders a pan/zoom lightbox (`Fit`, `1:1`, alpha checkerboard), split/onion version comparison, Metadata Inspector, and **Where Used** backlinks. Image Edit Focus provides non-destructive crop/aspect presets, rotate/flip, markup pen, alt-text editor, and `image-region` subtargets, stacking new `ItemVersion`s (`item.addVersion`) reversible with one undo.
- **Phase 4 — Rich Design System Focus (`DesignSystemFocus.tsx`).**
  Design System View Focus adds a **Governed Screens Matrix** auditing canvas HTML screens via `auditScreen`. Edit Focus embeds a structured Token & Direction Studio (color swatches with live WCAG AA contrast checks, typography scale, spacing/radius/component cards with live `{colors.*}` resolution, Direction & Voice fields, and `ds-token` subtargets) backed by `prepareDesignReconciliation` + `reconcileDesignProjection`.
- **Phase 5 — Wireframe Focus (`packages/modules/wireframe/src/focus.tsx`, `activation.ts`, `web.tsx`).**
  `@isocan/wireframe` contributes `wireframeFocusFacet` (`priority: 20`): View Focus adds interactive fidelity layer pills (`System · Copy · Low-Fi · High-Fi`), hotspot counts, and a toggleable **"Why this layout?"** (`explainWireDecision`) probability/entropy rail; Edit Focus provides the Wireframe Composer Studio (archetype/template/density selectors, `[data-wf]` slot inspector over the 53-component catalog, `POLISH_TOKENS` emphasis chips, copy/intent deck, Variations tray, and `wf-slot` subtargets) re-rendering valid `WireSpec` HTML via `renderWire`.
- **Phase 6 — HTML Screen Studio & `documents` / `mermaid` facets (`ScreenFocus.tsx`, `packages/modules/documents/src/web.tsx`, `packages/modules/mermaid/src/web.tsx`).**
  Built-in `screenFocusFacet` (`builtin.screen`) adds responsive viewport framing (`390` · `768` · `1440` · `Fit`), state preview toggles (`default` · `empty` · `loading` · `error`), inline `TextEditFrame` + copy-deck string roles (`copyDeck` / `applyCopyDeck`), and DOM landmark `FocusSubtarget` selection (`kind: "dom-element"`). `@isocan/documents` and `@isocan/mermaid` contribute reader/outline and diagram node-inspector `ModuleFocus` facets with clean module removability guards.
- **Performance pass across bundle and frame hot paths (`lookahead.ts`, `ItemView.tsx`, `modules.ts`, `FocusHeader.tsx`, `NodeFocusChat.tsx`, `ImageFocus.tsx`, `DesignSystemFocus.tsx`, `Toolbar.tsx`, `SprintChip.tsx`, `WhatsNew.tsx`).**
  Moved `@isocan/documents` and `@isocan/mermaid` focus views (`focus.tsx`), `@isocan/mindmap` edges (`edges.tsx`), and `WhatsNew`'s `Modal` behind `React.lazy()` boundaries (~8.3 KB trimmed from the entry chunk, back well within the `JUMP` budget). Cached `moduleCapabilitiesFor` by registry version, memoized `nodeCapabilitiesFor` and `displayedGroup` in `ItemView`, cached viewport `stageSize` via `ResizeObserver` and filtered `sweptCorridorEntry` ahead of version scans in `lookaheadCandidates`, decoupled `FocusHeader` and `NodeFocusChat` thread selectors from `canvas.items` mutations, keyed Where-Used / Governed-Screen blob fetches on candidate `(id, blobHash)` signatures, and pruned unused `Toolbar` / `SprintChip` UI-store subscriptions.
