# 15 October 2026 — Capability-driven Node Focus, `@isocan/lottie`, Explain simplification, and Stateless Proxy Identity

## Why every node needed declarative capabilities and kind-aware focus

Selecting a node on the canvas used to scatter focus affordances across three unrelated doors: an under-card `"Full screen"` button, an ad-hoc `"Read / select text"` pill on Markdown cards, and a Workbench (`/w/:itemId`) built around raw text files. Static images had no metadata inspector or non-destructive crop/markup studio; `DESIGN.md` items lacked a live governed-screen matrix in View and a visual token/direction studio in Edit; wireframes had no visual slot/catalog composer inside Edit Focus; and opening Chat while editing an artifact was not anchored to the focused node or its active sub-element.

## What landed (`docs/projects/node-focus/`, phases 1–6 CLOSED; `docs/projects/lottie/`)

- **Phase 1 — `NodeCapabilities`, top-left selection strip & context-menu/launcher rationalization (`packages/core/src/capabilities.ts`, `ItemView.tsx`, `menuentries.tsx`, `actions.ts`, `open --edit`).**
  Every node computes `{ view, edit, enter, file }` via `nodeCapabilitiesFor(item, version)` (extensible by loaded modules). Selecting a node renders a counter-scaled top-left strip with **`⤢ View`** (`Enter` → `/p/:canvas/i/:item`), **`✎ Edit`** (`E` → `/p/:canvas/w/:item`, when `caps.edit && canEdit`), **`↘ Enter` / `↖ Leave`** (**only** when `caps.enter` is true — screens, wireframes, documents, videos, and browser frames, never static PNG/JPEG images), and **`⊡ Fit`** (`F`). The right-click item menu and `⌘K` launcher are rationalized around the same four verbs (`View`, `Edit`, `Enter`/`Leave`, `Fit`), retiring legacy `"Open full screen"`, `"Open in the workbench"`, and `"Zoom to it"`. `isocan open <item> --edit` opens `/p/:canvas/w/:item` from the CLI.
- **Phase 2 — Unified Focus Header, `ModuleFocus` slot & Node-Anchored Chat (`FocusHeader.tsx`, `NodeFocusChat.tsx`, `ArtifactStage.tsx`).**
  `FullScreen.tsx` (`/i/:itemId`) and `Workbench.tsx` (`/w/:itemId`) share `FocusHeader` (`[ View | Edit ]` switch, editable title, version pill `vN`, and `💬 Chat (⌘J)` toggle). `WebModule` gains `focus?: readonly ModuleFocus[]`. When `caps.file` is true, Edit Focus offers `[ Studio | Code | Split ]` alongside `StageEditor` and `SaveToDisk`; when `caps.file` is false, CodeMirror stays out of the way. Opening Chat in Edit Focus mounts `NodeFocusChat` bound to `anchorItemId = item.id` with removable `FocusSubtarget` pills (`[focus: kind:id — label]`) and starter prompt chips.
- **Phase 3 — Image View (Metadata Inspector) & Image Edit Studio (`packages/core/src/image-metadata.ts`, `ImageFocus.tsx`).**

Image View Focus renders a pan/zoom lightbox (`Fit`, `1:1`, alpha checkerboard), split/onion version comparison, Metadata Inspector, and **Where Used** backlinks. Image Edit Focus provides non-destructive crop/aspect presets, rotate/flip, markup pen, alt-text editor, and `image-region` subtargets, stacking new `ItemVersion`s (`item.addVersion`) reversible with one undo.

## Why proxy-authenticated homes needed stateless arrival and session attribution

When a home already sits behind an authenticating reverse proxy (`ISOCAN_PROXY_EMAIL_HEADER`), minting a local `bdg_...` secret via `/api/door`, requiring a `#pss_...` pass inside a same-browser iframe, running `isocan identity --session` before an agent's first command, or keeping a background tunnel daemon alive just to inject proxy headers duplicated credentials the perimeter had already verified.

## What landed (`docs/projects/proxy-identity/`, phases 0–2 CLOSED)

- **Phase 0 — Stateless proxy principal at the door (`packages/core/src/attest.ts`, `packages/server/src/attest.ts`, `http.ts`, `ws.ts`, `packages/api/src/identity.ts`, `packages/web/src/lib/identity.ts`).**
  When `ISOCAN_PROXY_EMAIL_HEADER` (`proxyAuth`) produces a verified `email:<addr>` attestation on a badge-less HTTP request or `/ws` upgrade, the home derives a deterministic `bdg_prx_...` badge (`secretHash: ""`, never bearer-accepted without the verified proxy header) and binds a canonical `home:person` actor (resuming an existing actor attested to `email:<addr>` or claiming the email's local-part on first sight). `GET /api/attest` returns `bound` so `SsoGate` enters directly without a colliding `enterAs` claim, and `resolveIdentity` queries `actorBindings(["home:person"])` when `~/.isocan/identity.json` is absent.
- **Phase 1 — Stateless per-session agent attribution (`X-Isocan-Session`) (`packages/core/src/attest.ts`, `packages/server/src/attest.ts`, `http.ts`, `packages/api/src/routes.ts`, `client.ts`, `identity.ts`).**
  When an ambient coding harness session is present (`harnessVars`) and not overridden by an explicit `--as` or enrolled `agent:` identity, `DaemonRoutes` sends `X-Isocan-Session: <harness>:<sessionId>`. On a proxy-authenticated home, `(email:<addr>, sessionKey)` auto-claims a distinct agent actor on that person's proxy badge on first sight (`ownsAgent` = true) with zero prior `isocan identity --session` calls.
- **Phase 2 — External credential helper & forward-proxy transport (`homeAuth`) (`packages/server/src/config.ts`, `paths.ts`, `packages/api/src/auth-helper.ts`, `client.ts`, `ctx.ts`).**
  `HomeConfig.homeAuth` (`config.json`, `ISOCAN_HOME_AUTH`, `ISOCAN_AUTH_HEADER_COMMAND`) configures per-home `authHeaderCommand` (executed via `execFile` with `shell: false`, 10s timeout, and `ISOCAN_TARGET_URL`) and optional `httpProxy`. Headers are cached at `~/.isocan/auth-cache/<sha256>.json` (`0600`) with single-flight memory deduplication and refreshed once on `401`/`302`/`303`/`307` (`redirect: "manual"`), letting CLI commands speak directly to a proxy-protected home with zero `identity.json`, zero `/api/door`, and zero background gateway daemons.
