# 18 November 2026 — shrink before answering the bundle finding

The Plates Loop gate failed on two unanswered 14 November findings: two
ESLint errors and an entry bundle 10,793 bytes past the agreed 734,500.
The reports were correct. Dion asked to fix both, including a ceiling bump
**after** a shrink run. The queue's three-day deadline and its assertions
are unchanged.

Exact's `FilmStrip` now names the `exact.film` and `exact.frames` property
values before passing them into `useMemo`. Each parser still recomputes
only when its own serialized value changes; neither a suppression nor a
whole-properties dependency is needed. `npm run lint` reports zero errors.

The source-map breakdown (`node scripts/bundle-what.mjs --by-file --top 100`)
puts the largest costs in React DOM, core's canvas groups and reducer, and
the canvas components. These serve the main visit and remain eager. The
front and terms pages also remain eager for the cold-visitor reason already
recorded in `App.tsx`. No dependency or functionality was removed.

The release-notes dialog was a smaller real opportunity: everybody downloaded
it before anybody opened it. `WhatsNew` now loads `NewsDialog` on first open
and retains it thereafter, preserving the last reading while closed and
refreshing on reopen. The unread indicator and browser read-state helpers
remain eager in `lib/news.ts`. The dialog's seven CSS rules moved unchanged
to its own stylesheet; the CSS loader fetches it with the dialog.

Production builds of base `5618fbcb6` and the change, both using the locked
dependencies and Node **24.22.1**, measured through
`npm run build` and `node scripts/measure.mjs bundle-bytes`:

| Asset | Before | After | Reclaimed |
| --- | ---: | ---: | ---: |
| Entry JavaScript | 745,293 | 744,323 | 970 |
| Initial stylesheet | 139,113 | 138,540 | 573 |

The final entry is `index-BbLdMOZP.js`; the baseline is `index-DkywNKLJ.js`.
The source-map analysis reports 745,336 for the baseline because its build
adds a 43-byte source-map trailer; the table uses normal production assets.
The 970 bytes are removed from the initial download, not from all code a
person who opens release notes eventually fetches.

The remaining **9,823 bytes above the old ceiling** are explicitly accepted,
not claimed as savings. `CEILING` moves to **749,400**, following the existing
measured-size + 5,000 headroom rule, rounded up to the hundred. `GOAL` stays
640,000, `JUMP` stays 20,000, and the persona's 747,000 entry target still
asks before all of that headroom is spent. The 14–18 November performance
and QA rows now carry the answer and reason; `node scripts/reviews.mjs`
regenerates their index without rewriting the historical measurements.

Targeted regression coverage includes film parsing, release-note first open,
read marking, refresh on reopen, storage refusal, unread counts, eager import
reachability, lazy CSS and the source-map reader. A real headless Chrome walk
on a scratch canvas confirmed that neither `NewsDialog` asset is requested
before opening; opening loads its JS and CSS, renders the notes as a grid,
marks the newest day read, and closes and reopens without JavaScript errors.

The operation vocabulary, CLI verbs, agent guide, shared core helpers and
README feature list deliberately do not change: this is delivery and hook
maintenance, with the existing CLI news behavior preserved. Tests cover the
changed loading boundary and existing parser behavior.
