# 30 September 2026 — Proving Loop's claims, and the first minute's last two mechanisms

## Proving every Stitch Loop finding against the tree (`92bec34f`)

The first triage pass over Stitch Loop's 36 insights left a tell in a third of
the files: *"I did not run `npm audit`"*, *"Not verified if an explicit test
asserts…"* — a proposal written from reading one file and hedging the rest.
Dion asked to go back through all 36, **prove whether each sub-claim is
actually true against the codebase**, re-rank accordingly, and wire that proof
step into the nightly workflow.

`findingProblems` in [`packages/core/src/loop.ts`](../../packages/core/src/loop.ts)
now rejects any non-`untriaged` finding whose `## Our read` section still
contains unverified hedges (`I did not check`, `not verified`, `unverified`),
and `provePrompt` / `proveArgs` in `loop.ts` give `node scripts/loop.mjs pull`
and `.github/workflows/loop.yml` a bounded `claude -p` pass (`Bash,Read`) that
proves each newly pulled insight and records a proposal via `loop.mjs propose`
before opening or merging the nightly PR.

Re-proving all 36 findings moved three already-shipped items (`duplication-of-domain-computations-across-clients`,
`global-store-subscriptions-cause-full-viewport-re-renders`, and
`spatial-diffing-missing-for-agent-design-edits`) to `done`, promoted one stale
item whose third sub-claim held (`heavy-parser-dependencies-bloat-web-entry-chunk`),
and surfaced four `next`-ranked defects that we fixed and closed in the same
pass:

1. **Offline text creation and revision (`text-creation-and-comments-await-network-requests`):**
   `addTextNode` and `reviseTextNode` in `packages/web/src/lib/text.ts` now
   stage deterministic Markdown blobs locally via `uploadOrStageTextBlob` when
   `uploadBlob` fails offline, and `TextComposer.tsx` awaits `commit()` before
   clearing `pendingText` so a refused write never loses the user's draft.
2. **Offline canvas list (`remote-calls-bypass-local-canvas-replicas`):**
   `CanvasListPage.refresh` falls back to `recentCanvases(readRecents())` when
   `api.listCanvases()` fails offline instead of wiping the list with
   `setCanvases([])`.
3. **Rollup circular-chunk warnings (`heavy-parser-dependencies-bloat-web-entry-chunk`):**
   Extracted leaf validators into `packages/core/src/design-partner-values.ts`
   so `design-brief.ts`, `design-request-parse.ts`, and `design-partner.ts`
   form a DAG, eliminating all three Rollup circular-chunk warnings in the web
   build.
4. **Workspace manifest alignment (`workspace-package-imports-deviate-from-manifest-declarations`):**
   Declared `@isocan/api`, `@codemirror/state`, and `@codemirror/view` in
   `@isocan/web`, `remark-parse` and `unified` in `@isocan/cli`, removed unused
   `react-dom` from `@isocan/talk`, and added a workspace runtime import guard
   in `test/packaging.test.ts`.

## First-minute phases 4 & 5, per-asker standing, and roadmap reconciliation (`d1c94518`)

Closed phases 4 and 5 of [the first-minute project](../projects/first-minute/phases.md)
([#332](https://github.com/dglazkov/isocan/issues/332)) and the recommended
first step of [per-asker summons scopes](../research/2026-09-11-per-asker-scopes.md)
([#273](https://github.com/dglazkov/isocan/issues/273)):

- **Phase 4 (the summons carries its context, and says who woke it):**
  `summonsPrompt` in `packages/rc/src/helpers.ts` and `room.ts` now includes
  the summoning thread's full comment history, the anchored item's `{ id, kind, title }`,
  and — when a turn on an open agent (`listen: "everyone"` or a named list) is
  woken by someone other than the machine's owner — the standing sentence
  naming the asker and the owner whose machine is running the turn (#273).
- **Phase 5 (an agent that holds no secret, `no-secret-identity.md`):**
  With `ISOCAN_BADGE_UPSTREAM=1`, `ISOCAN_ACTOR_ID`, and `ISOCAN_ACTOR_NAME`
  set, `resolveIdentity` resolves the actor from the environment, reads and
  writes no `identity.json`, sends no `Authorization` header of its own, and
  never knocks on `/api/door` (`upstreamBadgeStore`). `DaemonClient` routes
  non-loopback requests through `HTTPS_PROXY` / `HTTP_PROXY` (honouring
  `NO_PROXY`) via `EnvHttpProxyAgent` without needing `NODE_USE_ENV_PROXY=1`,
  and names the proxy URL when the proxy itself is unreachable.
- **Flow-arrow touch long-press & roadmap front matter (`#350`, `#337`, `#206`, `#139`):**
  Added `[role=button]` to `CanvasViewport.tsx`'s touch long-press cancel
  selector so pressing a flow-arrow label pill on touch does not fire the
  radial menu, and reconciled stale front matter across `2026-09-23-flow-arrows.md`,
  `2026-09-23-wireframe-components.md`, `2026-09-19-move-the-red-one.md`,
  `2026-09-07-the-docket.md`, and `2026-08-24-voice.md`.
