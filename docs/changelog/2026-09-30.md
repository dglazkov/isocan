Dion asked to compare `/wire` against the standalone Jev design prototype and
port the best of both worlds into pure TypeScript (`@isocan/core/jev` and
`@isocan/module-wireframe`) with zero external sidecars
([research note](../research/2026-09-30-jev-isocan-synthesis.md),
[phases 9–13](../projects/wireframes/phases.md),
[#369](https://github.com/dglazkov/isocan/issues/369)):

- **Phase 9 — Multi-region `@container` layout templates, density, and `data-wf` paths (`da237a5c`):**
  Added 7 spatial layout templates (`single`, `sidebar-main`, `main-aside`,
  `split-50-50`, `three-col`, `top-grid`, `master-detail`) with nested
  `container-type: inline-size` sub-regions so `sidebar-main` and `main-aside`
  never clip inside 320px columns, `density` (`compact` | `default` | `spacious`)
  scored in Round 2, and stable `data-wf="<screen>.<slot>.<el>"` + `data-sec="<slot>"`
  DOM paths across every rendered block.
- **Phase 10 — `PriorityGate` and entropy-gated `/ask` in `@isocan/core/jev` (`2454d333`):**
  Added a 3-lane priority concurrency limiter (`PriorityGate`) so interactive
  single-screen edits preempt bulk background calls, plus `entropyBits` and
  `gatedChoice` so high-entropy ($H(p) > 0.85\text{ bits}$) or low-confidence
  ($\max_i p_i < 0.55$) choices surface an interactive `/ask` card in the Chat
  or CLI (`--pin <key=value>`, `--no-ask`).
- **Phase 11 — Surgical section editing (`wire edit`) and decision Q&A (`wire why`) (`6d3c7f15`):**
  `isocan wire edit <screen> "<instruction>"` (and `/wire edit`) uses Jev to
  classify and scope an edit (`content` | `add` | `remove` | `variant` | `restyle`)
  to a single slot (`scopeEdit`), leaving all sibling slots untouched and
  rebuilding the kept prototype via `followFlowPrototype` in one undoable op
  group. `isocan wire why` (and `/wire why`) reads `WireSpec.decisions`
  (`compactDecisions`) to explain why each screen, archetype, template, density,
  and block was chosen, citing the recorded probabilities and entropy.
- **Phase 12 — Schema-driven AI copy (`wire copy --ai`) and flow naming (`wire name`) (`4a21bd82`):**
  Added the vendor-neutral `TextGenerator` seam (`stubTextGenerator`,
  `httpTextGenerator`) in `@isocan/core/jev`, `blockContentSchema(spec)` for
  strict per-slot JSON-schema copy generation that keeps actionable `Intent`
  bindings intact, and `nameFlow` + `sanitizeFlowTitle` so `isocan wire name`
  and `isocan wire copy --ai` (and `/wire name`, `/wire copy`) populate coherent
  brand names, screen titles, shared navigation bar labels, and domain copy
  across a flow in one op group.
- **Phase 13 — Concurrent design system synthesis (`wire ds`) and Jev-budgeted polish (`wire polish`) (`8688ed84`):**
  `isocan wire ds "<request>"` (and `/wire ds`) runs `proposeThenPick` across
  candidate visual directions, deterministically repairs any foreground/background
  token pair below 4.5:1 WCAG AA contrast (`repairContrast`), writes a complete
  `DESIGN.md` item beside the flow, governs the scope (`designUse`), and restyles
  all screens and the prototype in one op group (**Swap 1**). `isocan wire polish`
  (and `/wire polish`) scores `polish_intensity` ($0\text{–}1 \rightarrow 0 | 4 | 8 | 12$
  patch budget), applies `POLISH_TOKENS` to `data-wf` slots, and gates every
  version with `verifyWireContract` (**Swap 2** contract verification) so no
  `data-sec`, `data-wf`, `data-hot`, or `data-intent` node is ever lost and AA
  contrast always holds.


## Voice phase 7: the fast path acts (`d2eae116`)

Phase 6 had Jev listen in shadow beside the live voice model. Phase 7 lets
it act for the one verb with a measured threshold. A plain spoken move
("move the login page left of home") runs at once through the browser's
own `runTool`, the executor the model's tool calls use, so it is one
`item.move` and one undo. It is announced with "say undo", and anything
less certain goes to the model unchanged. Acting lives in a new
`fastact.ts` that is handed the executor, so the shadow and the resolver
keep their non-acting source guard. The switch in Configure voice is now
three states, and off is still the default.

The conductor settled two of phase 6's open items without a microphone:

- **The race.** Whether the transcript beats the model's first tool call
  had never been read from a real record. So the fast path does not race:
  the model's acting calls for a turn are held up to 1.5 s while the words
  settle and Jev answers. They are refused as "already done" if the fast
  path acted, and released in order otherwise.
- **"Say undo".** The fast path's announcement would have been a promise
  the browser could not keep, so `WebHost.retract` (module API 0.2.3)
  hands modules the same actor-scoped undo ⌘Z calls. The voice dialog's
  `undo` now retracts instead of refusing.

What it taught:

- **The threshold moved.** A rerun of the same 197 scripted commands put
  phase 6's 0.60 at 94.3%, under the bar, so `move` acts at p ≥ 0.63.
- **Probability alone let "300 pixels to the right" through,** so numbers
  are now escalated by a deterministic check.

On a fresh daemon with the real Jev: 63 acts, 61 the one meant, every one a
single op that one retract restored, and 134 escalations that wrote nothing.
Last word to acknowledged was p50 565 ms. The microphone walk, which would
