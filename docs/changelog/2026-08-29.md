# 29 August 2026

Sixteen commits in two lanes that never touched each other. On `main`: personas
get a file, a model and a panel; auto-upgrade finishes, so a machine nobody is
watching keeps itself current; a performance question answered by counting
rather than reading; and phase 10.5 finally closes on two walks a session could
never have supplied. On a branch: phase 11's direct mode — a machine that runs
no daemon at all — and the door Scene 6 opens with, which turned out to be
assigned to no phase at all.

## Personas: a file, a model, a panel

Three commits, and the shape is the one this repo already had. `.agents/personas/*.md`
is the file; `.claude/agents/*.md` is a relative **symlink** to it — the same
arrangement `installSkill` uses, whose comment states the principle: one copy
per directory, several doorways to it. A guard asserts each doorway is a link
and resolves, because the failure is silent — the moment one becomes a real
file, copied by a tool or restored by an editor, there are two personas with
one name, they drift, and only one harness ever sees it.

**A goal is `(number, bound, the command that produces it)`**, never an
aspiration, and a goal missing any of the three is DROPPED rather than
half-kept: half a goal reports success forever, which is the failure the whole
feature exists to prevent. `scripts/measure.mjs` is that command — one number
on stdout, every metric declaring a way to break it, and `--selftest` breaking
each on purpose.

Then the panel, and with it the day's sharpest small finding: **personas needed
a jail of their own.** The file tree's `listable` refuses every name beginning
with a dot, which is exactly what keeps `.ssh`, `.env` and `.git` out of a
listing anybody can ask for — and personas live under `.agents/`. Loosening
that rule for one markdown feature would open all three. So `personas.ts` has a
narrower jail: **the directory is fixed and the name is a stem, never a path.**
There is no traversal to catch because nothing can express one. Twelve cases
shake it, symlinks in both directions included. And a save with no front matter
is refused *before* it is written, because the alternative is the worst shape a
save can have — it succeeds, the file parses to null, the next listing skips
it, and it is saved, gone, and silent.

## An upgrade is a build proved aside, then one symlink

Auto-upgrade phases 3 and 4. `npm i -g` overwrites in place, which is why it
can never run unattended: a failed install leaves no working CLI and nothing to
fall back to. So isocan owns its install root — `~/.isocan/builds/<sha>`, one
tree per build, `current` naming the one in use.

An upgrade installs into a directory nothing points at, starts that tree as a
daemon against a scratch home, asks `/healthz` which commit it is, and only
then renames one symlink. A candidate that will not start, or that is not the
build it was fetched as, leaves the machine on what it was running and says
why.

Phase 4 gives it callers that are not a person: an agent parked in `isocan
wait`, `isocan restart`, and `ensureDaemon` — three moments idle by
construction rather than a timer. A park considers an upgrade every lap and
reports it *in the wake it was parked for*, because an agent reads one message
and then acts.

Two things the design asked for cannot be built as written, recorded rather
than quietly dropped: `--channel main` would install an empty directory, and
the home cannot report commit subjects between two shas because the image has
no `.git`.

Then the default was found denying itself to the population it was written for.
`auto` was for managed installs and `notify` for everything else — but `setup`
runs `npm i -g`, so **a global install is what every machine that came through
the front door IS**, Priya's included. On her machine the four steps notify
mode requires never complete, which is the exact argument for `auto` existing.
So `global` is `auto` too. `npx` and `local` keep the notice, and not out of
caution: an npx cache is a directory npm is about to delete.

## The tether measured something that had not moved

Answering a direct question — did the performance work actually check for
excess re-rendering? — the honest answer was no, not systematically. So: a
temporary counter in all 103 components, through a scripted pan and zoom.

`ItemView` renders **zero** times during a pan. Idle is genuinely idle. **One
component rendered twice per frame, and it was holding the 14% an earlier note
left unexplained.** `LaneTethers` called `setLines([])` with a *fresh* array
while suppressed — `Object.is` sees two different arrays, so React never bails,
and a pan re-rendered it sixty times to set empty state that was already empty
— and ran `getBoundingClientRect` on every chip in an effect keyed on the
viewport, forcing layout to measure something that had not moved, because **a
chip lives in the panel and does not move when the canvas pans.**

    zoom  worst frame 33-67ms → 10-17ms
    script 1.20-1.28s → 1.11-1.15s

The guard had asserted `setLines([])` — one *spelling* of the rule — and failed
on a refactor that kept the rule and improved it. It asserts the rule now. And
the lesson is the method: two earlier hypotheses about zoom were wrong and both
were settled by counting renders rather than reading the component tree.

## The other lane: a machine that runs no daemon at all

### The switch is called `--direct`, not `--thin`

The journey has called this seat "thin" since Scene 6 was written, and that word
is fine in prose about a topology. As a flag it tells somebody who has not read
the journey nothing about what will happen. What the switch actually means is
*do not stand up a local daemon or replica here; commands talk to the home
itself* — so it is `--direct`, `ISOCAN_DIRECT`, and a `direct` key in
`config.json`, one spelling across all three surfaces.

The alternative that nearly won was `--no-daemon`, which is more literal and
matches `setup`'s existing `--no-install` and `--no-open`. It lost on the other
two surfaces: `ISOCAN_NO_DAEMON=1` and `{"noDaemon": true}` are both negative
names, and a setting whose natural spelling is a double negative is one people
get wrong. "thin/thick" stays in the journey as the name of a seat.

### No provider is named in the code, on purpose

The obvious way to build "setup notices what it stands on" is to sniff for the
cloud you expect to be running in. That is wrong here, and not only for taste:
**direct-versus-daemon is a property of the directory, not the vendor.** A CI
runner is disposable; a cloud development workspace has disk and persists for
days and would reasonably want a daemon; a headless box in a closet wants one
like any laptop. A table of vendor fingerprints gets half of them wrong.

So the shape is `harness.ts`'s, for `harness.ts`'s reason — a table isocan
happens to know, a `config.json` hook so an environment isocan has never heard
of works the day it ships, and an environment variable that beats both. The
built-in table has exactly **one** entry, `CI`, because that one probe covers
every continuous-integration system worth covering and nothing else can be
guessed on somebody else's behalf. Anyone else adds a line of
`{"ephemeralVars": [...]}` rather than waiting for a release.

The guess is narrower still: it runs **only in `setup`**, only when nobody has
declared, only when nothing is attached to a terminal, and only when an address
is already in hand — because direct mode with no home is a CLI with nothing to
talk to. Then it is written down, which is the phase-14 birth-default shape
again: decide once, record with a receipt, and leave every later command with
nothing to re-derive. A per-command sniff would let an exported variable move an
agent's canvas between two replicas halfway through a session.

### The seam was one function, because the CLI never touched the store

The expected cost of this phase was a transport rewrite. It was not. Grepping
first turned up that the CLI's use of `~/.isocan` is identity, actors, config
and session files — `paths.canvasesDir` has exactly one caller, in
`neverHeldACanvas`. **Canvas data and blobs already travelled over HTTP.** So
pointing `DaemonClient.base` at the home is most of direct mode, and the work
was collecting ten hardcoded `http://127.0.0.1:${port}` sites into one
`resolveBase` — which is worth doing on its own, since ten call sites each
learning the rule separately is ten chances to reach the wrong replica, silently,
because both answers are real daemons that will cheerfully serve the request.

Two things turned out to be already correct, both written for phase 10.3's many
homes: `redeemPass` omits the `home` field when it equals its own base, which is
exactly right when the base *is* the home; and `joinFromHome` answers
`not-a-replica` with a 409 that callers already swallow. Neither needed a line.

What refuses now: `serve`, `restart` and `stop`, because they are about a
process the machine has decided not to run, and starting one would give it a
second replica queueing toward a home the CLI is already talking to. `isocan
home` too — a canvas made on a direct machine is born at the home, so there is
no birth default to hold. `isocan status` stops saying "daemon: not running",
which is the answer a broken machine gives, and describes the home instead.

### Why isn't `--direct` the default?

Asked mid-build, and the answer moved a debt. **The daemon's headline
justification is offline, and offline has never worked for the CLI:**
`HomeUnreachableError` refuses a replica's CLI write when the home is
unreachable, deliberately, and says so in its own message. Writes forward
synchronously to the home's single-writer pipeline either way, so the replica
*adds* a hop rather than removing one; only reads are served locally.

And the part that reaches further: a machine with no CLI replica has exactly
**one** replica — the browser's, from phase 10 — instead of two that cannot see
each other. That is the entire premise of the local-bridge debt. Flipping this
default would retire phase 12.7, its Private Network Access dependency and its
failure-mode list, by deleting the thing they exist to reconcile. What it costs
is the airplane thesis, converted from a debt into a decision: a person in the
browser and their agent in the terminal with no network becomes
impossible-and-honest rather than half-built-and-silent.

It cannot be unconditional — a locally-born canvas needs a daemon to be its
home — so the honest formulation is *direct when the canvas lives elsewhere,
daemon when this machine is the home*, and since phase 14 the first is the
common case. It is `DEFAULT_MODE` in `direct.ts`, one line, and it is filed in
Deliberately open rather than decided, because the evidence is a real session
rather than an argument.

### The kill test came back with a finding

The lap was driven by hand against a scratch home — name, create, list, park,
wake, reply — and `isocan wait` parks at the home and wakes on a mention with
nothing bound to `127.0.0.1`. The kill test did not pass, and is the more useful
result: **a killed agent's ring lingers for five minutes.**

CLI presence is TTL-based (`SESSION_TTL_MS`, five minutes, swept every ten
seconds) and touched by commands — it is not bound to a connection. Measured
after a `kill -9`: still there at t+250s, gone at t+300s. So Scene 6's *"her
ring fades only if her sandbox dies, which is the truth"* holds only within a
five-minute window, and for that window the pile says "here" about a sandbox
that no longer exists. It is not caused by direct mode — a thick agent behaves
identically — but direct mode is what makes it matter, because a torn-down
sandbox is the ordinary way this agent ends. Filed open; the fix is presence
bound to a connection rather than a clock, which belongs to the ephemeral plane
and not to this phase.

### The door Scene 6 opens with, which no phase had

Direct mode was built, tested, and unwalkable. "Run an agent in the cloud…" —
the dialog Scene 6 *opens* with — existed in exactly one place in this repo,
`journey.md:295`, and in no phase. Its Scene 5 sibling has been a real
component since phase 8, which closed only when the dialog at dev minted a pass
and the pasted command worked. Phase 11's Outcome said "an agent in an empty
ephemeral directory works the canvas": a statement about the *mechanism*, so
building to it produced a verifiable CLI and no journey. Caught by Dimitri
asking what he was being asked to verify.

The dialog is `TerminalDialog`'s sibling in shape and deliberately not in kind.
Scene 5 hands a shell command to a person at a terminal; this hands a **prompt
to an agent**, because the four clicks are New session, pick the repo, paste,
Start, and the paste goes into a prompt box. Two things it does that its
sibling must not:

**The line carries `ISOCAN_DIRECT=1`**, which resolves the tension direct mode
left behind. Refusing to sniff the vendor made "setup notices what it stands
on" false in a sandbox that sets no `CI`. It is true again without a guess:
**picking the menu entry IS the declaration**, so the line declares and the
person still types nothing.

**The pass endows nobody.** Scene 5 puts your machine on the canvas and its
pass carries your identity; Scene 6 starts an agent, and the journey is
explicit that it claims its own actor, finds Isaac and Nico taken, and names
itself. An endowing pass would put a second face wearing your name in the pile.
The dialog's closing line changed with it — "it arrives as you" is false here,
and that sentence sat directly above a credential somebody was about to paste.

Then walking it found what fifteen green tests had not. `setup <address>` is
the only path that writes `home` into a marker, and no test took it: **the home
answers `null` for its own canvases** — meaning "the daemon you are talking to
is its home" — and `refuseHomeDisagreement` read that as "a LOCAL canvas on
this machine" and refused. Every command after a successful arrival failed,
including the `identity --session` the agent runs next. `null` resolves to
whoever answered now, which is what it always meant.

The lesson is cheap to state and was expensive to learn twice in one day: a
scene's UI is load-bearing, and prose in the journey reads like description
rather than like work. **Phase 12 has the same hazard right now** — its
registration UI is one clause of its Work line.
