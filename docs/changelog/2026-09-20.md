# 20 September 2026 — "Move the red one next to the blue one, actually undo that"

A branch of cloud-session work landed at once — judge, voice, memory and
extensions — and the voice work continued on a laptop through the evening.

## Voice: the bottleneck was what the model was shown (#337)

Asked from a video in which a person says *move the red one next to the
blue one, actually undo that* and it just happens: could Gemini Live 3.8
and TypeSafe's Jev do that here? The research answer was that the models
are the part that already works. `@isocan/talk` hands a live session 47
canvas operations as tools. What blocked the sentence was
`canvasSnapshotText`, which gave the model a title and an id per item and
nothing else — so "the red one" could not be *attempted*, and "next to" had
no coordinates to compute from. The work split by what needs a vendor, and
everything that does not was built:

- **Where things are.** Each row now reads `"Title" [id] kind WxH at
  (x,y)`, under a header stating that y grows downward, capped at sixty in
  reading order with the rest disclosed so the model can ask. Reading order
  rather than viewport order, as the note had said, because the standing
  harness has no viewport and the two surfaces must describe one canvas one
  way.
- **Colour.** A closed spoken vocabulary of eleven words in `core/colour.ts`
  ("darkslategrey" is nobody's word). `itemColour` answers only from data
  that means colour — a note's paper, an area's tint, a drawing's dominant
  ink by stroke length — and never from a title: "Red team retro" is not a
  red item. The header says an absent colour means *unknown*, not *not that
  colour*, and tells the model to ask.
- **"Next to".** `move_item` gains `beside_ref` and `side`, computed by
  `besideBox` in core over the existing placement gap. It deliberately does
  not dodge a busy spot: landing somewhere else is how a spoken command stops
  being trusted. `isocan mv --beside` followed, because a sentence reachable
  by voice and not from the terminal is the drift the isomorphism exists to
  prevent. No new op; "beside" is a way of saying where.

Driving a real Gemini Live session then found two bugs that looked fine
from inside. **The red one still could not be resolved**: ink was the only
route to red (red is not a paper), and no production caller could reach the
stroke branch, because an item's strokes live in its SVG blob. A drawing now
writes its colour word when the ink is laid — the Pen, `drawing_add`, and
the CLI's add and merge, which read the ink back from an SVG format we write
ourselves. **There was no `undo` tool**, so told "actually, undo that" the
model improvised an inverse move — which demos beautifully and is wrong: the
log then claims both changes were meant, and a delete has no inverse from
memory. Before and after, against the same canvas: an "I'm not sure which is
the red one" became a `move_item` with `beside_ref` in 958 ms, and the
improvised move became `undo {}` in 596 ms. The browser dialog declines undo
in words, because widening the module API is a versioned decision.

`test/live-copy.test.ts` now holds the talk module's copy of `live.ts`
byte-identical to the harness's, turning "reconciled by hand" into a bound.

And **[`docs/verify/`](../verify/)**, a third lane for what no machine can
check — is the reply audible, does the pause feel like a partner. Everything
that "verified" voice so far went in as typed text. Each walk is a dated page
for somebody with no repo knowledge, written by the builder, because the
builder knows which step breaks. There is no gate: a walk costs twenty
minutes and a microphone, and a gate on that would be switched off by the
first person shipping at midnight.

## Judge: a typed judgment tier (#334)

[Research](../research/2026-09-19-system-one-and-the-ledger.md) into
"System One" models — a typed answer with a calibrated probability and no
prose — became [a project](../projects/judge/) the same day, because the
repo had twice asked for this shape without naming a vendor: #205's declared
cost for the nightly personas, and the evals plan's $0.39 comparisons. The
constraint that shapes it: such a judge cannot cite, so it triages and never
rules. What it buys is a cheaper *sort*. Phase 0 read the vendor's reference
first-hand and found the sketch wrong in three places (a Choice returns the
whole distribution; one request asks many questions; only input is billed).
Its confidence is not p(correct), and the same request five times moved by
±0.035. The one hand-run card was wrong in the shape the project studies: it
chose the parent folder at 0.72 over the subfolder a person picked at 0.23,
with 0.99 of the mass on the right branch — the region, not the depth.
Phase 2 is allowed to end the project. The build container cannot reach the
vendor at all (the proxy refuses the tunnel), so the vendor phases are a
local leg, recorded so nobody rediscovers it a third time.

## Memory closes; extensions reorders

**Memory phase 6**: `isocan context pin <item> --from <canvas>` and the
picker's "Copy a piece here" make an editable pinned copy of one inherited
piece. It is the existing copy act with a `decorate` hook, so pin,
provenance and stripped design role ride one `group.change` and one undo,
and the byte path is shared so a browser cannot grow a second one. The
phase's Proof named an entry ceiling eleven kilobytes stale and
contradicted its own requirement; the number was corrected and the eager
cost measured at 1,080 bytes. Every memory phase is now closed.

**Extensions** got its `phases.md`, and writing it changed the order: the
demand since 6 Sep has all been for the hosted tier (modules' browser
sandbox, the workbench's Sandboxes), none for declarative panels, so hosted
comes first and declarative waits on evidence. Phase 3 then built the panel
manifest: `role=panel` on an ordinary item, `isocan panel add`, one reader
whose refusals the CLI prints verbatim. Nothing renders yet, on purpose.
