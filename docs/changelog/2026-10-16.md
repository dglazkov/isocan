### Persist actor marks across joined identities and multi-instance engines

`26c42fc`

When two browser sessions join into one identity and Cloud Run routes requests
across multiple instances, setting a profile mark could fail or revert on
reload: `claimsActor` checked raw `actorId` without resolving joins, and cached
`actorsRuntime` on a second instance could sit behind the newest `ACTORS` seq
and either serve a stale mark or throw `OplogFencedError`.

- Make `claimsActor` resolve `joined` so a joined session passes ownership checks
- Add `tipActorsSeq` on `Store` and `CloudStore` and reload `actorsRuntime` when
  a newer seq exists in storage
- Retry once on `OplogFencedError` in `setActorMark`, `setActorColor`,
  `joinActors`, and `applyClaimAndPersist`
- Re-sync `/api/marks` after saving a mark in `IdentityMenu` and surface errors

### identity: --home --as makes a pass-admitted actor this machine's person

keyless row, so the same command with the old id switches back; harness
keys are unchanged. Same path in direct and daemon mode.
