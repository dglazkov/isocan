# 17 September 2026 — A machine with no browser is told, not crashed

A collie test run in a GitHub Codespace found two ends of `isocan setup`
where the road stopped without saying so.

**The opener no longer takes the command down.** `openInBrowser` spawned
`xdg-open` and handled nothing, so on a machine without one Node raised
the child's `error` event unhandled: `isocan setup` printed its report,
then a stack trace, and exited non-zero after having done everything it
said. The child now has an error handler, and a missing opener is one
stderr line naming the opener it looked for and the switch that stops the
attempt (`ISOCAN_BROWSER=none`). The address was always printed by the
caller; what was lost was only the ending. `browser.test.ts` points the
switch at a path that does not exist and reads the line.

**"Name yourself here" now says how.** A pass redeemed with no identity on
it left setup saying *admitted — this pass carried no identity, so name
yourself here*, and "here" meant the browser it had just failed to open.
The line now names the two ways a machine gets its person from a
terminal: `isocan identity --home --name "You"`, or a pass minted as you
(the app's "Bring your own agent" line, or `isocan pass` on a machine that
already is you). Sheep's `collie setup` stops at the same fact and, from
today, says the same thing instead of pointing back at `isocan setup`.

What the run did not explain: the pass that Codespace redeemed had been
minted from the app's "Bring your own agent" dialog, which mints for the
tab's own actor, yet arrived with no identity. The same dialog's pass
redeemed on a laptop the same evening handed the identity over. The
Codespace's `~/.isocan/daemon.log` is where the answer is, and it was not
kept.
