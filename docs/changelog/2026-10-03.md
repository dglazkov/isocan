# 3 October 2026 — Fake keys look fake

A "Secrets detected" alert flagged the model-keys tests. None of them held a
real key, but two fixtures matched Google's API key pattern exactly — an
`AIzaSy` string of the right length in `authaction.test.ts`, and the Gemini
key in `keys.test.ts` — and about forty more carried real provider prefixes
(`64e6552`). A fixture that looks like a credential costs the same alert as
one that is, and teaches the next reader to ignore it.

So the fakes now say what they are. Gemini keys are `fake-gemini-…`, and the
Firebase link's `apiKey` is `FAKE-firebase-web-key-TESTONLY`. Anthropic fakes
keep the `sk-ant-` prefix, because `textProviderFor` reads it to choose
Claude, but are short and spelled `sk-ant-fake_…`. Nothing in the source
validates a key's shape, and keys are only ever shown by their last four
characters, so no behaviour changed.

The guard is `test/secret-shapes.test.ts`: it reads every tracked text file
and fails on a Google, Anthropic, OpenAI, GitHub, AWS or Slack credential
shape, or a private key block, with a case proving it catches the one that was
reported. It earned its keep within the hour — on rebase it caught
`live-token.test.ts`, added by keys phases 3–4, still matching Google's
pattern, and the rest of those phases' fixtures carrying real prefixes
(`a6a2e36`). Lesson 107 records it.

Loop findings (`e2d80fc`) and the practice page (`71db635`).
