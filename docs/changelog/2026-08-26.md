# 26 August 2026

## Trajectories: the history becomes readable, then legible

The [Headlong survey](../research/2026-08-24-headlong.md) found the gap in one
measurement: `compactOplog` writes every dropped entry to
`oplog-archive.jsonl`, and nothing in the product could read that file. isocan
was preserving its history into a record with no reader — "a delete with
better manners." Today the read half shipped, and with it the survey's other
trajectory idea.

**The archive opens.** `Store.readArchivedLog` is the read half of
`compactOplog`'s write half, implemented on both backings (a JSONL read on
disk, an object read in the bucket) and enforced by the storage-seam
conformance suite, so a third backing cannot ship the write without the read.
It surfaces as `GET /api/projects/:id/oplog/archive` and as
`isocan tail --archived` — the full history, live log and archive in one seq
order. With `--archived` and no `-n`, tail prints everything: the flag asks
for the whole past, and a default window of 10 would answer with none of it.

**`isocan recap` — the history at decaying resolution.** Headlong renders its
trajectory with recent entries verbatim and older ones progressively
summarized, the tiers acting as an index. isocan now does the same over the
record it already keeps: the last N ops verbatim, and behind them windows
that double in size with each step back, each summarized to one line — who,
how many ops, how much conversation, which items (titled from live state when
the item survives, from the ops themselves when it does not). Every window
carries its seq span, and `tail --archived` replays any of it at full
resolution. The tiering is pure math in `@isocan/core` (`buildRecap`), so the
CLI renders it today and any surface can render the same structure tomorrow.

The principle both changes serve is Headlong's, taken seriously rather than
quoted: *nothing is compacted away in place — compaction and introspection
operate on the same record.* `gc` already archived instead of deleting; now
the product can open what it kept.

Both surfaces, walked: no new `Operation` (these are reads), two CLI verbs
(`tail --archived`, `recap`), the agent guide teaches both (and the surface
test enforces it), the tiering lives in core, the README says so, and tests
land at every seam — recap tiering in core, the archive round-trip in the
store conformance suite (both backings), and the route in the gc suite. The
web app deliberately gets nothing today: recap is orientation for an agent
arriving by CLI; the web's activity list stays the human's reader until a
scene forces more.

## The workbench, V1: the agent room

The [workbench design](../projects/workbench/design.md) stopped being a
document. `W` (or `isocan open --workbench [item]`) flips the canvas to a
cover — FullScreen's exact architecture, so the socket, presence and viewport
survive the flip and Esc lands at the zoom you left — holding the agent
roster, the one main thread, and one artifact on a stage.

The build matched the design's headline finding: **zero new operations, zero
new protocol messages**, and `workbench.test.ts` keeps it that way — the
workbench's own code may not call `sendOp`, must render the thread through
`MainThreadBody` (the same component the canvas docks, grown a `docked` prop
so the permanently-open column marks messages read on engagement rather than
on flip), and must build every address from `address.ts`'s new
`workbenchPath` family. The stage extracted `ArtifactStage` out of FullScreen
so `/i/<item>` and `/w/<item>` render one item through one component — the
two-products tell, closed before it could open.

The roster is presence projected: one row per actor (the facepile's law, but
cli-primary rather than first-push-wins — `lib/roster.ts`), working rows
first, the status string VERBATIM with its quiet-age beside it. No PARKED
badge: that waits for `statusSource` to cross the wire, and string-matching
the wait copy into semantics is banned by name in the design. Expanding a row
shows the thread it is answering, a live thumbnail of its working locus
(click puts it on the stage), and `recentActivity`'s made/edited/said trail.

The lazy chunk came in at 4.5KB with the main bundle up ~1.4KB, and the
spacing guard earned its keep during the build: `padding: … 22px` was a
26th spacing step the scale had never had, and the fix (24px) turned out to
be the honest indent anyway — the dot, its gap, and the head's padding sum
to exactly 24.

## The workbench, V2: the working surface

Same day, second stage. The editor is the headline: an editable artifact
(text by mime — `editableText` in core; a png simply has no Edit tab) gets
Preview / Edit / Split across the stage in BOTH covers, CodeMirror riding in
its own 613KB chunk that Preview never loads, and **⌘S is `item.addVersion`**
— the identical op `isocan edit` sends, so a web save stacks, S-fans,
promotes, undoes per-actor, and wakes an agent parked on `wait --item … --op
item.addVersion` exactly like a CLI edit. Drafts persist and restore
silently (the sketch precedent), keyed by the version the buffer opened
against; a version landing under you is a note, not a conflict dialog —
the stack keeps both.

Underneath it, the honesty work: `statusSource` crosses the wire (the
daemon's private sticky boolean became the stored source — one field, one
home), `roster()` moved to core with `openAsk` beside it, and both surfaces
answer from the one derivation: `isocan who` grew a STATE column and the
workbench wears the same states as pills. An agent that starts a comment
with `/ask` reads as **blocked** — pinned first, cleared by an ANSWER
(anyone else replying in that thread), never by being seen — and the agent
guide teaches the convention. Away rows landed with the probe-actor defence
built in: only actors who actually DID something here, capped, newest act
first — and never the viewer, who is by definition not away.

Verified as a full loop on the live canvas: Kenny parked with an open ask →
who says `blocked` → the answer posted from the browser cleared the pill AND
woke him ("reading your comment…", exit 0 from wait) → the editor saved a
version attributed to the browser's actor that `isocan versions` read back.
The agent column grew a drag edge (PanelResizer generalized to props, its
two old call sites untouched) and folds to a rail, both remembered.

## The workbench, V3: the disk, the watch, and the invitation

The file tree arrived with the security review's rules intact rather than
softened: `GET /tree` and `/tree/file` answer only on a loopback-bound
daemon, to a loopback peer, for a canvas living HERE with a binding the
on-disk marker confirms — owner-scoped, never the admissions door, because
every canvas is born with a link grant and a tree behind that door hands
anyone with the link the owner's `.env`. `server/tree.ts` jails
independently of the gate: no dotfiles ever, secret shapes denied by name,
symlinks never followed, traversal refused in every spelling — and the
mutation pass earned its keep twice, catching one equivalent mutant (the
symlink clause was dead code behind lstat, now deleted with the reason
written down) and one deliberately unreachable wall (the POSIX-redundant
prefix check, kept as the belt and existence-asserted with lesson #16's
honest exception).

`isocan tree` prints the same listing from the same route; the workbench's
files pane renders it with the line between disk and canvas drawn in UI: a
file that IS an item opens on the stage, a file that is not carries a ＋
that pulls its bytes through the owner-scoped read and adds them through
the ordinary upload + item.add — content crosses to the shared surface only
by that explicit act.

Workbench follow: Watch on an agent's row and the stage tracks what their
locus names — with `replace` navigation so Back stays yours, any click of
your own clearing it (`goStage`, one spelling), and Esc stopping the watch
before it pops a level. And `isocan present <item> [--say]` is the
"attention" verb the design refused to make a channel: a main-thread
comment carrying the workbench address — durable, attributed, it wakes the
room, and the record answers "why was everyone looking at that".

Custom views stay gated, deliberately: no view HTML executes before the
content origin and extension actors exist. The registration vocabulary
waits with them rather than shipping tabs that cannot render.

Verified live end to end: the stitch repo's tree listed with dotfiles
absent, a ＋ added agent-1.html as a real attributed item (bytes read back
by `isocan get`), Watch chased a working agent across two items, Esc
stopped the watch first, and `present` landed its address on the main
thread as a clickable link.

## Edit text in place — the WYSIWYG V0, plus the room learns manners

The research doc's recommendation shipped its first stage the same day:
"Edit text" on the stage's saved preview renders the artifact in the frozen
frame the doc measured (same-origin, scripts dead, srcdoc), double-click
makes one text node editable, and Save applies the unique-match rule —
verbatim and exactly once, or a refusal by name — landing as an ordinary
version. Proven live on a 477KB screen: the v6→v7 diff was one line. The
refusal fired honestly on its first real outing (`&` vs `&amp;`), and the
limitation showed its face: script-rendered screens freeze to a skeleton —
text living in JS needs the editor.

And four pieces of polish from watching the room get used: the roster and
files sections grew grab-edges (per-browser heights, clamped); the AGENTS
header and its fold share one line; a folded rail wears a chevron at its
foot as well as its label; and hovering any agent row — away rows included
— peeks a longer trail of what they did, floated clear of the scroll box
that clipped its first draft (the emoji picker's old wall; position:fixed
escapes it without a portal).

## The content origin gets its walk

The atlas mechanism that three projects now lean on — serve item content
from an origin that owns nothing — has an execution plan
(`docs/projects/atlas/content-origin-plan.md`), written under one constraint:
every stage ends stable on BOTH shapes. The seam is a role, not a listener
(local mounts it on a second loopback port; hosted, being one Cloud Run
`$PORT`, mounts it on a Host header for a second registrable domain), five
invariants each owed a guard test — unconfigured means today byte-for-byte,
the sandbox upgrade keyed to the split and never a flag, chrome reads badged
forever, the role answers blobs only, hosted frames frozen until read-auth
is answered — and four stages: the seam, the local half, the outbound-exfil
CSP decided on measurement, then the hosted half in dependency order
(domain, short-lived signed URLs resolving the collision with the 08-23
blob-route closure — expulsion reaches the bytes within one TTL, recorded
honestly — then the flip). The signed-URL design belongs with the door and
is pointed there, not improvised here.

## Content origin, stage 1: the seam, with nothing routed to it

The plan's first stage landed the same day it was written, and nothing a
user can see moved — which is the acceptance. `server/src/content.ts` is the
content role: one function registering exactly one route (the blob GET,
extracted verbatim from `http.ts`), its route table enumerated by a guard so
it can never quietly grow a second API. The app origin mounts it behind the
existing door hook; the 24-test blob suite passes untouched, which is
invariant 1's witness. `GET /api/serving` advertises the content base —
`null` everywhere today, and derived from a listener that actually exists,
never from configuration alone. On the web side the sketch got tighter in
the building: one URL spelling (`blobUrl`, badged, all chrome reads) plus
ONE frame builder (`itemFrame`) that decides src and sandbox together, so
"app-origin src + allow-same-origin" is unbuildable rather than avoided —
invariants 2 and 3 turned out to be the same seam. Stage 2 is the local
listener and the flip.
