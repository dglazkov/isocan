# 26 August 2026

## Trajectories: the history becomes readable, then legible

The [Headlong survey](../research/2026-08-24-headlong.md) found the gap in one
measurement: `compactOplog` writes every dropped entry to
`oplog-archive.jsonl`, and nothing in the product could read that file. isocan
was preserving its history into a record with no reader — "a delete with
better manners." Today the read half shipped, and with it the survey's other
trajectory idea.

**The archive opens.** `Store.readArchivedLog` is the read half of
`compactOplog`'s write half, implemented on both backings (a JSONL read on
disk, an object read in the bucket) and enforced by the storage-seam
conformance suite, so a third backing cannot ship the write without the read.
It surfaces as `GET /api/projects/:id/oplog/archive` and as
`isocan tail --archived` — the full history, live log and archive in one seq
order. With `--archived` and no `-n`, tail prints everything: the flag asks
for the whole past, and a default window of 10 would answer with none of it.

**`isocan recap` — the history at decaying resolution.** Headlong renders its
trajectory with recent entries verbatim and older ones progressively
summarized, the tiers acting as an index. isocan now does the same over the
record it already keeps: the last N ops verbatim, and behind them windows
that double in size with each step back, each summarized to one line — who,
how many ops, how much conversation, which items (titled from live state when
the item survives, from the ops themselves when it does not). Every window
carries its seq span, and `tail --archived` replays any of it at full
resolution. The tiering is pure math in `@isocan/core` (`buildRecap`), so the
CLI renders it today and any surface can render the same structure tomorrow.

The principle both changes serve is Headlong's, taken seriously rather than
quoted: *nothing is compacted away in place — compaction and introspection
operate on the same record.* `gc` already archived instead of deleting; now
the product can open what it kept.

Both surfaces, walked: no new `Operation` (these are reads), two CLI verbs
(`tail --archived`, `recap`), the agent guide teaches both (and the surface
test enforces it), the tiering lives in core, the README says so, and tests
land at every seam — recap tiering in core, the archive round-trip in the
store conformance suite (both backings), and the route in the gc suite. The
web app deliberately gets nothing today: recap is orientation for an agent
arriving by CLI; the web's activity list stays the human's reader until a
scene forces more.

## The workbench, V1: the agent room

The [workbench design](../projects/workbench/design.md) stopped being a
document. `W` (or `isocan open --workbench [item]`) flips the canvas to a
cover — FullScreen's exact architecture, so the socket, presence and viewport
survive the flip and Esc lands at the zoom you left — holding the agent
roster, the one main thread, and one artifact on a stage.

The build matched the design's headline finding: **zero new operations, zero
new protocol messages**, and `workbench.test.ts` keeps it that way — the
workbench's own code may not call `sendOp`, must render the thread through
`MainThreadBody` (the same component the canvas docks, grown a `docked` prop
so the permanently-open column marks messages read on engagement rather than
on flip), and must build every address from `address.ts`'s new
`workbenchPath` family. The stage extracted `ArtifactStage` out of FullScreen
so `/i/<item>` and `/w/<item>` render one item through one component — the
two-products tell, closed before it could open.

The roster is presence projected: one row per actor (the facepile's law, but
cli-primary rather than first-push-wins — `lib/roster.ts`), working rows
first, the status string VERBATIM with its quiet-age beside it. No PARKED
badge: that waits for `statusSource` to cross the wire, and string-matching
the wait copy into semantics is banned by name in the design. Expanding a row
shows the thread it is answering, a live thumbnail of its working locus
(click puts it on the stage), and `recentActivity`'s made/edited/said trail.

The lazy chunk came in at 4.5KB with the main bundle up ~1.4KB, and the
spacing guard earned its keep during the build: `padding: … 22px` was a
26th spacing step the scale had never had, and the fix (24px) turned out to
be the honest indent anyway — the dot, its gap, and the head's padding sum
to exactly 24.
