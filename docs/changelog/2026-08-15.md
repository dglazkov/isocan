# Day one: a canvas that already knows what it is

**2026-08-15** · 38 commits · 279 files · +18,619 · Dimitri Glazkov

The whole spine in a day: the monorepo, one reducer, a single-writer daemon, the CLI's full operation surface, and a web app in the Drafting Table design. By evening it had presence, comments, undo and garbage collection.

## The shape everything else rests on

- **One reducer, two clients.** Mutations are `Operation` values applied by the same pure function in the daemon and the browser — the isomorphism guarantee, present in the first commits rather than retrofitted.
- **Storage as an oplog plus blobs**, with a single writer serialising every mutation.
- **Actor-scoped undo**: your undo walks your stack, not everyone's.
- **Blob garbage collection** with a grace window, on the day blobs appeared.
- **Reject ops a build does not know**, instead of corrupting state — forward compatibility decided early.

## Presence, on the first day

- Live cursors, unified actor colours, sessions that survive an agent thinking, and a "working" activity with simulated cursor motion.
- Work shows on the item, not just the cursor.
- Comment pins show all of a thread's authors; a comment arriving says so.

## The agent side

- `isocan wait` and `isocan tail`: park on feedback, stream the oplog.
- @-mentions that a wait can filter on, so an agent wakes only when addressed.
- One thread is main: a docked chat the agent always hears.
- Agents name themselves after the canvas, not their vendor.
