# 4 October 2026 — Wait on the condition, not on a count of ticks

Main went red in release run `37179059320` on one test, and not the one the
run was named for (`d48a494`). `chat-reparse`'s setup waited twenty 5 ms ticks
for the Chat's lazily loaded markdown chunk, then asserted every message had
been parsed. On a loaded CI runner the import took longer than 100 ms, so the
test began at zero parses — "expected 0 to be greater than or equal to 12".
The messages were already on screen as plain text, so the content check had
passed first and hidden it. Builders had seen the same flake under load on 2
Oct; the commit the red run carried, the fake keys, had nothing to do with it.

The setup now waits on the condition itself, with a 10 s deadline inside the
hook's 30 s limit. Reproducing it took some care: saturating every core on a
Mac did not make it fail, but a 400 ms delay injected into the chunk's import
did, exactly — the old wait fails under it and the new one passes. Lesson 108
names the shape: wait on the condition, never on a count of ticks. Proved by
`npm run test:deep` (the decisions suite failed until the lesson count was
regenerated), typecheck, and `chat-reparse` three times alone, three times
with every core busy, and the slow-chunk reproduction both ways.

Loop findings (`3d4a435`) and the practice page (`645a3e0`).
