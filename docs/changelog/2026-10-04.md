### test(web): chat-reparse waits on the parses, not on 100 ms of ticks

`d48a494`

Main went red in release run 37179059320 (4 Oct) on one test:
chat-reparse's setup waited twenty 5 ms ticks for the Chat's lazy
markdown chunk, then asserted every message had been parsed. A loaded
CI runner took longer than 100 ms to import the chunk, so the test began
at 0 parses ("expected 0 to be greater than or equal to 12"). The
messages were already on screen as plain text, so the content check
passed first. Builders saw the same flake under load on 2 Oct. The
commit the run was named for (fake keys) had nothing to do with it.

The setup now waits on the condition with a 10 s deadline, inside the
30 s hook limit. Saturating every core did not reproduce the failure on
a Mac; a 400 ms delay injected into the chunk's import did, exactly, and
with it the old wait fails and the new one passes. Lesson 108 records
the shape: wait on the condition, never on a count of ticks.

Proof: npm run test:deep (decisions failed until the lesson count was
regenerated, then passes); typecheck; chat-reparse 3/3 alone, 3/3 with
every core busy, and the slow-chunk reproduction both ways.
