### Voice: the meters were never drawn, and the glow ran at 45% (#337)

`c8c8026`

Dion, using it for real: "the voice effect is really subtle. I really
kinda want it to bump around more... I thought I would see it moving in
real time to the left of the voice picker."

**The meters were not subtle, they were invisible.** `.talk-meter`'s
rules lived inside the config dialog's own `<style>` block, so in the
composer the bars were unstyled spans with no width or height. The level
was arriving and being painted onto nothing. They are one shared
constant now, interpolated by both surfaces.

That is the THIRD rule today scoped to a component that was not the one
rendering it — the key panel's, the bar's, and now the meter's. A
stylesheet a component owns is only present while that component is, and
this module keeps its CSS in JSX.

**The glow ran at 45% size.** `type="pill"` carries `scale: 0.45`, and
pill was right when the wrapped thing was a 294x32 bar. The transcript
made the block tall, so it is `default` now — a chat input or card,
which is what this became. Rise and spread up, resting presence DOWN:
what reads as movement is the contrast between quiet and loud, and a
glow that idles bright has nowhere to go when a voice arrives.

**The mic icon sat right of centre**, which Dion could see and I could
not until I measured it: 7px left, 3px right. A rule further up gives
panel buttons `padding: 1px 6px`, leaving a 16px content box for an 18px
glyph — it overflows and grid centring resolves that to one side. Zero
padding, and now 5px on every side. The selector is tag-qualified so it
also survives `.phone-face button`, which forces a 44px touch target and
a 10px radius: the target is right to enforce and the shape should still
be a circle.

**And the modifier key.** `⌘` was spelled into seventy-odd labels, every
one of them wrong on Windows and Linux — "Send (⌘⏎)", "Undo (⌘Z)",
"⌘Z still undoes". The behaviour never was: the handlers take `metaKey
|| ctrlKey` and always did. `shortcut()` in core, because a module may
import nothing else, and it joins the way each platform joins rather
than translating a word into the other's shape — `⇧⌘Z` against
`Ctrl+Shift+Z`, not `Ctrl+⇧Z`. With no navigator it says Ctrl rather
than claiming a Mac it cannot see.

One capability gate quoted `title="Undo (⌘Z)"` to anchor a claim about
`canEdit`. The anchor now stops before the label: a capability check
should not fail the day a tooltip learns to say Ctrl.

### Voice has one door, and it is the composer (#337)

captions colliding with it: "this talk button just hanging out is

The composer has the transcript, the names, the voice picker and a full

**The rail was the other candidate and is not open to a module.** The
rail and the dock keep FIXED lists precisely so two modules cannot fight

wants horizontal room for a transcript and a glow, and a rail is a
narrow vertical strip.

Nothing became unreachable. ⌘K's "Configure voice" carries its own test
listen for when the Chat is closed.

the mic was 32 — so it bottom-aligned and stood 4px proud, which is what
looked crooked. Now 28 and round; both read top 709, bottom 737. Round
rather than a rounded square because the mic starts a MODE and the

### Voice: the conversation has a record, a voice, and somewhere to land (#337)

`5597669`

Three asks in one pass, and the first finding is that the history was
never missing. The session has kept forty turns since it was written —
partials collapsing per speaker, so "read", "read the", "read the
canvas" is one line rather than three. Two of them were shown, as
floating fragments with no name on them. The UI was throwing away the
thing it had.

**The record.** A transcript above the bar: a name column, oldest at the
top, newest pinned to the bottom, capped and scrolled so a long
conversation cannot eat the thread above it, with Expand for when it
should. A run by one speaker drops the repeated name, so a
back-and-forth reads as a conversation rather than a form. First names
in the column and the whole name to a screen reader — "Glow Tester"
clipped to "Glow T…" on every second row, and a column of ellipses says
less than a column of first names.

**Somewhere to land.** Dion asked for the session in the Chat rather
than behind a Save button, which is the better idea and answers the
objection to posting at all: one block per SESSION is not a monologue of
partials. It goes through the module's own `say` tool — that path
already births the main thread, mints the id and rides `host.send` — so
it is an ordinary `thread.reply`, one undo, with the speaker's name on
it. Markdown carries the styling: a comment renderer of its own would
need a typed marker on `Comment`, and those are writer-owned by design.
The Chat reaches every collaborator, so the transcript says where it is
going WHILE you talk rather than after.

**A voice.** The thirty prebuilt names, read from Google's reference
rather than invented — Autonoe, the one in Dion's screenshot, is among
them. Changing one RECONNECTS: `speechConfig` is a setup-time field and
the Live API documents no way to change it on a running socket, so a
picker that appeared to switch mid-sentence would be lying. The
transcript is React state and survives the round trip, so the
conversation reads as continuous even though the socket is not.

**There is deliberately no accent control.** The docs are explicit that
these models detect the input language automatically across ninety-odd
languages — speak French, get French. A dropdown that looked like it set
an accent and did nothing would be worse than its absence.

Still nobody has spoken to it: the level, the glow and the reconnect are
all unproven with real audio.

### The rival-skill guard asks git, not the disk (#44)

`e1f901e`

`test/skills.test.ts` was red on this machine and green in CI, every
run, for a day. The cause is legitimate: another maintainer's sync drops
an untracked copy of `conduct` into `.agents/skills/` every few hours,
and the guard read the FILESYSTEM — so a twin appearing there made the
tracked `.claude` copy look like the rival it is not.

What the rule is actually about is what the REPOSITORY holds. A checkout
is not only the project's files; a person's machine syncs things into
it, and something a sync left in a working tree is not a second original
the project ships. So the lookup is `git ls-files`.

It loses nothing. `ls-files` reports the index as well as HEAD, so a
real duplicate is caught the moment somebody `git add`s it — before the
commit, which is the moment that matters. Verified by staging the stray
and watching the guard fire, then unstaging it. A checkout with no git
falls back to the disk, so it never quietly weakens into nothing.

The new failure mode that introduces is `ls-files` returning EMPTY — a
wrong cwd, a detached worktree — which would make every file look
untracked and the guard pass for exactly the reason it should fail. So a
second test asserts the lookup can see the two files it reasons about.

A guard that is permanently red where the work happens is a guard people
stop reading, which is worse than the fork it watches for.

Both execs carry a deadline, which `syncexec.test.ts` caught me
forgetting.

### Voice: the glow rises with your voice (#337)

`3af23f4`

Dion asked for the effect at libraries.dev/voice: "a colorful glow that
rises with your voice from the bottom of a chat input, then sweeps side
to side while the reply is thought through." Their preview is a chat
composer with a mic, which is the thing we built yesterday.

It is `voice-glow`, MIT, by Jakub Antalik. **No runtime dependencies**,
React as a peer, and three of its props are state we already hold:
`level`, `theme`, and `processing` — the travelling beam, which is
exactly "while the reply is thought through".

**It costs a first visit 22 bytes.** Measured, because a 95KB dependency
is the shape a bundler most wants to hoist: the glow lives entirely in
the talk module's lazy chunk and the entry chunk carries none of it.
`moduleapi.test.ts` now reads the built entry for it, beside the sticker
and anatomy guards that exist because that check was got wrong before.

The level is a GETTER, not a number. The package samples it once per
frame, so the glow is smooth without re-rendering the composer sixty
times a second — the mistake its own docs warn about. It taps the meters
the bar already paints, and takes whichever of you is louder, so the
glow belongs to the conversation rather than to the microphone.

`theme` moves onto `ComposerFacts` rather than being sniffed from
`prefers-color-scheme`. isocan's theme is a CHOICE; a canvas whose owner
picked Light under a dark system would otherwise get a control that
disagreed with everything around it. Same reason `groupMode` is there: a
module cannot read the shell's stores without becoming unremovable.

Three things found by looking at it rather than by reading it. The
stylesheet lived inside the idle branch, so none of the bar's CSS
rendered once a session started — hoisted to one constant both states
carry. The beam's own wrapper did not take the row, so a 294px composer
drew a 32px glow. And `type` is `pill`, not `default`: the presets are
about SHAPE, default is tuned for a ~350px chat input, and at this bar's
294x32 it drew a wash too faint to read.

**Also fixes 2KB I shipped yesterday.** The composer slot's renderer was
a plain import, so every first visit paid for a slot that is empty
unless an experiment is on — 753,083 with it, 751,071 lazily. The entry
was already 750,401 before any of this, so 3,401 of the overshoot past
the 747,000 agreed on 20 Sep arrived with that day's landing, not here.

Nobody has spoken to it yet; the glow with real audio is still
[the walk](docs/verify/2026-09-20-talk-on-canvas.md).

### Voice: a mic in the Chat composer that flips it (#337)

`12a3dd0`

Dion asked for the pattern every voice product has trained people to
expect, with a reference: a mic among the composer's own buttons, and
pressing it turns the message box into a live conversation with a
waveform. He had asked for exactly this the first time — "turns the chat
box into a voice UI" — and I answered a different question about a
floating button.

**The slot.** An overlay names an EDGE and may never cover the middle,
which is the right rule and is why voice had nowhere to go: a mic in the
composer is neither. So `composer`, proposed: a module contributes ONE
control, drawn beside Send, and asks for the row with `takeOver(true)`
when it wants to stand where the message box is. The shell keeps owning
the row — a module reports, it does not seize — and drops a takeover
when the module goes, because an experiment switched off mid-session
would otherwise leave a composer nobody can type in and no control left
to give it back.

**Three things only looking at it could have found.**

The control must have ONE render site. Drawn in two — an idle row and a
taken-over row — React unmounts and remounts it on takeover, which drops
its state and flips it straight back; the shell hides its own parts
instead.

The key panel could not be a popover. At 300px inside a 250px Chat panel
it clipped whichever edge it was anchored to, and `position: fixed` does
not even reach the corner it names because the panel's transform is the
containing block. So configuring flips the row too: one mechanism for
both states rather than a bar and a pop with separate bugs.

And the panel is now one component shared by both doors rather than a
second copy — the floating mic keeps its pinned placement through a
prop.

The floating mic stays: it works with the Chat closed, which this
cannot. Both doors share one `useTalkSession`, so they are two ways into
one conversation rather than two conversations.

The experiment is renamed **Voice**, and says what it still cannot do:
undo is not carried on this surface.

Walked on a real build — the mic renders beside Send, pressing it flips
the composer to the key panel full-width with nothing clipped, and
closing gives the row back. Everything past the key is
[the walk](docs/verify/2026-09-20-talk-on-canvas.md), unchanged: nobody
has spoken to it.
