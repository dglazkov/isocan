# 21 September 2026 — Voice moves into the composer

A day of Dion using the voice module for real and saying what was wrong
with it, and of the fixes being measured rather than nudged. Through all of
it, nobody has yet spoken to it: the level, the glow and the reconnect are
unproven with real audio, and say so.

## A walk first (#337)

The in-canvas voice UI was news to Dion, which was itself the finding: the
more discoverable of the two voice surfaces was the one nobody had written
down. [The walk](../verify/2026-09-20-talk-on-canvas.md) was walked on a
real build before it was written, and three steps were not what the
source implied — a fresh browser meets the identity door first, the mic
does not exist until the `modules.talk` experiment is ticked, and the ⌘K
route is under "Configure voice", so searching for "talk" finds nothing.
Each would have been a wrong instruction written from the code. The page
says plainly that everything past the key panel has never been tried.

## The mic belongs in the Chat composer (#337)

Dion had asked for this the first time — "turns the chat box into a voice
UI" — and got a floating button instead. So the shell gains a `composer`
slot: a module contributes one control beside Send and asks for the row
with `takeOver(true)`. The shell keeps owning the row and drops a takeover
when the module goes, so an experiment switched off mid-session cannot
leave a composer nobody can type in. The control has one render site,
because drawn in two React remounts it on takeover and it flips straight
back.

Then, through the day:

- **The glow.** Jakub Antalik's `voice-glow` (MIT, no runtime
  dependencies) rises with whichever of you is louder and sweeps while the
  reply is thought through. It lives entirely in the talk module's lazy
  chunk — 22 bytes of the entry, and `moduleapi.test.ts` reads the built
  entry to keep it that way. `theme` comes from the shell, not
  `prefers-color-scheme`, because isocan's theme is a choice. The same
  commit made the composer slot's renderer lazy, 2 KB every first visit had
  been paying for an empty slot.
- **A record, a voice, somewhere to land.** The session had kept forty
  turns all along and the UI showed two unattributed fragments. There is a
  transcript above the bar now, with names, and the session posts to the
  Chat as one ordinary `thread.reply` per session. The thirty prebuilt
  voices are read from Google's reference; changing one reconnects, because
  the Live API cannot change it on a running socket and a picker that
  pretended to would be lying. There is no accent control: the model follows
  the language you speak, and a dropdown that did nothing would be worse
  than none.
- **One door.** The floating mic was deleted rather than moved — two doors
  into one conversation had already drifted — and the rail is not a
  module's to claim. The mic is now 28px and round beside the 28px square
  Send: round because it starts a mode, and two squares read as two submits.
- **The meters were never drawn, and the glow ran at 45%.** The meter CSS
  lived in the config dialog's own stylesheet, so in the composer the bars
  were unstyled spans — the third rule that day scoped to a component that
  was not the one rendering it. The `pill` preset scales the glow to 0.45;
  with a transcript the block is tall, so `default`. The mic sat 7px left,
  3px right, from padding that left a 16px box for an 18px glyph.
- **`⌘` was spelled into seventy-odd labels**, wrong on Windows and Linux,
  though the handlers always took `metaKey || ctrlKey`. `shortcut()` in
  core joins keys the way each platform does — `⇧⌘Z` against
  `Ctrl+Shift+Z` — and says Ctrl when it cannot see a Mac.

## The rival-skill guard asks git (#44)

`test/skills.test.ts` was red on this machine and green in CI for a day:
another maintainer's sync drops an untracked copy of `conduct` into
`.agents/skills/`, and the guard read the disk. The rule is about what the
repository holds, so it reads `git ls-files` — which includes the index, so
a real duplicate is still caught the moment it is staged. A second test
asserts the lookup can see the files it reasons about, since an empty
answer would pass the guard for exactly the reason it should fail. A guard
that is always red where the work happens is a guard people stop reading.

Also: 13 review rows answered with the decisions of 20 Sep, applied rather

with no comment. Grades and a persona run as usual.
