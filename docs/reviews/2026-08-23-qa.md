# QA — 2026-08-23

Baseline run. First pass by this persona, so everything below is a first
measurement rather than a comparison.

**Suite at the start:** 759 passed | 45 skipped across 87 files, `npm test`
green, `npm run typecheck` green.
**Suite at the end:** `npm test` → **779 passed | 45 skipped across 89 files**,
green on 3 consecutive runs; `npm run typecheck` green. 15 of the new tests and
1 of the new files are this persona's; the rest is
`packages/web/test/accent.test.ts` from the design audit in the same session.

## Verdict

**The suite is real, and unusually so.** 63 mutations were applied to the code
the tests claim to protect — the reducer, the op vocabulary, the inverses, the
per-actor undo stacks, the engine's repair-and-skip policy, and the three
guards named in `lessons.md`. **60 were killed.** Of the three survivors, one
was a genuine hole (fixed below), and two are equivalent mutants — changes that
produce the same observable behaviour by a different route, which no test can
or should catch.

That is a very high mutation score for a hand-written suite, and it is worth
saying where the credit lies: the round-trip and random-walk property tests in
`packages/core/test/` kill most of the inverse mutations on their own, and
`daemon.test.ts`'s actor-scoped undo cases kill every stack mutation that does
not hang.

Three real problems were found anyway, and one of them is in `main` right now.

## 1. `main` is red: a reducer invariant was committed away mid-run

`110027d` ("The personas get the fields the real ones use") carries a two-line
change to `packages/core/src/reducer.ts` that has nothing to do with its
message. `item.add` lost its trash check:

```
-      if (canvas.items[op.itemId] || canvas.trash.some((t) => t.item.id === op.itemId)) {
+      if (canvas.items[op.itemId]) {
```

An item id that is sitting in the trash became reusable, so `item.add` with a
trashed id would put a second item under an id the trash still holds — and
`item.restore` would then collide with it. `packages/core/test/reducer.test.ts`
catches this ("rejects duplicate ids", the `itm_trashed` case), which means
**the commit is red as it stands.**

It was this persona's own mutation harness that produced the bad line: the
mutation was live on disk for ~20 seconds while a scoped vitest ran, and a
concurrent agent committed the whole working tree in that window. The fix is
restored in the working tree (uncommitted, so it is visible in `git diff`).
Two follow-ons:

- **Verify `110027d` before building on it.** `git show 110027d -- packages/core/src/reducer.ts` is the whole of it.
- **Mutation testing now runs in a `git worktree`** (see the lesson below), which is where the rest of this review's mutations ran.

## 2. Lesson #2's guard was a test that could not fail

`packages/web/test/presence.test.ts` had a `describe("who is working here")`
block guarding the "null is working" bug. It defined its own `nameOf`:

```ts
const nameOf = (label, actor, names) => label ?? (names[actor.id] ?? actor.name);
```

…and then asserted four things about it. Nothing in the block imported
anything from the app. The rule it was guarding lived inline in a zustand
selector in `ItemView.tsx`, and could be deleted entirely with all four
assertions green.

**Proved, not assumed:** the original bug was reintroduced —
`return \`${session.label}\`` — and the original test file passed, 10/10.

The local copy had also already drifted from the app: `names[id] ?? actor.name`
returns a blank registry name where the app's `actorNameIn` falls through to the
stamped one.

**Fixed** by giving the rule somewhere to live and pointing the test at it:

- `packages/web/src/lib/names.ts` gains `sessionName(names, session)`, documented with the bug it exists for. A blank label is treated as no label, matching `actorNameIn`'s treatment of a blank registry name.
- `packages/web/src/components/ItemView.tsx:559` calls it instead of re-typing the rule.
- The test now imports it. Five mutations, **5 killed**: the literal `${session.label}` bug, falling back to the stamped name instead of the registry, a blank label winning, an explicit label losing, and a blank registry name rendering as an empty chip.

**Not fixed, and worth an architect's eye:** seven other call sites still write
`session.label ?? session.actor.name` by hand — `CursorLayer.tsx:173`,
`Minimap.tsx:142`, `Presence.tsx:82`, `CommandBar.tsx:88`, `OnIt.tsx:75`,
`lib/mentions.ts:50`, `pages/CanvasPage.tsx:71`. All seven use the **stamped**
name, so `lessons.md`'s "a stamped name is a log entry, not an identity" is
live in seven places: rename yourself and your cursor keeps the old name. Six
of them are one-line swaps to `sessionName`; this pass did not make them
because none can be verified without driving a browser.

## 3. The reducer's stated contract was believed, not checked

The one genuine survivor out of 63. The reducer's own docstring says *"Every
mutation stamps `updatedAt`/`updatedBy` from the envelope."* Deleting `...stamp`
from `item.move` left the whole suite green.

Nothing was checking it. The single stamp assertion in `reducer.test.ts`
covered `item.addVersion` only, and the round-trip and random-walk property
tests are blind here **on purpose** — `helpers.ts`'s `normalize()` strips
`updatedAt`/`updatedBy`/`deletedAt`/`deletedBy` so undo comparisons can ignore
them. That is the right call for those tests and it is exactly why the stamp
needed a test of its own.

It matters because `updatedBy` is what the item titlebar shows as "last edit
by", and `updatedAt` feeds the activity and elapsed displays.

**Fixed:** two tests in `packages/core/test/reducer.test.ts` state the rule over
the whole vocabulary rather than over the op that happened to break — nine
item-touching ops plus `project.update` and both delete forms' `deletedBy`.
**13 mutations, 13 killed**: the stamp dropped from `item.move`, `item.resize`,
`items.move`, `item.update`, `item.addVersion`, `item.setCurrentVersion`,
`item.removeVersion`, `item.add`, `project.update`; the stamp carrying the wrong
actor; the stamp carrying wall-clock instead of the envelope's `ts`; and both
delete forms crediting the item's author instead of the deleter.

## What survived mutation and should not have (the residual gap)

**`oneblock.test.ts` covers only classes that already have a canonical block.**
`"declares each class once, unscoped"` fires when a dropped scope leaves a
*second* bare rule. Drop the scope from a class that has only ever appeared
scoped and the leftover is the *first* bare rule for it — count 1, green.

Measured: **229 classes in `styles.css` have a bare block; 57 appear only as
the tail of a scoped selector.** Two mutations on that set survived the whole
suite:

```
.projects-head .who-btn {   →   .who-btn {
.toolbar .conn { … }        →   .conn { …; opacity: 0.3 }
```

The second is lesson #1's exact symptom — a thing dimmed app-wide — with the
build green.

**Partly closed.** A derived invariant that does hold: a class chained onto
another class (`.face.away`) is a *modifier*, and a modifier is meaningless
alone, so it must never have a bare rule. 41 such classes in the file today,
**zero** with a bare rule. Added as `describe("state classes")` in
`oneblock.test.ts`; five mutations, four kills (`.away`, `.active`, `.selected`
and `.live` stranded bare) and one deliberate negative control (an unrelated
new bare class) correctly ignored.

That still leaves descendant tails like `.who-btn` uncovered, and I did not
force a guard for them. The two candidates both fail on their own terms: *"a
bare rule must be the first appearance of its class"* is violated 10 times in
the file today by legitimate code, and pinning the count of bare selectors is a
snapshot, which `lessons.md` is right to call a wish rather than a guard.

## The other survivors were equivalent mutants

Named so the next run does not re-investigate them:

- `repairInverse`'s `if (moves.length === 0) return null` removed — the empty batch reaches the reducer, which throws `bad-op` ("batch op requires at least one item"), is caught as an `OpValidationError`, and the candidate is discarded on the same path. Same outcome.
- `repairInverse(...) ?? target.inverse!` in `Engine.undo` — the unusable inverse throws `OpValidationError` on apply and is skipped identically.

## One mutation did not fail the suite — it HUNG it

Making `UndoStacks.discardUndoTarget` a no-op does not turn a test red. It
wedges `Engine.undo`'s `for (;;)` (engine.ts:586–604), which sits inside the
single-writer promise chain, so the daemon stops answering anything and the run
never finishes. The harness killed it after 15 minutes with nothing to show.

A hang is a worse signal than a failure — nobody can tell it from a slow
machine — and the loop has no iteration bound; `discardUndoTarget` is the only
thing that makes it terminate. Two responses:

- **Added `packages/server/test/undo-stacks.test.ts`** (8 tests, ~3ms) to assert the stack contract directly instead of only through HTTP, including that discarding never hands the same seq back twice. **10 mutations, 10 killed** — the no-op discard now fails in milliseconds with the reason, instead of hanging.
- **For the architect:** a bound on that loop (or a `seen` set) would turn a future wedge into a 409. Not changed here; engine control flow is not a QA edit.

## New tests for the edges nobody was standing on

All in `packages/server/test/daemon.test.ts`, all proved by a mutation targeted
at that test alone:

| Test | Catches (proved) |
| --- | --- |
| two actors writing at once get one order, and two separate stacks | 20 ops fired concurrently, 10 each. Killed by making `Engine.enqueue` non-serializing, and by making the undo stacks global. Every prior actor-interleaving test wrote one op at a time. |
| undoing a multi-item delete restores only the members still in the trash | Alice deletes three, Bob restores one and moves it. Killed by removing `repairInverse`'s `items.restore` case. The negative half is the point: Bob's move must survive her undo. |
| a batch undo whose every member is gone is skipped, not half-applied | Killed by letting `item.delete` tolerate a missing item, which turns a dead undo into a silent success. |
| a hundred-item move is one op and one undo step | Killed by shrinking the `items.move` inverse to its first member. |

### And one flake this pass introduced, then found

The scale test above started at **200** items on vitest's default 5s timeout.
Alone it took 4.3s. In a full run, sharing the machine with fifteen other files
spawning daemons, it took longer than 5s and failed **3 of 3** times — a
textbook new flake, caught only because the run was repeated afterwards rather
than declared green once.

Now 100 items with an explicit `{ timeout: 30_000 }` and a comment saying why.
1.8s alone, and **3 of 3** clean full runs after the change.

## The 45 skipped tests — all accounted for, and correctly so

Every one is a cloud suite, gated on a Firestore emulator, and the gate is
better designed than most:

| File | Skipped |
| --- | --- |
| `packages/cloudstore/test/cloud-store.test.ts` | 26 |
| `packages/cloudstore/test/cloud-desk.test.ts` | 9 |
| `packages/cloudstore/test/fencing.test.ts` | 5 |
| `packages/cloudstore/test/daemon-composition.test.ts` | 3 |
| `packages/cloudstore/test/cloud-desk-arrays.test.ts` | 2 |

Nothing is skipped for being broken, obsolete or slow, and no `it.skip` exists
anywhere else in the repo. `bind.test.ts`'s two `skipIf(!hasIpv6Loopback)` cases
ran here (this machine has one).

The important part is that a skip cannot become a silent pass on the branch
people install from. `test/emulator.ts` starts an emulator when it can; when it
cannot, every case registers as skipped **with the reason in the describe
title**, and `ISOCAN_REQUIRE_EMULATOR=1` — which `.github/workflows/release.yml`
sets, alongside pinning Temurin 21 and installing the emulator component —
turns the skip into a failure.

Verified rather than read: `ISOCAN_REQUIRE_EMULATOR=1 npx vitest run
packages/cloudstore` fails 5 files with *"the Firestore emulator is REQUIRED
here and is not available"*. This machine has no `gcloud` and no JRE, so the 45
could not be run locally; the CI switch is what stands behind them.

**This is the model the rest of the repo should copy.** A conditional skip that
names its reason in the test title and fails loudly in CI is not a hole.

## `daemon-takeover.test.ts` — the flake, diagnosed and hardened

Reported as: times out under load, fights for a port, passes alone.

**It did not reproduce.** 8 full `npm test` runs, all green. Then the file alone
under 40 spinning node processes on a 14-core machine: 8/8 passed, slowest test
3.5s against a 10s poll deadline and a 30s test timeout. Alone it is 7.5s
end to end.

**The port hypothesis is measurably wrong.** `freePort()` (bind :0, read, close,
hand out) is a genuine TOCTOU, but the kernel hands ephemeral ports out from one
rotating counter: **13 processes taking 300 ports each, as fast as they could,
produced 0 cross-process duplicates in 3,900 allocations.**

The leading hypothesis is now something this session demonstrated first-hand:
**four personas ran the full suite concurrently in one checkout, and one of them
(this one) was rewriting source files mid-run.** The architect's review records
`npm test` failing "a different test in 2 of 3 runs" in the same window. A
different test each time is the signature of a shared checkout, not of a port.

Three changes, none of which weakens an assertion:

1. **`test/ports.ts`** — a shared `reservePort()`. Each vitest worker gets its own slice of 20000–32000, below the ephemeral floor on Linux (32768) as well as macOS (49152), and each port is bind-tested before use. Two workers now *cannot* be handed the same number. `daemon-takeover.test.ts` and `restart.test.ts` had identical copies of `freePort`; both now use it. Written with the measurement above in its comment, so nobody re-derives it.
2. **The squatter's stderr is captured.** It was `stdio: "ignore"`, which is why a startup failure and a slow machine produced the identical message.
3. **Failures now name the cause.** `timed out waiting for the squatting daemon` became:

```
gave up after 56ms waiting for the squatting daemon
  last probe: nothing answered on 20000 (TypeError: fetch failed)
  squatter:   pid 62975 already exited (code 3, signal null) — stderr: boom
```

`until` reports elapsed time, what the last probe saw, and whether the process
is alive; a squatter that has already exited fails immediately instead of
polling a corpse for ten seconds (56ms above, not 10,047ms). `startSquatter`
also asserts that the pid answering the port is the one it spawned — so a
stolen port fails *there*, instead of `afterEach` killing a stranger's daemon
and failing an unrelated file.

All three were demonstrated by deliberately breaking the spawn and reading the
output, not by reasoning about it.

## What is good, specifically

- **`packages/core/test/randomwalk.test.ts` and `roundtrip.test.ts` carry the inverse layer.** 16 mutations across `invert.ts` and the engine's redo/repair policy, 16 killed, including several no example-based test would have thought to write (a `thread.setAnchor` inverse that restores the anchor but not the old coordinates; an `items.move` inverse capturing the new positions).
- **`daemon.test.ts`'s actor-scoped undo cases are the best tests in the repo.** Making the stacks global, reversing either stack's order, letting an undo skip its pop, or dropping the badge→actor check on undo — all killed.
- **The reducer's validation is airtight.** 16 of 17 mutations killed, including every atomicity case (a batch that applies before validating, a batch accepting duplicate ids, `items.restore` not verifying every id).
- **Lesson #3's guard is now genuinely invariant-shaped.** Five mutations on `marketing/style.css`, all killed — including the `max-width` variation that walked past its first version, and `height: auto` hidden inside a media query.
- **The skip design (above) is exemplary and should be the pattern for any future conditional suite.**

## Gaps not filled, and why

- **Nothing drives a browser.** No test in the repo does, and `lessons.md`'s standing rule is that browser-only interaction is proven by driving a browser or not claimed. The suite currently obeys the second half — `keys.test.ts`, `shortcuts.test.ts`, `pensession.test.ts` and friends test pure logic and do not pretend otherwise, which is honest. But the seven un-migrated `session.label ??` call sites above are exactly the class of bug that only a driven browser catches, and there is no way to close them from here.
- **The 45 cloud tests could not be executed** — no `gcloud`, no JRE 21 on this machine. The gate was verified instead.
- **Scale beyond 200 items.** The 100-item batch test already costs seconds; 1,000 would cost a minute under load and prove the same property.
- **The descendant-tail half of lesson #1** — see the residual gap above.
