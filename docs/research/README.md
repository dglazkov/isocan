# Research

Findings that took longer to reach than they take to read — surveys, format
evaluations, and readiness assessments. Each one is a markdown file here (the
durable, greppable copy) and a designed write-up behind a link (the version to
send someone).

The rule for this directory: **write down what was measured, not what was
assumed.** Every number in here came from an API, a converter, or a test run on
the day it is dated. Where something is inference rather than evidence, it says
so.

| 26 Aug 2026 | [WYSIWYG on the stage](2026-08-26-wysiwyg.md) | How to edit a screen's text and properties without opening its source — and the finding that no off-the-shelf comparison covers: **the sandbox physics decide, and they were measured here**. Today's `allow-scripts` frame is unreachable from outside (no visual editing, period); `allow-same-origin` alone reaches the DOM with page scripts DEAD — the safe edit mode before the content origin lands — and whole-DOM serialization normalizes (doctype dropped, head injected), which is the fidelity problem. The field: GrapesJS (BSD-3, healthy, **~500KB gzipped** — and its own docs say unregistered elements round-trip as generic divs: it edits documents born inside it), Puck/Craft (a page IS their JSON — cannot ingest arbitrary HTML), Onlook (the right idea — visual edits landing as source patches — welded to React+Next+Tailwind in a CodeSandbox container), TipTap/Lexical/ProseMirror (own a document model; right layer for a future markdown lens, wrong species for screens). Recommendation: the native path — edit the rendered DOM in the measured no-scripts frame, double-click a text node, patch the SOURCE at parse5 `sourceCodeLocation` byte offsets so the file survives byte-for-byte except the edit, save as ordinary `item.addVersion`. Zero new ops; the cost is a parser, not a platform. One server wrinkle read on the way: the blob route's response-header CSP forces its own sandbox, so edit mode must render fetched text via srcdoc — the draft preview's existing path. |
| 25 Aug 2026 | [Retiring a name](2026-08-25-retiring-a-name.md) | Who may retire an actor, and how that stops being a way to take somebody's name. Measured on this three-day-old home: **87 badges, 0 killed, 64 claim rows, 42 of the 216-name roster consumed** — full in about **fifteen days** at 14 names/day, after which every agent is "Isaac 2". The number that says what those names are: **29 of the 44 name-holding actors have never written a single canvas op**. One worry is already answered by the architecture — a name is held by a CLAIM ROW, which is desk state and never replays, while `bindName` rebuilds the public registry from the name stamped on each envelope, so **retiring cannot change how any historical op renders**. The hard part survives: copying the `killBadge` precedent ("a badge that shares an identity with yours — the stolen-laptop gesture and not a way to expel other people") gives a rule that is safe and cleans up 15 of 44; widening it to the canvas scope cleans up everything and IS the impersonation vector. **A manual verb can be safe or useful, not both.** So the recommendation is neither: `CLAIM_STANDS_MS` already exists as "how long a claim stands as proof its owner is alive", `reincarnate` already trusts it for `as` — which is strictly more dangerous than name reuse — and `allocateName` is the one place that never asks. Staleness adds no authority, cannot be forged, and needs no verb. Caveat measured: **all 64 claims here are already past the 30-minute horizon**, so the rule must be stale AND not live, and 30 minutes is likely the wrong number for this purpose. |

| 24 Aug 2026 | [Live mode: voice](2026-08-24-voice.md) · [full](https://claude.ai/code/artifact/2121fde2-7a38-42e1-8129-1aea8f722e5e) | Voice through Google's Live API is a new input surface for the 28 operations that already exist, not a new vocabulary — and the API's one real limitation draws that line for us. **Function calling is synchronous** ("the model will not start responding until you've sent the tool response"), so a voice tool may only be something that finishes inside a turn. That rules out "build me a screen" as a tool call, which is correct: slow work is not a tool call, it is a **comment on the main thread**, which already wakes every agent parked on `wait`. All but the two content-carrying ops are fast enough to be voice tools — including `item.setCurrentVersion`, the convergence op the night-shift research found unused at 9 fan-outs to 2 choices, and which *"keep the second one"* makes a one-second gesture. And the canvas solves voice's hardest problem for free — **deixis**: `PresenceSession.selection` is already on the wire, so the daemon knows what "this" is before the sentence ends. Wire facts (16 kHz in / 24 kHz out, 15-min sessions, ~10-min connections, `interrupted`, both-side transcription flags) are second-hand: Google's own doc hosts fail certificate verification from here. |
| 24 Aug 2026 | [The night shift](2026-08-24-the-night-shift.md) · [full](https://claude.ai/code/artifact/81cda096-b7b9-4526-acb4-cf10010bb0ab) | An off-hours self-improvement loop is worth building, and the measurement that decides its design reverses what the [evals plan](../projects/evals/plan.md) concluded a day earlier.
