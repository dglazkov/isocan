# Research

Findings that took longer to reach than they take to read — surveys, format
evaluations, and readiness assessments. Each one is a markdown file here (the
durable, greppable copy) and a designed write-up behind a link (the version to
send someone).

The rule for this directory: **write down what was measured, not what was
assumed.** Every number in here came from an API, a converter, or a test run on
the day it is dated. Where something is inference rather than evidence, it says
so.

| 24 Aug 2026 | [Live mode: voice](2026-08-24-voice.md) · [full](https://claude.ai/code/artifact/2121fde2-7a38-42e1-8129-1aea8f722e5e) | Voice through Google's Live API is a new input surface for the 28 operations that already exist, not a new vocabulary — and the API's one real limitation draws that line for us. **Function calling is synchronous** ("the model will not start responding until you've sent the tool response"), so a voice tool may only be something that finishes inside a turn. That rules out "build me a screen" as a tool call, which is correct: slow work is not a tool call, it is a **comment on the main thread**, which already wakes every agent parked on `wait`. All but the two content-carrying ops are fast enough to be voice tools — including `item.setCurrentVersion`, the convergence op the night-shift research found unused at 9 fan-outs to 2 choices, and which *"keep the second one"* makes a one-second gesture. The socket belongs to the **daemon, not the browser**: a browser-held socket makes voice a web-only feature forever, while the daemon keeps tool calls landing as ops through the one engine and the key out of the page entirely. And the canvas solves voice's hardest problem for free — **deixis**: `PresenceSession.selection` is already on the wire, so the daemon knows what "this" is before the sentence ends. Wire facts (16 kHz in / 24 kHz out, 15-min sessions, ~10-min connections, `interrupted`, both-side transcription flags) are second-hand: Google's own doc hosts fail certificate verification from here. |
| 24 Aug 2026 | [The night shift](2026-08-24-the-night-shift.md) · [full](https://claude.ai/code/artifact/81cda096-b7b9-4526-acb4-cf10010bb0ab) | An off-hours self-improvement loop is worth building, and the measurement that decides its design reverses what `evals.md` concluded a day earlier. Counted across all 17 canvases in this home: divergence has gone **1 → 9** multi-child parents in a day while convergence stayed at **2** `item.setCurrentVersion` ops, with 54 versions stacked and 19 undos. The preference mine is no longer empty of ore — it is empty of the *act of choosing*, exactly as `design/convergence.md` predicted. So convergence is the loop's **exit**, not a follow-up: a night shift multiplies divergence, and without it everything made overnight arrives somewhere nobody can accept it from. The rest follows from one rule — an overnight change may be called an improvement only if it names, *before the work starts*, a number already being measured — which splits the loop into a converge lane (verified, may land as a version, revert is one command) and a diverge lane (provocations, never lands). The graders for the first already exist and are wired to nothing: `grade.mjs`'s 7 failable checks were run for this write-up by typing the command lesson #13 says nobody types. The version stack is what makes unattended work safe; the morning gesture is what makes it worth anything, and every accept or reject is the labelled preference pair Stage 4 needs. |
| 24 Aug 2026 | [The ask](2026-08-24-the-ask.md) | Six platforms that do not cite each other — MCP elicitation, MCP's 2026-07-28 stateless rebuild of it, Linear's `awaitingInput`, A2A's interrupted states, LangChain, the OpenAI Agents SDK — all grew the same object for *"I am blocked on a human"*: a question with a shape, a state the surface derives rather than the agent asserts, and an answer that resumes the work. isocan has the third part built (`wait` already wakes the asker on a reply in its own thread) and neither of the first two: unread state clears when your eye passes over it, so the canvas forgets anybody is stuck, and no query on either surface answers "what am I holding up". The fix costs zero operations — `/ask` is a comment, the way `/cancel` already is, and `#Title` already resolves the candidate set into `comment.items`. Underneath: `measure.ts` turns out to be an independently invented `ui/notifications/size-changed`, so isocan is accidentally most of an MCP Apps host — except that the spec **mandates** the `allow-same-origin` that `ItemView.tsx:670` refuses, making the content origin load-bearing for a fourth reason and the first one from outside the repo. |
| 24 Aug 2026 | [A story is a URL](2026-08-24-storybook.md) | Supporting Storybook costs zero operations and was run end to end today: a story is a URL (`iframe.html?id=…`), `/index.json` is the map, and three components landed on a canvas in three `isocan browse` commands as ordinary `text/uri-list` items. The measurement that decides every deeper design is a boundary this repo already drew — a story renders in the **site** sandbox and goes **blank** in the **screen** one (`allow-scripts` alone, opaque origin), so a component here is a projection and can never be a baked HTML blob. Ladle publishes the same two objects (`meta.json`, one URL per story), so what is worth supporting is the contract, not the vendor. Also measured: `storybook init` now installs an MCP server by default (eight tools live, seven documented), the install is +131MB over a bare Vite app, and Ladle is broken on a current scaffold. Inward, the answer is weaker: 31 web tests render zero React, and Storybook's test addon would buy Vitest 4 and Playwright to fix that by accident. |
| 24 Aug 2026 | [Design systems and tokens](2026-08-24-design-systems-and-tokens.md) | Nobody renders DESIGN.md — not Google, whose format it is, and not the 110k-star library of DESIGN.md files, which ships 74 files and no viewer — so `DesignSystemView` sits in an empty spot. But measured against the official 2025.10 JSON Schema and Google's own reference exporter, `isocan design --tokens` does not emit what its help text promises: colours must be `{colorSpace, components}` objects and dimensions `{value, unit}`, and isocan's hex strings pass the schema only because the published schema never applies a group's `$type` to its leaves. `fromDtcg` reads 0 of 20 colours back out of a real W3C file and turns spacing into `[object Object]`; it is also unreachable from either surface. And the 74-file corpus run through `design check` gives 308 errors across 42 files, of which 295 are isocan rejecting valid input — compound references, YAML block scalars, `rgba()`. All of it is pure functions in core: zero operations, both surfaces at once. |
