# A deep copy edit: N voices for a screen's words, and a pick

**2 October 2026.** Dion: *"When going from base wire to adding text…
could we add the ability to do a DEEPER 'copy edit'? … both on how to do copy
at the wire time but ALSO doing it actually on any screen. You select a
screen and can say 'Please give me 3 variations of the copy' and you get the
options to choose from. Do we need to even do anything vs. a normal agent
pass? What would make this a true upgrade?"*

Everything below was checked against `main` on the day; references are
`file:line`.

## What a normal agent pass already does

More than you would guess, and that sets the bar.

- **Any screen.** `/variation 3 try different copy`
  (`core/src/command-catalogue.ts:69`, body `command-bodies.ts:463-490`)
  makes the agent read the file, write three edited copies, `isocan add` each
  with `--prop parent=`, and comment which it would keep. You compare in
  *Compare versions* (`VersionCompare.tsx`, the word-level diff in
  `core/src/diff.ts:415-430`) and pick with *Choose this variation* /
  `isocan choose` (`converge.ts`, one op group, one undo), or record a
  preference without folding with `isocan prefer`.
- **A wireframe.** `isocan wire copy <screen>` prints the words as JSON slots
  with a strict schema (`blockContentSchema`, `copy-schema.ts:70`); an agent
  writes K files and applies one with `--apply` (validated, one version, the
  prototype rebuilt, one undo). `wire copy --ai` fills one screen at a time
  through a vendor-neutral `TextGenerator` (`core/src/jev.ts:591-720`).

So "give me 3 and let me pick" works today. What it does badly is the part
that makes it worth asking.

## Where the plain pass falls short

1. **It rewrites the whole file to change the words.** An agent has no verb
   for "replace this text"; `isocan edit` uploads a new file, so a copy pass
   can and does drift layout, classes and markup. `/variation`'s default even
   says *vary layout and hierarchy* (`command-bodies.ts:463`).
2. **Three rewrites are not three choices.** Nothing asks each variant to be
   a coherent voice with a stance; you get three paraphrases and no reason to
   prefer one.
3. **You compare two at a time.** Compare is pairwise; there is no N-up view,
   and no way to take the headline from one and the button from another.
4. **Nothing knows how much room the words have.** No check that a variant
   fits its box, wraps sanely, or stays on one line where the layout needs one
   (design-lint's kinds are colour, size, radius and spacing only,
   `designaudit.ts:19`).
5. **Nothing knows the product's voice or its words.** DESIGN.md has no voice
   section (`designmd.ts:88-96`) and a canvas has no glossary, so "Sign in" on
   one screen and "Log in" on the next is invisible.
6. **At wire time it is one screen at a time and one answer.** `generateWireCopy`
   and `nameFlow` return one result; a flow's words are never chosen as one
   voice.

**Two bugs found on the way** (fixed in phase 0 below):

- `wire edit --kind content` does not call a text model: the planner writes the
  **instruction itself** as the slot heading (`edit.ts:358`), so "make the CTA
  friendlier" becomes the heading "make the CTA friendlier".
- The web `/wire copy` and `/wire name` pass no generator
  (`dialog.tsx:341,356`), so from the browser they always use the stub's
  noun-salad, whatever is configured.

## What the field does

Figma AI rewrites, shortens and translates a selected text layer, with a tone
dial (Executive, Technical, Basic, Educational)
([help](https://help.figma.com/hc/en-us/articles/24004868368919-Rewrite-translate-and-shorten-text-with-AI),
[tone](https://help.figma.com/hc/en-us/articles/24244814883735-Adjust-tone-using-Figma-AI)).
Frontitude adds team guidelines as guardrails and actions — rewrite, shorten,
expand, brainstorm, simplify
([guidelines](https://write.frontitude.com/assistant-guides/team-guidelines)).
Ditto treats product copy as a single source of truth synced across designs
([overview](https://product.dittowords.com/)). All three work one text layer
at a time; none offers coherent whole-screen voices to choose between, and
none checks fit in the real renderer. That is the opening.

## The upgrade: copy as data, voices as choices

**1. A copy deck for any screen.** A pure core function reads an item's HTML
and returns its strings in reading order, each with a **role** (heading,
body, button, link, label, placeholder, error, empty state, nav), a stable
**address** (`data-wf`/`data-sec` on wireframes; on any other screen the
element path the WYSIWYG splice already uses, `web/src/lib/textPatch.ts`,
checked by its current text so a moved file is refused, never guessed), and a
**budget** — the box the layout gives it, measured where the screen renders.
`isocan copy <item>` prints it; the web shows it as a panel. This is the
missing primitive: an agent edits *strings*, never the file.

**2. Variations that change words only, as voices.** `isocan copy vary <item>
--n 3 [--brief …]` and *Vary the copy…* on a screen produce N **copy
variants**: whole-screen sets of strings, each with a short **stance** (e.g.
*plain and direct*, *warm*, *benefit-first*) and one line of **why**. Applied
by splicing strings into the original file, so layout, classes and markup are
byte-identical outside the text — the guarantee a plain pass cannot give.
Each lands as a variation item with `parent=` (the existing `/variation`
contract), so *Choose this variation*, `isocan choose`, version diff and undo
all work unchanged. No new op.

**3. An N-up copy compare, with mix and match.** The variants side by side,
live, in the real screen; and per string, a picker to take *this* headline
from B and *that* button from C. The mix is applied as one new version of the
source (one undo). The text diff across siblings is the existing diff engine
in text mode.

**4. Fit, measured.** Each variant is rendered where screens render and every
string checked against its budget: overflow, clipped, wrapped past the lines
the role allows (a button gets one). A variant that does not fit is marked,
with the offending string, before anyone picks it — the check a model cannot
do from the source.

**5. Voice and words in DESIGN.md.** A **Voice** section — tone in a sentence
or two, words to use, words to avoid, and a glossary (*sign in*, never *log
in*) — read by the variants, the fit pass and a copy lint: one name per
thing across a flow, a button's verb matching where it goes, the slop tells
already written in `core/src/slop.ts` applied to a canvas's screens instead of
only to isocan's own.

**6. At wire time: one voice for the flow.** After `wire flesh`, *Choose a
voice*: the flow's words, all screens, written in N voices at once (a
`TextGenerator` call per voice, not per screen), previewed on two or three key
screens, chosen once and applied to every screen in one group. Intents and
links stay bound — the schema already refuses changing them
(`copy-schema.ts:134-140`). `wire copy --ai` becomes the one-voice case.

**7. The choice is evidence.** Every pick is a preference pair (`preferredOver`
already records them); the stance that won is the label. The judge's corpus
gets a copy kind; a later voice can be recommended rather than guessed.

## Where generation runs

Copy needs prose, so not Jev: it goes through `TextGenerator`, which today is
OpenAI-shaped HTTP with a key on the machine, and the stub in the browser. The
browser path should go through the home (the same no-key-in-the-browser rule
voice's fast path follows) and gain a Claude route. Jev has two honest jobs
here: choosing which roles a brief is about (cheap typed choices), and ranking
variants against the voice once the judge has calibration for it.

## The walk

0. **Fix the two bugs.** `wire edit --kind content` calls the text model and
   writes words, not the instruction; the web `/wire copy`/`name` go through
   the home's generator.
1. **The copy deck.** Core extraction with roles, addresses and budgets;
   `isocan copy <item>`; a string-level apply (`isocan copy <item> --apply
   deck.json`) that splices only text and refuses a stale address.
2. **Copy variants.** `copy vary --n`, stances and reasons, applied as
   `parent=` variations; *Vary the copy…* on a screen.
3. **N-up compare and mix.** The side-by-side and the per-string picker,
   folded as one version.
4. **Fit and voice.** The renderer-side fit check; DESIGN.md's Voice section;
   the copy lint.
5. **Wire time.** *Choose a voice* across a flow.
6. **Evidence.** Picks as labelled preference pairs; a copy kind in the judge
   corpus.

Phases 1–3 are the answer to *"what would make this a true upgrade"*; 4 is
what makes it better than Figma's; 5 is the wire-time half Dion asked for.
