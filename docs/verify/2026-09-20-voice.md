# Voice, out loud

**Status: `unverified`.**

**What you need:** a microphone, speakers or headphones, a Gemini API key, and
about twenty minutes. No repo knowledge.

**Why this page exists.** The voice agent has thorough automated proof — the
model's tool calls were driven and inspected, the projection is unit-tested at
the seam, the operations it mints are checked. All of it went in as **typed
text**. Nobody has ever said a word to it out loud. Everything below the line
"does it feel like a partner" is unproven, and that was the whole point of
building it.

---

## 1. Start a canvas to play on

Do NOT use a canvas you care about — the agent will move things on it.

```bash
node packages/cli/bin/isocan.js canvas create "Voice test"
```

**You should see:** `created canvas prj_…` and `(set as default canvas)`.
Keep that `prj_…` id; you will paste it in step 3.

Now put three things on it, in three colours, so there is something to refer to
out loud:

```bash
node packages/cli/bin/isocan.js text "Checkout screen" --title "Checkout screen" --paper blue --at 600,200
```

```bash
node packages/cli/bin/isocan.js text "Release notes" --title "Release notes" --paper green --at 1100,600
```

```bash
node packages/cli/bin/isocan.js text "Standup" --title "Standup" --paper yellow --at 200,900
```

**You should see:** three `wrote itm_…` lines.

## 2. Start the voice agent

```bash
npm start -w @isocan/voice-agent
```

**You should see:** it build the page, then print the canvas it attached to,
the identity it resolved, the daemon it is talking to, the model
(`models/gemini-3.8-live`), and an address — **`http://127.0.0.1:7654/`**.

**If it prints a command instead of an address**, run that command first: the
page is built separately from the harness.

## 3. Point it at the canvas and give it a key

Open `http://127.0.0.1:7654/` and click the **settings cog**.

1. Paste your **Gemini API key**. The provider validates it, so a wrong key
   says so here rather than failing silently later.
2. Set the **canvas** to the `prj_…` from step 1.

**You should see:** the *"needs setup"* callout disappear. If it stays, it is
naming which of the three things (key, canvas, daemon) is still missing —
believe it.

## 4. Say something easy

Press **Listen** and say:

> *"What's on this canvas?"*

**You should see and hear:** the ring animates while you talk (your waveform
inside, the model's around the outside), and it **answers out loud**, naming
the three items.

**This is the first real check.** If you get text but no audio, or audio but it
cannot name the items, stop and write down which — they are different faults.

## 5. The sentence the whole thing was built for

> *"Move the green one next to the blue one."*

**You should see:** the Release notes card move on the canvas so it sits to the
right of Checkout screen, with a gap, middles lined up. Open the canvas in a
browser alongside if you want to watch it land.

**Time it, roughly.** From the end of your sentence to the thing moving should
feel like a beat, not a wait — driven by text it was about one second. **This
is the judgement no machine can make for us**: does it feel like a partner, or
does it feel like a slow remote control? Write down which, in those words.

## 6. The clause that is hardest to get right

Immediately after it moves, say:

> *"Actually, undo that."*

**You should see:** the card go back where it was.

**What to check, and this is the real test:** move one of the OTHER cards
yourself first — drag `Standup` somewhere with the mouse — then ask the agent
to move something, then say *"undo that"*. **It must undo its own move and
leave yours alone.** Undo here is per-actor, and that is the property most
canvas tools get wrong.

**If it instead moves the card back by hand** — i.e. you see a second move
rather than a retraction — that is the bug this walk exists to catch. It was
fixed on 20 September but only ever confirmed by watching which tool the model
asked for, never by watching the daemon do it.

## 7. The ambiguous case

> *"Move the red one next to the blue one."*

There is no red item on this canvas.

**You should hear:** it **ask you which one you mean**, in a sentence. It must
NOT pick one and move it.

**This is the behaviour worth protecting.** It comes from one paragraph of
prose in the projection, not from any confidence score, and it is the thing
most likely to regress silently.

---

## When something is wrong

Write down **which step**, what you expected from this page, and what happened
instead — then open an issue with that. A step that is ambiguous is also a
finding: this page should need no interpretation, and if you had to guess, say
so and it gets rewritten.

## What this walk does not cover

- **Enrolling the agent on a canvas so `@mentions` wake it** (`isocan rc add
  VoiceAgent --harness voice`). Separate walk, not written yet.
- **The browser talk module** — the in-app voice dialog is a different surface
  from this standalone page, and its undo path is
  [its own walk](2026-09-20-undo.md).
- **Anything on a phone.** Untried.
