# Public — deliberately findable

Public answers where a canvas is advertised. Its existing link answers how
somebody enters, and its capability answers what they may do there. A person
can publish a canvas without changing the meaning of any permission rung.

## Journey 1: Put the work on the home

Maya owns a synthetic canvas called Acme Examples. In Share she enables a
Canvas Viewer link, then separately chooses **Public on this home**. The
control explains that anyone who can reach this home can find its title and
open it with the link's existing access. Presentation Viewer works too.
An Editor link must be changed deliberately before publication is available.

Rowan has never received its address. The signed-in home has a Public section;
the unsigned front page offers Public canvases without requiring a name.
The dedicated public page lists titles, their home and their read/view access.
It does not load previews, item contents, histories, comments or activity.
Opening a row takes Rowan through the ordinary home door: presentation may
open anonymously, while canvas viewing retains the existing naming flow.

Rowan's ordinary working list, Inbox and parked agents do not acquire every
public canvas. Merely browsing the catalogue creates no canvas admission or
seen-mark. Entering a canvas makes it an ordinary visited canvas afterward.

## Journey 2: Stop advertising without closing the door

Maya unlists Acme Examples. A fresh catalogue read no longer names it, but
Rowan's known address and existing admission still work. Share says exactly
that. Turning the link off is the different act that ends link-based access.

Turning a link off and on, replacing it, revoking it, or changing it to Editor
does not silently republish the canvas. Restoring read/view requires another
explicit publication. An old publication request cannot resurrect a revoked
grant. Restart preserves the latest decision.

## Journey 3: The home owns the advertisement

A replica retains Acme Examples after losing its home connection. Its public
catalogue does not advertise that copy. The owner's publication command can
follow the existing authenticated home route; catalogue browsing explicitly
names the home to ask and never silently aggregates replicas.

A takedown or purge suppresses the entry. The public route observes the
home's refusal rules, and a retained snapshot cannot supply an old success.
An ordinary editor, a space grant, an absent link and an unknown capability
cannot create a public listing by bypassing the UI.

## What these scenes force

Publication is explicit, owner-controlled, home-local desk state tied to a
specific link grant. Legacy grants are unlisted. The public catalogue is a
separate read surface with a narrow metadata projection; the existing working
lists and their discovery rules stay unchanged. Public is never a capability.

Both CLI and web reach the same API and shared eligibility rules. The first
release supplies no search-indexing or social-preview feature: public pages,
catalogue responses and canvas entry pages send noindex instructions. They
are indexing instructions, not a confidentiality boundary or a crawler promise.

No new cloud resource, paid model run, live user canvas publication or operator
sign-in is needed for this project's synthetic local and emulator acceptance.
