task: lay a small tabbed app out as a flow map (screens, navigation arrows, device sizes, tokens) from a separate tool, and keep it current on save

### Rough
- Navigation arrows: contract symbols names a path("route") target as a route reference at its column, but not the verb (push/replace/select/back are builtins) nor the action it sits in; back(nav) leaves no reference. The tool reads the verb from the text left of the reference, the action from indentation, and the screen from enclosing `e.name == "…"` conditions (~1.5 h). A `navigations` list in symbols (verb, target, action, span) would replace all of it.
- `tamber uses` exists only on the design server's wire; listing every token's sites means starting `tamber serve`, fetching the loopback token and posting one request per token (~10 min). A CLI `tamber uses <app> [--json]` would do.
- Grants are printed nowhere; read from app.ts with a regex.
- web-build output is not reproducible (.exact-build.json, .gen/server.js, .gen/ts-data.js change on every rebuild), so a "did anything a capture depends on move" key hashes the app's input files plus the Exact commit instead of the build output.
- A root component must come first in app.contract: putting a small component above App made App "a child" and refused its `persist` state with a message that pointed at the wrong fix (move state into the other component).

### Lean in
- agent web captures are byte-identical run to run, and resize + prefer color-scheme + clock settle + screenshot in one driver gives the same bytes as a cold single shot — six device/scheme pictures per cold start (~2.5 s), so "post a version only when pixels change" is a hash compare.
- contract test prints compiled tests as clean JSON; contract symbols' references make "which components does this draw" a filter.
