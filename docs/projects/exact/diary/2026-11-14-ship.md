# Ship from a canvas — isocan exact phase 7, 14 Nov 2026

Exact cbe553f6 · Bun 1.4.2 · Acme Market (synthetic) · iOS Simulator (dedicated, iOS 26) · a directory origin on this
Mac served on 127.0.0.1:4790 · channels internal and production · Ed25519 test key from `deploy.mjs keygen`.

## Rough

- `deploy.mjs` refuses a clean commit of any app that has been worked on: git-IGNORED files count as uncommitted
  source — the app's own `.exact/` diary and logs (which `exact new`'s .gitignore ignores), `.vscode/`,
  `app.contract.d.ts`, and `vendor/ibex/crates/*/target/` inside the Exact checkout. `--dirty` is the only way past,
  and then those bytes fold into the snapshot id, so `--snapshot` cannot pin a dry run to its `--yes` while
  anything appends to `.exact/commands.jsonl`. A canvas client had to hold the commit itself and refuse tracked
  changes before passing `--dirty`.
- `deploy.mjs <path>` for an app outside the checkout refuses ("the captured app resolver does not select the
  app and workspace frozen by the launcher"): the path re-selects the live directory in the captured child.
  `EXACT_APP_DIR=<dir>` plus the name works. The app's `exact.mjs` has no `deploy` verb.
- A channel that names a directory is baked into the binary as a bare path; the iOS client then says
  "Failed to fetch — unsupported URL". The channel must be the URL and `--origin` the directory. `serve.mjs
  --origin` refuses an origin that holds update streams but no web root, so a plain static server served it.
- A production simulator build with an update store refuses without `EXACT_UPDATE_GENESIS=1` on the first build.
- `deploy.phased` and `deploy.release` are schema only: nothing in `deploy.mjs` reads them. A phased production
  rollout cannot be asked for; the canvas says so on the card.
- AppDrop (`share`) needs appdrop.app and `npx appdrop@0.8`: a hosted service, not run.

## Lean in

- The dry run's JSON table is exactly what a canvas needs: each row's `action` (`bundle` / `binary` / `current`)
  and Exact's own reason made the classification card with no guessing.
- `--yes` signed and published in one step; the head's `seq` and the release record are enough for a release card.
- The simulator build's compatibility id equals the device bake's, so `deploy`'s first stream is the stream the
  simulator checks. Pickup: the running app changed 10.6 s after the head was written (check.interval 10,
  activate immediate), with no relaunch.

## Needed

- Ignored files out of the snapshot (or a named allow-list), so a clean commit deploys without `--dirty`.
- A `deploy` verb on the app's launcher that takes an outside app.
- A publisher rollback, or a documented "re-publish release X" — a canvas re-publishes the old commit from a
  worktree, which works but rebakes.
- `phased` implemented, or removed from the schema.
