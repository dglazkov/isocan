# Memory — bring a source, see where it came from

## Journey 1: Inherit the design system

Theo's team keeps Design System as a canvas. On Acme Onboarding he places it
with the inception popup and ticks Inherit memory. Context gains a heading
from Design System with its system and pinned rationale notes. The local
canvas's own system wins when one exists; otherwise the shared system governs.
An agent reads the same headings and provenance through isocan context.

## Journey 2: Bring yourself

Maya opens Acme Onboarding and chooses Your canvas in Context. Her first use
creates ~Maya privately at this home; every later project on this home returns
the same canvas. A rename changes no address. There is no moment when its
birth has a public link or belongs to somebody else's default space.

She writes and pins a preference on her canvas: I review on a phone; keep
screens at 390 first. She links Your canvas on Acme Onboarding. One small
card appears in the Context sheet saying Maya's canvas is linked. Everyone
can see that she brought a personal source; the card shows no private preview.

Maya explicitly allows her agent Rowan to read this personal layer. Rowan's
claimed session can read the current pinned preference and its provenance.
Theo's agent cannot, even if a local client happens to hold more than one
identity. A copied card in another project grants nothing. Personal reading
never quietly substitutes Maya's design for the team's governing design.

Maya unlinks the card. Rowan's next read no longer receives that layer. One
undo restores the same card and consent. Closing Maya's browser does not
unlink it: she enabled the source for this project, so her standing agent can
continue. Revoking Rowan's access stops his next private read even while the
visible card remains. Maya can still read her own source.

A home that cannot be reached says so. It never supplies a retained replica's
old private success as if the authoritative permission were still known.
When two of Maya's identities join, both existing memory datasets survive;
one stable primary binding is chosen without merging or deleting contents.

## Journey 3: Put it in the repo deliberately

The team exports Design System into the product repo, reviews a token change,
and imports it elsewhere. The inherited source has the same bytes afterward.
Exporting Acme Onboarding contains the visible link to Maya's source and none
of the private preference, its source title, versions, hashes or screenshot.
Maya may separately export her own personal canvas into her private files.

## Journey 4: A newcomer reads the corner

Ravi joins Acme Onboarding. Context's visible group identifies the linked
sources and whose memory is present. The Context panel, CLI and MCP report
local, inherited and personal layers consistently for their selected caller.
An unclaimed or ambient MCP call cannot silently borrow Maya's personal layer.
A frozen request still includes only the shared project's own context.

## What these scenes force

Canvases remain the memory record. Ordinary inheritance is shared; personal
consent and delegation are authoritative private Desk state. The visible card
uses the existing operation vocabulary and undo. Authorization precedes every
private source read, and the response carries provenance. No vendor index,
paid run, cloud resource or live personal data is required to prove this work.

See design.md for the existing layered mechanism and personal-memory.md for
the precise personal birth, consent and reading contract. Browser closure is
not revocation; unlink and explicit delegate removal are the deliberate acts.
