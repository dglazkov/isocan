# A comparison ends in one reversible decision

The debt is that the phase 0 planner can copy an option and write a property,
but a public property cannot establish who chose it. A separate answer followed
by an edit can also leave a choice recorded without its adoption. Phase 4
replaces that proposed authority representation with canonical comments and
one fixed, conditional adoption act. This mechanism implements Scene 3; it
does not claim the quality improvement that phase 7 must measure.

## The decision worth presenting

Use two options by default when an unresolved structural or visual decision
could change the result. Structural options are working wireframes; visual
options use comparable polished content. Each source declares one scenario,
common fidelity, a hypothesis and tradeoff per option, and an attributed
recommendation. Those declarations do not prove useful diversity or task
success: the named browser walk and later study do.

A batch permits one to three options. One is for an explicit direct or
delegated fast path, not a fabricated comparison. Requests for more exploration
remain durable instructions and can produce additional linked batches; the
batch bound must not silently discard a requested fourth hypothesis. Precise
edits in an incumbent design need neither comparison nor a new interview.

Keep brief and candidates separate. A person tries an exact version, selects
an option locally, then presses **Use [option]** once. Trying is not choosing.
The consequence names the actual target, without a second confirmation.
A human reason is optional and represented as null when absent. Never fill
that field with the agent's recommendation. Agent decisions require their own
rationale. Selecting a connected-app prototype records a direction; it does
not claim the repository runtime was implemented.

## Four bounded operations, one existing store

The comment store gains immutable comparison, comparison-response and
adoption-decision records, distinct from phase 0's legacy decision property.
They reuse exact thread/comment/payload/revision source identity, ordinary
Markdown projection and flat writer-retained references. Ordinary questionnaire
questions and known-human answers retain their existing semantics.

| Operation | Public intent and canonical effect |
| --- | --- |
| `design.compare` | Publish an exact comparison as one comment. The writer stamps actual author, references and intent identity. An explicit reissue names the previous exact source and preserves its history. |
| `design.respond` | Record one non-adopting outcome beside its exact comparison: delegate to a named agent, request more directions, request a combination of identified option parts, skip or dismiss. It writes one attributed response comment and never edits the output. |
| `design.decide` | Choose one exact option or direct proposal and adopt it. Its only resolved effect is one conditional target edit plus one immutable decision comment, applied together. |
| `design.restore` | Internal only: restore the specific target-version and decision-comment pair for Undo/Redo. It cannot carry an arbitrary operation array. |

The vocabulary was already 40 at phase 3: the architect's 36 bound omitted
phase 1's ask/answer and phase 2's request/receipt. Record those four refusing
acts and this phase's deliberate 40→44 addition in the persona's argument.
Do not alter the measurement or invent call sites. Publish, revise/delegate,
adopt, and restore have different custody and effects; an arbitrary batch or
a disguised questionnaire answer would erase those distinctions.

Comparisons carry request/epoch, exact admitted brief, stable outstanding
decision key, audience, scenario/fidelity, exact candidate versions, intended
target/scope, governing basis and explicit supersession. A new comparison
requires an outstanding brief decision, or an explicit correction of its
canonical previous decision. A correction identifies the prior decision; it
does not need to manufacture another discovery question. Reissue preserves
author custody and checks the current predecessor. More/combine responses
remain linked when the designer publishes the next batch or combined result.

`design.respond` has a closed outcome union. More carries a requested count
when supplied and an optional instruction. Combine carries at least two
identified option parts and a specific instruction. Neither marks a chosen
output until the resulting real version is later selected or delegated.
Delegate identifies an eligible actual agent; skip/dismiss cannot be treated
as supplied preferences. Superseding responses identify their exact predecessor
and retain it. Ordinary prose cannot resolve or revise these records.

A larger exploration request can span multiple batches without another human
response. Each batch retains the original effective revision-response identity
through its exact authored predecessor chain: same request, brief item, epoch
and decision key, unchanged source text, explicit consecutive supersession and
no fork or missing predecessor. The response must still be effective at its
original source. A response to an unrelated comparison is not a predecessor.
This preserves the original requested count and instruction while allowing,
for example, four additional hypotheses in two batches of two.

## Authority belongs to the actual act

Audience is either a named known canvas human or the reporter of an admitted
external request. Resolve identities through current canonical actor joins,
while retaining the original public authors in history. Missing actor kind is
unknown, never evidence of a human.

Decision authority has four closed branches:

- **Human choice:** the actual known-human actor is the named respondent.
  Record their chosen option and optional reason, without an agent fallback.
- **Canvas delegation:** the actual known agent has an effective canonical
  human delegation naming this exact source and this agent. Link that separate
  human act and record the agent's rationale. Do not mint a human preference.
- **External report:** the authenticated original reporter, or current worker
  after explicit reasoned resume, reports native choice or native delegation
  against its admitted external request. Record which outcome was reported,
  the reported statement/reason and the adopting agent's rationale separately.
  A quote does not create a human actor, canvas response or human custody.
- **Agent judgment:** an actual known agent takes the direct speed path with
  its own rationale and no assertion of delegation. This cannot settle an
  outstanding comparison addressed to a named human.

Non-adopting responses similarly distinguish actual named-human action from
external dialogue reported by its authorized agent. External reports must not
pass through the known-human questionnaire writer. Native adoption need not
first create a synthetic canvas response or repeat the conversation. A new
reporter must explicitly resume; merely knowing an external request ID is
insufficient. Existing canvas cancellation and source-custody rules still hold.

## Prepare the approval, then enforce it at the writer

The client captures the basis the person actually saw before approval: exact
comparison/source, brief/epoch, every option including rejected options,
target current version, title, description, properties, relevant membership/
scope and governing identity. The final submit validates this captured basis;
it must not silently substitute the latest target metadata or options.

The serialized writer checks the admitted current request, source/cancellation,
decision key, actor custody, exact current brief, all options, target metadata,
context and governing/scope facts. Use the same existing request guards and
source permissions, factored narrowly for reuse. Foreign governing preflight
and post-save consistency are not a cross-canvas transaction or policy lock.

An existing-screen target must be the brief's target. Greenfield uses the
selected candidate, adding a fresh version with the same bytes. Require
compatible MIME and a real screen target; no admitted JSON brief or group
can be overwritten. Preserve the existing target filename. Do not move,
resize or delete candidates, and do not call the sibling-removing `choose`.

The public operation cannot supply its canonical effect, author, retention or
receipt digest. The writer resolves exactly the target edit and decision
comment, and the reducer validates and applies both to one next state before
persistence. There is no partial commit. The decision contains the frozen
comparison/proposal, recommendation author, actual decision/reporting author,
authority branch, approval basis, prior target and adopted version, explicit
decision supersession and writer-owned intent identity.

One Undo restores the target and decision together; one Redo restores the
original authored records. A conflict in either member leaves both untouched
and does not consume the Undo candidate. Grouped Undo preflights all members
before persistence. Ordinary later HTML edits and pruning remain legal: HTML
does not acquire the JSON-only `designRecord` marker or protected properties.

## History and currentness are separate readings

Shared reads combine canonical current comments with original decisions in
the existing live and archived operation log. Return authored history,
effective decision, current consistency and allowed next acts separately.
Superseded, undone and deliberately removed decisions retain their original
authorship in log history. Undo of a correction makes the earlier live
decision effective again; it never reauthors the original choice.

An adopted target can be a live input captured by the brief. Continuation
recognizes only proven exact before→adopted transitions for the same admitted
brief item, request and epoch. Every edge comes from a still-present canonical
decision and matches the target's prior and adopted version/hash plus captured
metadata/scope. A superseded ancestor may support the exact transition chain,
although only its descendant is the effective preference. Reject forks,
cycles, missing edges and changed final content/metadata/scope. Undo/removal
removes that edge; another actor's later edit is not waived. A later ordinary
brief update within the same epoch may retain the original input and valid
chain; resume captures current context and starts a new epoch. Use this one
derivation in writer lifecycle/receipt validation and shared freshness reads.

Only an effective canonical decision settles its stable brief decision key.
An authored property, `direction.stage=accepted`, or copied/imported JSON
cannot do so. A follow-up through either entrance can read relevant accepted
rationale by request or selected target without asking brand again. It does
not promote abandoned options or private evidence into global memory.

Before freshness checks, an identical accepted retry matches the complete
validated public intent and join-aware authenticated actor against live or
archived receipts. Changed payload, wrong actor and stable-ID collisions
refuse. Accepted retry after cancellation, Undo, pruning or target/comment
removal appends nothing and recreates nothing. Snapshot recovery requires
canonical intent proof, not only matching IDs, bytes or a generic property.

A structured intent-conflict response is definitive only when canonical
live/archived receipt lookup proves that this submitted identity belongs to a
different full intent or authenticated actor. It refuses this submission; it
does not erase another actor's original pending journal. A generic access,
custody, source or transport failure before that lookup cannot prove an earlier
uncertain write absent. Preserve pending status and the original scoped intent.

## Retention and mixed decoders

Comparison/decision comments retain exact local brief, all options, prior
target, adopted output and required local reference versions, including visual
faces. Flatten admitted brief references and strip nested admission markers;
do not recursively embed decision histories. These current comments root
evidence through source pruning/deletion, trash empty, compaction and restart.
Canonical historical text survives through archived operations. If all owners
are deliberately removed, archived acceptance does not promise eternal blob
availability. Test the actual collector with distinct visual blobs and a real
orphan that is swept. Respect permission-bearing reference reads; remote or
private context is not copied locally to evade its source policy.

Add `design-decisions-v1` while retaining earlier feature declarations for
communication with previous daemons. An actual phase 3 daemon refuses new
public acts. The new daemon gates snapshots, operations, inverses, archived
receipts and HTTP/WebSocket/relay delivery before exposing unsupported kinds.
Forward caller feature headers through source and log reads. A generic
operation collision retry cannot leak a new canonical receipt to an old decoder.

## The surface and its recovery

One lazy comparison surface is reachable from chat, task, output and history;
the shared API and CLI expose the same read, publish, respond, prepare, adopt,
reference and history acts. Keep the shared workflow procedure authoritative
instead of copying another interview into each harness.

The designer publishes from canvas chat or an external conversation through
that same API/CLI. Phase 4's browser consumes those comparisons and performs
Try, Use and non-adopting responses; it does not add a manual schema-authoring
form. Every human act has a CLI equivalent. Publication is explicitly an agent
producer here, not an unused browser wrapper counted as a working control.
The surface audit must report this scope honestly.

Equal desktop summaries show names, hypotheses, actual retained previews,
tradeoffs and one attributed recommendation. **Try** opens an interactive
exact-version frame using existing content-origin/ticket machinery. Give this
bounded surface form permission for local script-handled tasks while retaining
`form-action 'none'`, origin isolation and the top-navigation restriction.
Thumbnails stay inert. Never silently fall back to the latest item version.
Keep active same-version frames mounted across status refresh and changes
between desktop and phone layouts. The comparison is owned by a stable
page-level host, not by a chat/task button whose responsive parent can unmount.
Changing width is not closing the comparison; in-progress prototype state,
choice and focus remain available. Actor/canvas changes still enforce their
existing boundaries and preserve exact pending drafts. Provide Return
controls before and after the frame and restore focus to Try. Parent Escape
handlers cannot be assumed to receive events inside a cross-origin child.

At 390 pixels use stacked summaries and one usable interactive prototype at a
time. Native radio semantics, descriptive action labels and wrapping controls
must work through actual keyboard and pointer events. A draft keeps choice and
human words separate from immutable pending delivery, scoped to canvas, actor,
request/epoch and exact source. Any approval-basis drift preserves the draft
and requires explicit review of a refreshed source. Prepare before journaling;
invalid local input remains editable. Pending delivery retains exact IDs and
payload across refresh/navigation. Acceptance followed by failed consistency
read means saved/unavailable, not another enabled adoption. A superseded draft
can be archived/restored/exported with storage acknowledgement before release.
