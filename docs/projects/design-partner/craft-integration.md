# Craft guidance that keeps the same brief

The debt is that importing one Impeccable instruction file cannot supply a
package, and executing its whole discovery procedure can reopen decisions the
canvas already settled. Phase 6 supplies a bounded, optional **adapted-guidance**
path over the existing request, system projection and review. It adds no writer
operation, second interview, workflow database or automatic paid work.

## The compatibility finding

Pin upstream `pbakaus/impeccable` at
`2149fcce39a90bb409df5f16515f316a76dc6199`. The skill reports **4.3.1**, the npm
manifest **4.1.0**, and the launcher requires engine **0.1.5**. They are different
identities; none substitutes for another. The conductor checked 64 package/role/
license files, plus nine relevant engine sources, against their Git blob hashes.
The local Darwin arm64 engine also matches both the release digest and its
sidecar: `0d48b6e16aa97664fdbe607d5da9ae320e389a1843e0ff1328f8c2530530320d`.

An actual isolated launcher/context probe reads PRODUCT.md, the exact DESIGN.md,
a mapped surface brief and the supplied reference path. A deliberately absent
engine refuses without downloading in the launcher's explicit probe mode. That proves local context resolution, not
execution of the new-work, critique, finish-reviewer or documenter playbooks.
Even with product context present, the engine emits general interview/autonomy
and image-workflow directives. New-work adds its own concept selection, detector,
image and role handoffs. Those semantics do not become this project's default
merely because the launcher works.

**Ship adapted guidance only in this phase.** Native full-playbook orchestration,
hooks, live overlays, automatic engine download, image generation and native
review/documenter roles remain unsupported here. Local launcher compatibility is
reported separately; Linux and hosted native execution remain unverified. This
is a coherent narrowing of the optional integration, not a hidden prerequisite
for the core workflow. A future native adapter needs its own measured support.

## One optional read on both entrances

Expose `design craft <request> --stage new-work|critique|finish --json` and the
same CanvasHandle/browser-safe API. The stage is explicit. It returns the same request-bound context
and attributed adapted knowledge. An explicit call chooses guidance for that
stage; ordinary design enrollment does not turn it on. The shared workflow and
agent guide name this opt-in door once and keep the core procedure authoritative.
There is no new canvas-wide default and no automatic mode inferred from a
harness name. Phase 7 condition C, if included, names this exact adapted subset.

The browser provides an optional lazy craft-guidance read beside the design task,
using that API. People are not asked for runtime settings or a package path to
continue ordinary design work. Stage selection explains the work (starting,
critique, finishing), without importing a new discovery ceremony. The browser
view and CLI expose package/mode, actual source identities, constraints, limits
and stale/unavailable status; neither claims a review happened by opening them.

Route concise adapted knowledge from the pinned new-work/operate/craft-floor,
critique and polish/harden/adapt references. Preserve their useful distinctions:
visitor task, incumbent authority, visual hierarchy and density, substantive
composition, real content/states, and bounded inspection. Explicit user direction,
existing components/tokens and settled answers win. Do not import the random
concept ceremony, mandatory comp-first path or a second question budget. Source
checks remain the existing auditor; browser tasks remain actual observations.
Mode-specific guidance is contextual: operational work can use familiar fonts,
dense tables and standard controls. Do not turn a broad craft-floor preference
into a universal ban that contradicts the accepted brief or incumbent system.
The shared two-repair allowance covers any guidance-assisted corrections too.

The distributed guidance identifies its own revision, upstream commit, skill
version, original reference paths/hashes and adaptation scope. Keep a small
bounded resource set; do not load the full package corpus into every summons or
the initial browser bundle. Preserve upstream Apache-2.0 license and applicable
NOTICE with attributed material. Updating any pin or guidance body is a reviewed
change, with the same compatibility and evaluation controls.

Optional CLI `--package <skill-directory>` inspects the directory containing
SKILL.md against the 56-file manifest of the pinned Codex skill variant and reports absent, incomplete/drifted or verified
source separately from native execution, which remains not-run/unsupported.
Other generated harness variants are not silently treated as this exact package.
It reads bounded files at fixed relative paths and hashes their bytes; it never
executes a discovered script, downloads an engine or infers tool availability.
The browser does not inspect a remote agent's filesystem or promote its own
bundled guidance into a claim that the external native package is installed.

## Context is a projection

Use the existing canonical request reader, permitted exact-reference reads and
governing-system resolver. Do not select another group's system or infer that a
missing DESIGN.md removes the repository's incumbent. A new-work packet can name
known absence without inventing a system; unavailable authority stays unavailable.
Critique/finish name the actual declared output or repository delivery scope.
They do not attest that the repository was inspected or its runtime executed.

Capture the exact request/brief/epoch, selected context, factual provenance,
accepted decisions, governing binding and cited reference identities. Preserve
reported facts, human answers, assumptions, skips and open decisions as different
things. Read only references already in this admitted scope through existing
source-policy-bearing APIs. Excluded/private/unavailable material is never copied
by bypassing those readers. Historical citations retain their original versions;
current context and output keep their existing freshness rules and exact canonical
adoption/repair continuation. No silent recapture on resume.

The API returns a bounded serializable packet with its own schema/revision,
`mode: adapted-guidance`, stage, upstream/resource identity, request capture,
context/files, limits and currentness. It performs no model call and no canvas
mutation. Pure parsing validates its whole shape and exact file hashes before a
saved packet is used; claimed source identities are checked against the actual
reader when checking freshness. A packet's prose is data, never authority to
bypass the captured request or permission boundary.

CLI `--out <new-directory>` writes a new standalone working packet: PRODUCT.md
with confirmed and explicitly assumed facts, exact governing DESIGN.md when
available, its existing DESIGN.projection.json, a compatible surface brief,
permitted reference bytes and a craft manifest/guidance file. Resolve names from
safe generated paths, refuse existing destinations, and never overwrite a real
repository's PRODUCT.md, DESIGN.md or .impeccable configuration. The packet can
be read alongside the actual repository; it does not replace its component or
runtime inspection. Do not persist a fabricated user build-path preference.

`design craft <request> --check <directory> --json` validates a saved packet
and its original capture against the current
request and source authority. Request correction, cancellation/resume, changed
governing scope or unavailable evidence yields explicit stale/unavailable status
and retains every working file. A new capture is explicit and goes to a new
folder; it never refreshes the base underneath authored edits.

System changes use the existing `design reconcile <directory>` and its exact
DESIGN.projection.json, stable intent, ordinary conditional edit and Undo. Prove
an attributed guidance-assisted system edit and an intervening-source refusal
with the working draft preserved. PRODUCT.md and surface brief edits are proposed
context notes: they cannot silently rewrite confirmed facts. Use the ordinary
explicit brief correction path to adopt such a change. HTML corrections go
through the existing review reservation and design.repair; the adapter adds no
write path, per-mode budget or independent approval state.

## What actually ran

Packet availability is not design execution. The agent that actually applies the
guidance records an ordinary versioned evidence artifact naming packet identity,
stage, scope, changes made, relevant original sources and actual limitations.
The existing review observation/receipt fields carry the mode and revision in
`tool`/`toolVersion`, with that exact evidence reference. No new receipt schema
or protocol feature is necessary. Native launcher output, if separately captured,
is labeled context-loading evidence only, never a native craft verdict.

A missing browser leaves browser obligations unavailable and the final receipt
an unverified draft. Missing images or review roles cannot become fabricated
execution or a blocker for this adapted subset; the actual core procedure and
existing scoped budget remain in force. Do not present self-authored craft
observations as independent human preference. Condition C's incremental design
quality remains unmeasured until phase 7's authorized comparison.

## Proof and support boundary

The phase's matrix names the exact local/browser/API/CLI build and distinguishes
adapted support from native compatibility. Walk a settled request through both
entrances: identical source identities and guidance, no extra question, supplied
brand and accepted rationale preserved. Export exact allowed bytes, load the
projected context with the actual isolated native launcher as a compatibility
check, and verify its output names the correct product/system/surface.

Use deliberate missing package/resource/engine and missing browser/image/role
controls. Package source/readability and native execution are separate statuses;
an edited or missing resource cannot be reported as a verified pinned package.
Walk request and system drift, retained historical references, denied inherited
source, malformed/tampered packet and same-name output-file refusal. Reconcile
one real system edit through the existing CLI, Undo it, then prove a concurrent
edit refuses the saved base. Record a real adapted craft observation and finish
through the same shared review/receipt path, with no third repair allowance.

Full fast/typecheck/build/strict checks and an independent real browser/CLI walk
are required. No model-quality claim, paid provider call, recruitment or default
rollout is authorized by this compatibility work.
