## Findings that changed implementation

Validation must precede an immutable save journal. A malformed draft was being
locked into an uncorrectable retry even though no write had been sent. The shared
preparation now runs before browser and CLI journaling; actual refusal, correction
and uncertain-delivery cases exercise the difference.

The receiving async handler originally let a user change quantities while saving
and then silently restored the submitted quantity. An actual browser reproduced
15 becoming 12. Capturing one coherent receipt and disabling dependent controls
through the save fixes the loss; the correction path remains usable afterward.

Running the installed HTML normally did not prove the embedded preview. An
actual opaque iframe exposed blocked native form submission without allow-forms,
then a Fieldwork history.pushState SecurityError before focus restoration. The
preview retains an isolated origin, allows forms and scripts, and gives temporary
state honest labels. Local fragment links scroll/focus within the preview; normal
native pages preserve normal history. Final embedded evidence is required above.

Different governing winners need a way to preserve and close an old working
draft. Explicit archive-before-close keeps original source and incomplete fields
restorable while permitting the current source to open. Export and editor switches
serialize the actual authored direction instead of the captured old document.

Library creation must validate canonical full-intent receipts, preserve accepted
writes across later read failures, and retain uncertain retry identity. Legacy
area placement can require separate resize/shift operations; the library refuses
new adds on legacy canvases before journaling and points to groups migration.
Previews, downloads and scoped system reads/edits remain available.

Harness corrections are distinct from product fixes: early source observers
missed child CLI traffic until moved to actual HTTP; Node header keys needed
lowercase lookup; an assertion expected an undocumented ambiguity field; native
Mac keycode mixing opened browser chrome; and early iframe inspection missed the
actual out-of-process target. Final assertions use observed public state and the
actual target. Browser automation waits for asynchronous controls to be enabled.
The first full fast run exposed a source-location guard still expecting the old
inline CLI resolver. The updated guard follows the real shared scope/inheritance
and authority-bearing byte read; actual core/API behavior remains covered.
The conductor’s loaded journey exposed an embedded-frame input delivery race:
the quantity was 3 and both DOM hit tests identified Save, but no save occurred.
An 8× parent/child renderer slowdown reproduced a trusted pointerup with no
preceding pointerdown, click or submit and no child runtime errors. The journey
now waits for a rendered surface after both scrolls, remeasures both hit targets,
and sends one pointer cycle. It observes the actual trusted click, focus and
inserted text without retries, synthetic focus or timeout widening. The conductor
independently passed that stress command and the unchanged named journey:
`node --import tsx --import /tmp/isocan-design-partner-execution/phase3-web-slow-frame.mjs scripts/journey-design-systems.mjs`
(`phase3-root-journey-stress-final.log`, output `sR1xTN`). The scratch hook changes
renderer speed in memory and resets it at teardown; no product source changed.
The pre-fix failure log remains `phase3-web-journey-slow-frame.log` (`EoqGWA`).

The first full strict run exercised 606 files and found one failure: the existing
competition walk expected lowercase `/no design system/`, while the shared
reader returned `No design system governs this target.` The actual nonzero
refusal and correct scope remained intact. Its assertion now matches that
semantic refusal without making capitalization part of the protocol; the entire
real competition scenario is rerun, including its later steps.
