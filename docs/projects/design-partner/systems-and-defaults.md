# The system that actually governs the next screen

The debt is a split between the system a builder reads, the one an audit uses,
and the one the canvas says is missing. Phase 3 makes those answers agree and
adds working references for choosing a deliberate first direction. Scenes 4–5
remain the acceptance contract; this file settles their implementation boundary.

## Selection and the explicit exemption

Keep the existing precedence: direct group, its ancestors, canvas, then permitted
inherited canvases in their existing reading order. Within a winning local
level, keep the existing newest-item selection. Return the candidates at that
level, the selected identity and the reason; multiple candidates are visible
ambiguity, not permission to invent a different winner. An unavailable source
remains unavailable. Reads of inherited bytes reassert existing source policy.

Creation, CSS/tokens/show, checking and standing consume that same shared result.
A result names the exact canvas/item/version/blob, source, winning level and any
refused sources. A system from another group cannot satisfy the target. Screen
counts for a scoped nudge/refusal belong to that scope; unrelated lanes do not
make a new lane overdue. Canvas summaries evaluate uncovered screens rather
than treating the presence of any scoped system as global coverage. A proposed
new screen supplies its actual intended placement/group before its standing is
computed. Preserve the existing thresholds and ordinary import exceptions.

`design=none` exempts the canvas from requiring a written system. It does not
delete, hide or replace a real incumbent. The shared result reports the exemption
and the actual governing selection independently. Manual reads and available
brand tokens keep working. No new system is required merely to clear a nudge
on an exempt canvas. A check that uses an existing system must still identify
that system and become stale when it changes.

Phase 2 made `DesignGoverningBinding.explicitNone` mutually exclusive with its
artifact. Phase 3 deliberately widens that binding: `explicitNone` records the
canvas exemption, while `artifact` records the actual winner, including when
both are present. Historical null-artifact receipts remain readable. If there
is now a governing artifact, their policy evidence becomes stale rather than
receiving retrospective credit for an unrecorded check. Output/browser checks
retain their separate freshness rules.

This widening is decoder-significant. Advance admitted-request support to
`design-requests-v2`; upgraded clients also advertise v1 for communication with
the previous daemon. A new daemon refuses v1-only clients on admitted-request
state and operations before it exposes semantics they cannot decode, including
snapshots, replay, inverse metadata and relay ingress. Existing v1 records remain
valid to the new reader. A previous daemon rejects the widened binding rather
than silently losing its artifact; callers report that refusal honestly. Test
HTTP, WebSocket and original-caller forwarding, not only the capability helper.

## A direction is design documentation

Use native versioned `DESIGN.md`; do not add a second system store or token
format. Its preserved `tokens.isocan.direction` extension has version 1, a stage
(`provisional` or `accepted`), optional request ID, rationale, task hierarchy,
layout, density, typography, palette purpose and reusable interaction treatments.
These bounded fields are ordinary authored design documentation. Unknown vendor
fields and existing `isocan.lint` contracts survive an edit and native/DTCG
conversion. A malformed direction is reported, not guessed.

The provisional direction is recorded before a new build. The reusable accepted
treatments are written before adding the next screen. Read the document's real
version author alongside its declared stage. An agent recording that a person
accepted something is still agent-authored documentation; it is not an
authenticated human preference. Phase 4 owns the guarded decision/adoption act.
Do not add a mandatory approval dialog or promote the rationale into global
memory. Existing explicit memory pinning remains the only such act.

## Working files project a version, not new authority

A projection records schema version, exact source identity, captured target
metadata, document bytes and their hash. The source document stays the canvas
system. The CLI can materialize readable `DESIGN.md` with a companion manifest;
the browser can export and reconcile equivalent content through the same API.
The manifest identifies the base, never authenticates a caller. Do not put
private source bytes into shared artifacts or change source permissions.

Reconciliation refreshes permitted source/context, compares the captured source
version and metadata, and submits one conditional `item.edit` to that same
identified source. Retain edited bytes on conflict, permission failure and
pending/unconfirmed delivery. Preserve the exact retry intent. Never silently
save an inherited source as a local override, overwrite a newer source or
relabel an uncertain save as refusal. Explicit local override creation remains
a separate ordinary add with visible scope.

A prepared uncertain retry resends the exact original conditional envelope after
an authority-bearing source read. The proposed version need not remain in the
visible stack: pruning or later removal cannot make confirmation impossible.
Only a returned receipt matching source, full semantic intent and actual actor
confirms acceptance. A fresh attempt still needs the preflight reads and upload.
If an earlier unaccepted retry lands after governing selection alone changes,
the source version/metadata fence still applies and post-save consistency is
stale; no cross-canvas policy lock is claimed. Explicit direct-source access
retains its existing caller policy, including permitted personal access, while
inherited source operations retain automatic exclusion. Neither a manifest nor
a retry flag grants permissions.

Use the existing design-lint repair boundary: refresh before save, conditional
source edit, then reread after save. It is not an atomic lock across canvases.
If selection or remote context changes during the write, preserve accepted
content-save identity and report stale/unavailable consistency evidence. One
Undo restores one accepted reconciliation.

Expose native CLI verbs for direction, recipe discovery, projection and
reconciliation, in help and the shipped guide. Browser controls use the same
records and helpers. Keep public exports purposeful, type packaging complete
and instruction/reference bodies off the initial browser path.

## A small kit, with different compositions

Ship three inspectable, runnable native HTML references with useful authored
synthetic content and accompanying design documents: an operational receiving
list/detail/form flow, an editorial reading surface, and a persuasive surface
whose claims come only from supplied synthetic facts. They demonstrate choices
rather than impose themes. Reuse the existing declarative recipe contract for
machine facts; add no arbitrary policy execution or universal UI dependency.

The operational reference completes an empty receipt, validation, loading/error,
save and correction path. Reading demonstrates hierarchy, comfortable measure,
navigation and long content. Persuasion demonstrates an evidence sequence and
working CTA/form states without fabricated testimonials or certifications.
All relevant actions work by keyboard at narrow and wide widths; focus, long
labels, reduced motion and absent imagery have deliberate behavior. A reference
must remain useful beyond the exact values entered by its acceptance script.

Creating a reference or its system from the browser is one ordinary add in
its captured group or canvas scope. Group mode supplies explicit membership.
Legacy area geometry cannot guarantee that intent with one add: its existing
placement helper can require a separate area resize and shifts, while anchoring
beside an area can accidentally create a canvas-wide policy. Refuse new library
creation on a legacy canvas before journaling or uploading, explain the existing
groups migration, and keep previews, downloads and scoped source reads/edits
available. Do not silently migrate a canvas or claim geometric proximity is
membership. Previously submitted exact intents remain confirmable where the
canonical receipt proves their captured intent. A retained legacy automatic
anchor whose normalized receipt cannot establish that destination stays pending
with the limitation explained; it cannot become a claimed scoped success.

An accepted creation receipt must match the full normalized create payload and
authoritative actor, including destination, title, properties and content. A
later snapshot failure cannot turn that accepted add into a refusal. Likewise,
a retry preflight or upload failure cannot prove that an earlier uncertain add
was refused. Preserve the original intent until the actual writer confirms or
definitively refuses it; report post-save consistency independently.

The shared on-demand procedure explains when and how to inspect/adapt a recipe.
Both entrances can discover and open the same installed bytes. Connected work
first inspects actual repository components, token files and conventions; no
library is added just because a recipe uses one. Prove this using an owned copy
of the frozen synthetic brand repository, extending its real component import
and token declarations without modifying the frozen evaluation corpus.

## What closes this mechanism

Follow phase 3's named browser proof and record source conformance, actual task
behavior and brief-grounded craft review separately. The second screen must
read the recorded accepted treatments after switching entrances. Scope and
inheritance cases must exercise the shared API and actual CLI/web consumers.
Concurrent source edits must retain a stale working draft, and an incumbent
system change on an exempt canvas must still stale evidence that used it.
Neither a clean test suite nor the author's craft review establishes the
independent human quality result owed by phase 7.
