# Hosted acceptance and rollback

The debt is that a local journey and a green deployment cannot prove an
authenticated hosted journey. This is the remaining walk for phase 7, to run
after a named home, synthetic study canvas, identities, agent profile and usage
ceiling are authorized. It creates no authorization and changes no defaults.

## What has actually run

Its served `index-DEF98bII.js` was 742,315 bytes, SHA-256

152.0.7977.84 browser loaded the public landing page without observed errors.
No identity was entered and no hosted canvas or agent was used. Those reads
establish deployment identity and public navigation only.

The local rollback walk used the actual daemon, native CLI and Chrome. It
exercised `off → adaptive-v1 → unsupported → off` on both entrances, preserved
saved answers, comparisons, output versions and receipts, then resumed an
existing request with automatic enrollment off. A real daemon restart and
browser refresh preserved the resumed record. Its missing browser-task checks
remained an honestly unverified draft. These results do not stand in for the
hosted walk below.

## Bind the walk before starting

Record the full tested source revision, reported server revision, served web
entry hash, installed CLI revision, provider/model identity and tool capability
profile. Verify the exact installed CLI help; a newer guide does not establish
that an older hosted harness has the commands. Use ordinary existing identity
and membership flows. Never copy local credential files into the study record.

Use a newly authorized synthetic canvas, with Acme fixture content and no real
customer names. Record its original `design.workflow` property, including
whether it is absent. Name the person who answers and the distinct agents that
perform canvas-summoned, external and hosted-agent work. Capture operation and
request IDs as they are returned. Keep raw signed links and personal data out
of committed evidence.

`isocan --canvas "$study_canvas"` below selects that canvas through the
already-configured client and its authoritative home. It is not permission to
change global home configuration or create another identity. Inspect and save:

```sh
isocan --canvas "$study_canvas" whoami
isocan --canvas "$study_canvas" design workflow --json
isocan --canvas "$study_canvas" design brief --json
isocan --canvas "$study_canvas" design receipt --json
```

## Walk the experience

1. **Canvas-summoned request.** Select the supplied brief and incumbent system,
   then ask for an inventory app in the actual browser chat. The agent must
   capture that real thread/comment as its source. Answer consequential
   questions through the browser, attach the supplied sketch and record an
   unavailable reference honestly. A progress message must not dismiss the
   open question. Refresh with an unanswered draft and verify its recovery.
2. **Decision and output.** Try both receiving wireframes with the same sample
   data. Choose the nonrecommended direction or explicitly delegate; inspect
   the saved attribution and rationale. Undo and restore the adoption. Complete
   receiving, validation, save and correction in the delivered artifact at
   390 and 1,440 pixels. Record actual final bytes, task observations and any
   repair; a source audit alone is insufficient.
3. **External continuation.** A distinct external agent reads the same request
   and asks to add stock lookup. It must reuse the accepted answers and scoped
   system. A deliberate correction changes the current fact without rewriting
   who supplied the original answer. Reload both clients and compare their
   request, response, choice and receipt identities.
4. **Hosted-agent continuation.** Use the named, supported hosted harness on
   that same request. Record which context bytes and tools it actually receives,
   including any missing local repository or browser. Verify a normal return
   and resume through the other entrance without another interview.
5. **Staleness and fallback.** Change the governing system as the second actor.
   Both clients must expose the changed basis; an old repair cannot overwrite
   the teammate's edit. With browser capability deliberately unavailable in
   the recorded harness profile, produce a draft and verify that neither client
   claims a browser pass. Route later verification only to an authorized capable
   agent. Optional adapted craft guidance must use the same current context;
   unsupported native playbooks remain unsupported.

Read the actual IDs after each step rather than inferring success from a chat
sentence:

```sh
isocan --canvas "$study_canvas" design workflow "$study_request" --json
isocan --canvas "$study_canvas" design brief "$study_request" --json
isocan --canvas "$study_canvas" design questions --json
isocan --canvas "$study_canvas" design receipt "$study_request" --json
```

## Exercise the existing switch

Capture the starting property and exact records before changing anything. For
the authorized synthetic canvas only, the existing ordinary CLI acts are:

```sh
isocan --canvas "$study_canvas" canvas edit --prop design.workflow=adaptive-v1
isocan --canvas "$study_canvas" design workflow --json
isocan --canvas "$study_canvas" canvas edit --prop design.workflow=off
isocan --canvas "$study_canvas" design workflow --json
```

While enabled, verify automatic admission from each entrance. While off, submit
a fresh real canvas request and a fresh external starting intent using
`design start request.json --automatic --json`: both automatic admissions must
refuse. Files must carry distinct actual request/source IDs, using the versioned
shape in the [agent guide](../../../packages/cli/src/agent-guide.md).
An explicit `design start request.json --json` must still work while off.

Resume the existing completed request while off. Copy its exact current `ref`
and epoch from `design brief`, add a new stable version ID and an explicit
reason in `resume.json`, then run:

```sh
isocan --canvas "$study_canvas" design brief "$study_request" --resume resume.json --json
```

Reload the browser and reconnect the CLI. Verify the advanced epoch, original
source, accepted answers and historical receipt remain readable. Policy changes
must not alter output version bytes or erase earlier decisions. Restore the
original property, using `canvas edit --rm-prop design.workflow` if originally
absent, or its captured value otherwise. Record restoration separately from
whether the journey passed. No purge or history rewrite is part of rollback.

## Result and release decision

Attach actual browser actions/screenshots, exact CLI JSON, operation IDs,
source/build identities, provider usage and observed failures to the phase-7
verification record. Mark each entrance and capability separately; an unavailable
hosted harness is missing coverage. A public page load or local replay cannot
fill that cell.

Any broken routing, lost accepted context, false ready claim or destructive
rollback stops the rollout. Keep the shared policy opt-in until controlled
quality results, the six-person partnership study and hosted acceptance meet
the preregistered criteria. The product owner then names the opt-in cohort and
decides any broader enablement. The craft condition requires its own result.
